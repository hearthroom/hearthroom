# 角色設定查重

owner 2026-09-23 決定：審核頁為每張待審卡提供「角色設定」（`roleDetailDesc`）的重複度，
作為審核人判斷抄襲嫌疑的參考。只給審核人看，作者看不到；不自動駁回、不擋上架。

## 做法

參考論文查重（MOSS、知網一類）的純計算指紋比對，不用模型。實作在 `src/originality.ts`。

1. 正規化：NFKC（全半形）、小寫、繁轉簡逐字對照（OpenCC TSCharacters，
   `src/originality-hans.ts`），並去掉標點與空白。卡片自己的角色名、使用者名與
   `{{char}}`／`{{user}}` 換成同一個佔位符，所以只改名字的複製也抓得到。
2. 比對單位：中日韓文字一個字算一個單位，其他文字一個詞算一個單位。
3. 連續 K=8 個單位算一個雜湊，再用 winnowing 從每 W=6 個雜湊中選最小值作為指紋。
   兩段文字只要有連續 13 個單位相同，就保證至少共有一個指紋。
4. 送審時把指紋寫進 D1 倒排索引（`originality_texts`／`originality_prints`，
   migration 0041），和審核單在同一批寫入。
5. 審核人打開查重分頁時才即時計算：新卡的指紋對索引查詢，命中的片段在新卡上圈出來，
   連續不到 13 個單位的零星命中不算。同一個指紋出現在 5 張以上不同的卡，就視為套語丟掉。
   重複率＝被圈到的單位數 ÷ 總單位數；另外列出單一來源最高的前 5 張卡，
   並標示各來源的狀態與送審先後。

## 語料與保存

- 納入語料：審核中與已過審的卡。駁回、作者改稿作廢、審核中撤回的送審，指紋會由 trigger 刪除。
  同一張卡只保留最新過審的一版。已過審的卡被作者撤下後，指紋仍然保留，並標成「已下架」。
- 同一位作者的其他卡不列入比對；審核頁不顯示作者身分（盲審）。
- 只存指紋，不存原文：資料庫還原不出角色設定。0018 「定案即刪快照」的做法不變。
  但這張表改變了「本站不留任何私有設定痕跡」的承諾，由 owner 當天明確同意。
- 沒有回填：過審卡的快照早已刪除，本站也沒有作者 token，所以語料從上線那天開始累積。

## 限制（審核頁上也有一句提示）

- 翻譯、改寫與站外來源都抓不到。
- 「比這張早送審」不代表是原作者。
- 無快照的自動重審單與太短的角色設定顯示「無法查重」，不顯示 0%。
- 每張卡最多 60,000 個指紋，約涵蓋前二十萬字；超出的部分不比對，但送審不會因此失敗
  （D1 單一字串上限 2 MB）。
- 演算法參數改變時要一併更換 `ALGORITHM`；舊版指紋查詢時不採用，語料會重新累積。

## 端點與觀測

- `GET /v1/review/:id/originality`：和 `/detail` 使用同一道門（審核人、單子仍在審核中、
  由自己認領且未逾時、成人卡須完成年齡驗證），`Cache-Control: private, no-store`。
- 分析事件 `review_originality`，只記錄 `high`（≥30%）、`some`、`none` 或無法查重的原因；
  不記錄卡片內容或作者。這是 Cloudflare Worker，沒有 Prometheus；未新增 metric。
- MCP 不適用：這是內部審核工具，沒有新增面向外部 AI 客戶端的能力。
