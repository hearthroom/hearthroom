# 개발자 문서

Hearthroom API를 사용하면 커뮤니티 카드를 탐색하고, 작가를 찾고, 댓글을 읽거나 작성하며, 본인의 즐겨찾기, 팔로우 및 알림을 관리할 수 있습니다.

이 페이지에는 두 가지 OpenAPI 3.1 참조 문서가 있습니다.

- **Hearthroom 커뮤니티 API** (`docs/community-openapi.json`): 커뮤니티 탐색과 회원 소셜 기능을 제공하는 사이트의 `/v1` 엔드포인트입니다.
- **서비스 연동 API** (`docs/integration-openapi.json`): 사이트와 내장 채팅 클라이언트가 신원 확인, 카드 작성, 미디어 및 대화에 사용하는 인터페이스입니다. 요청은 연결된 서비스의 API 출처(origin)로 전송합니다.

경로, 필드명, 범위 및 작업 식별자는 기존 연동 계약과 호환성을 유지합니다. 서비스는 지원하는 기능 그룹을 단계적으로 구현할 수 있습니다. 클라이언트는 선택적 작업을 호출하기 전에 서비스가 알린 지원 기능을 확인해야 합니다. 이 참조 문서는 연동 인터페이스를 설명하며 특정 서비스의 배포 설정이나 상업적 조건을 설명하지 않습니다.

## 빠른 시작

공개 콘텐츠 탐색에는 로그인이 필요하지 않습니다.

```sh
curl 'https://hearthroom.club/v1/cards?zone=en&sort=new&limit=12'
curl 'https://hearthroom.club/v1/tags?zone=en&limit=12'
```

카드 목록은 `items`, `hasNext`, `limit`, `offset`을 반환합니다. 카드의 `id`로 상세 정보와 댓글을 조회하세요. 작가 링크에는 작가의 공개 `handle`을 사용합니다.

## 커뮤니티 요청 및 인증

| 항목 | 규칙 |
|---|---|
| 기본 URL | `https://hearthroom.club`입니다. 문서의 경로는 `/v1`로 시작합니다. 자체 호스팅 인스턴스는 자체 출처를 사용합니다. |
| 공개 조회 | **인증 불필요**로 표시된 엔드포인트는 익명 요청을 허용합니다. 선택적으로 인증하면 표시되는 콘텐츠 및 조회자별 필드가 달라질 수 있습니다. |
| 회원 요청 | 승인된 Hearthroom 로그인에서 받은 현재 액세스 토큰을 `Authorization: Bearer <access_token>`으로 보내세요. 브라우저 쿠키만으로는 이 엔드포인트를 인증할 수 없습니다. 이 API는 별도의 개발자 키를 발급하지 않습니다. |
| 요청 본문 | 엔드포인트에 본문이 정의되어 있으면 `Content-Type: application/json`으로 JSON을 보내세요. |
| 표시 언어 | 카드 및 작가 탐색에는 `lang`을 사용할 수 있습니다. 카드 텍스트는 첫 번째 `Accept-Language` 값, 그다음 중국어 순으로 대체합니다. |
| 콘텐츠 언어 | `zone`은 게시판을 `zh`, `en`, `ja`, `ko` 또는 `all`로 필터링합니다. 기본값은 `zh`이며 표시 언어와 별개입니다. |
| 식별자 | 카드의 `id` 및 회원의 `handle`은 공개 식별자입니다. 식별자는 불투명한 값으로 취급하고 API가 반환한 값을 사용하세요. |
| 타임스탬프 | 숫자 타임스탬프는 Unix 밀리초입니다. 댓글의 `createTime`은 ISO 8601 문자열입니다. |

인증된 요청은 로그인한 회원으로 동작합니다. 요청에 ID를 추가해 다른 회원을 선택할 수 없습니다. 비공개 결과를 공유 캐시에 저장하면 안 됩니다.

## 탐색 및 페이지 나누기

카드 검색 및 게시판 필터는 `GET /v1/cards`를 사용합니다. `tag`를 반복하면 선택한 모든 태그 그룹을 요구합니다. `hide`는 쉼표로 구분한 카테고리 키 목록입니다. 명시적으로 선택한 태그는 숨긴 카테고리보다 우선합니다. `author` 필터는 공개 handle을 사용하며 `zone`을 무시합니다.

카드, 태그 및 작가 목록은 `offset`과 `limit`을 사용하고 `hasNext`로 다음 페이지 유무를 알립니다. 카드의 `total`은 `null`일 수 있으므로 이것만으로 페이지 나누기를 판단하지 마세요. 즐겨찾기, 팔로우 및 팔로우한 작가 피드는 페이지당 24개를 반환합니다. 댓글 및 답글은 1부터 시작하는 `page`를 사용하며 페이지당 20개입니다.

공개 게시판 결과에는 게시된 카드가 포함됩니다. 카드 직접 링크는 접근 가능한 미리보기를 반환할 수도 있습니다. 링크에 접근할 수 있다고 해서 커뮤니티 심사를 통과한 것은 아닙니다. 숨겨졌거나 사용할 수 없는 카드는 제외하거나 404를 반환합니다. 성인 콘텐츠는 인증된 회원이 사이트의 연령 및 표시 설정을 활성화해야 접근할 수 있습니다. 권한 없이 직접 요청하면 `adult_content`와 함께 403을 반환합니다.

## 댓글 및 회원 컬렉션

댓글은 커뮤니티 카드에 속합니다. API는 최상위 댓글과 각 댓글 아래 한 단계의 답글 스레드를 지원합니다. 댓글은 앞뒤 공백 제거 후 Unicode 문자 1–500자여야 합니다. 회원당 분당 최대 6개의 댓글을 작성할 수 있습니다.

댓글 작성자, 카드 작가 및 권한이 있는 운영자는 댓글을 삭제할 수 있습니다. 최상위 댓글을 삭제하면 답글도 숨겨집니다. 좋아요 및 좋아요 취소는 멱등 연산입니다.

즐겨찾기는 카드의 `id`, 팔로우는 작가의 `handle`을 사용합니다. `GET`은 현재 상태를 조회하고 `PUT`은 추가하며 `DELETE`는 제거합니다. 피드에는 팔로우한 작가의 작품이 포함됩니다. 알림은 수신자에게만 보입니다. 알림을 읽음으로 표시해도 다른 사람의 알림에 대한 접근 권한이 생기지 않습니다.

## 커뮤니티 오류

오류는 2xx가 아닌 HTTP 상태와 JSON `error` 문자열을 사용하며 때로는 `detail` 객체도 포함합니다. 문자열은 코드 또는 짧은 문장일 수 있습니다. 클라이언트는 오류를 처리할 때 HTTP 상태를 함께 유지해야 합니다.

| 상태 | 의미 |
|---|---|
| 400 | 빈 댓글 또는 너무 많은 태그 등 입력이 없거나 유효하지 않습니다. |
| 401 | 인증이 없거나 더 이상 유효하지 않습니다. |
| 403 | 회원이 해당 작업을 수행하거나 요청한 콘텐츠에 접근할 수 없습니다. |
| 404 | 호출자가 요청한 리소스를 사용할 수 없습니다. |
| 429 | `comment_rate_limited` 등 요청 빈도 제한을 초과했습니다. |
| 5xx | 서비스가 요청을 완료할 수 없습니다. |

이 참조 문서의 범위는 탐색 및 회원 소셜 기능입니다. 운영진 심사, 계정 복구, 게시 작업 흐름 및 내부 자동화는 포함하지 않습니다.


## 서비스 연동

서비스 API는 별도로 설정한 `<API_BASE>`를 사용합니다. 주요 리소스는 `/open/v1` 아래에 있으며 OAuth 및 검색은 참조 문서에 나온 경로를 사용합니다. 커뮤니티 `/v1` 경로와 서비스 `/open/v1` 경로는 출처, 인증 맥락 및 데이터 소유권이 서로 다릅니다.

| 영역 | 클라이언트 계약 |
|---|---|
| 신원 | PKCE를 사용하는 OAuth 인가 코드 흐름, 토큰 갱신/폐기 및 `GET /open/v1/me`입니다. |
| 카드 작성 | 카드 상세 정보, 작가 소유 목록, 문서 갱신, 시작 메시지, 표시 에셋, Lorebook 및 미디어입니다. |
| 대화 | 시작/재개, WebSocket 메시지, 기록, 작업 상태, 중단 및 재연결입니다. |
| 플레이어 데이터 | 페르소나, 응답 설정, 보관함, 기억 및 메모장입니다. 소유권 및 서비스가 알린 지원 범위에 따릅니다. |
| 호스팅 및 심사 | 문서에 명시된 작가 자격 증명과 서버 보관 발급자 자격 증명으로 버전 및 결정 사항을 교환합니다. 커뮤니티 심사와 게시는 커뮤니티가 결정합니다. |

### 인가 및 비공개 데이터

클라이언트는 `/oauth/register`로 허용된 콜백을 등록하고 PKCE `S256`, `state`, 의도한 리소스를 `/oauth/authorize`로 보낸 뒤, 반환된 코드를 `/oauth/token`에서 교환합니다. 서비스 API 접근용 리소스는 `<API_BASE>/open/v1`입니다. 갱신 및 폐기에는 참조 문서의 엔드포인트를 사용합니다. 토큰은 부여된 범위 및 리소스에서만 유효합니다.

사용자 호출은 `Authorization: Bearer <access_token>`을 보냅니다. `role.read`는 작가의 비공개 카드 지침 및 Lorebook에 대한 접근을 포함할 수 있습니다. `role.write`는 해당 미디어 작업을 포함한 리소스 변경을 허용합니다. `chat.play`는 크레딧을 소비할 수 있는 대화 작업을 허용합니다. 연동 서비스는 인가 과정에서 이러한 영향을 알리고 모든 비공개 작업에서 소유권을 확인해야 합니다.

공개 카드에 대한 접근은 편집 또는 비공개 내보내기 권한을 부여하지 않습니다. 커뮤니티 회원 handle, 카드 번호 및 서비스 리소스 ID는 각각 다른 대상을 식별합니다. 클라이언트는 각 엔드포인트에서 요구하는 식별자를 사용해야 합니다. 필요한 경우 사용하는 `X-Hosting-Key`는 서버에 보관하는 발급자 자격 증명이며 브라우저 코드에 절대 보내면 안 됩니다. 개인 API 키는 선택 사항이며 형식과 발급 방식은 이 참조 문서의 범위 밖입니다.

### 대화 생명주기

1. `POST /open/v1/conversation/start`는 대화를 열거나 재개합니다. 모델 응답을 생성하지는 않습니다. 대화를 이어 갈 때 `firstPageSize`를 함께 보내면 같은 응답에 기록 첫 페이지(`firstPage`)가 포함되어 기록을 따로 요청할 필요가 없습니다.
2. `POST /open/v1/conversation/ws-ticket`은 사용자 bearer 토큰으로 수명이 짧은 일회용 티켓을 받습니다.
3. 클라이언트는 `/open/v1/conversation/ws`를 열고 인증 프레임을 보낸 뒤 턴 프레임을 보냅니다. 티켓 엔드포인트의 **WebSocket 프로토콜** 섹션에서 프레임, 이벤트, 완료 및 재생 필드를 설명합니다.
4. 기록 및 작업 상태 엔드포인트에서 영속적으로 저장된 결과를 확인합니다. `POST /open/v1/conversation/stop`은 취소를 요청합니다. 클라이언트는 최종 작업 상태로 결과를 판단합니다.

재연결 시에는 새 유료 턴을 제출하지 말고 스트림 식별자와 재생 위치를 재사용해야 합니다. 선택적 Agent 이어하기는 서비스가 진행 보존을 보고한 경우에만 `resumeFromOperationId`를 사용합니다. 거부된 이어하기를 새 유료 요청으로 조용히 전환하면 안 됩니다.

### 선택적 기능 및 오류

응답 환경설정에는 `responseSettingsVersion=1`이 필요합니다. 미디어 검색, 정렬 및 작가 지정 상대 경로에는 해당 반환 기능이 필요합니다. 복수 응답 제안과 Agent 준비도 서비스 지원 여부에 따릅니다. 경로가 일치한다는 사실만으로 기능이 활성화되었다고 판단할 수 없습니다.

요금, 잔액, 모델 가용성, 저장 한도 및 보존 정책은 연결된 서비스가 결정합니다. 클라이언트는 반환된 기능 및 비용 정보를 사용하고, 필요한 경우 유료 작업에 대한 확인을 받으며, 완료된 응답, 부분 출력, 취소 및 실패를 구분해야 합니다.

서비스 오류 및 인증 실패는 엔드포인트별 스키마와 연동 참조 문서의 참고 사항 섹션을 따릅니다. 위의 커뮤니티 오류 형식과는 별개입니다. 알 수 없는 선택적 기능은 서비스 이름에서 추론하지 말고 사용할 수 없는 상태로 유지해야 합니다.
