# 開発者ドキュメント

Hearthroom の API では、コミュニティのカード閲覧、作者の検索、コメントの閲覧・投稿、自分のお気に入り・フォロー・通知の管理ができます。

このページには、OpenAPI 3.1 のリファレンスが 2 つあります。

- **Hearthroom コミュニティ API**（`docs/community-openapi.json`）：コミュニティの閲覧とメンバー同士の交流に使用する、サイトの `/v1` エンドポイントです。
- **サービス連携 API**（`docs/integration-openapi.json`）：サイトと埋め込みチャットクライアントが、認証情報、カード作成、メディア、会話に使用するインターフェースです。リクエストは接続先サービスの API オリジンに送信します。

パス、フィールド名、スコープ、操作識別子は、既存の連携契約との互換性を維持しています。サービスは対応する機能群を段階的に実装できます。クライアントは任意の操作を呼び出す前に、公開された対応機能を確認してください。このリファレンスは連携インターフェースを説明するもので、特定のサービスのデプロイ設定や商用条件を定めるものではありません。

## クイックスタート

公開コンテンツの閲覧にログインは不要です。

```sh
curl 'https://hearthroom.club/v1/cards?zone=en&sort=new&limit=12'
curl 'https://hearthroom.club/v1/tags?zone=en&limit=12'
```

カード一覧は `items`、`hasNext`、`limit`、`offset` を返します。カードの `id` で詳細とコメントを取得できます。作者へのリンクには、作者の公開 `handle` を使用します。

## コミュニティへのリクエストと認証

| 項目 | 規則 |
|---|---|
| ベース URL | `https://hearthroom.club` です。記載するパスは `/v1` で始まります。セルフホスト環境では、その環境のオリジンを使用します。 |
| 公開情報の取得 | **認証不要**のエンドポイントは匿名リクエストを受け付けます。任意で認証すると、表示される内容や閲覧者固有のフィールドが変わる場合があります。 |
| メンバーのリクエスト | 認可済みの Hearthroom ログインで取得した現在のアクセストークンを使い、`Authorization: Bearer <access_token>` を送信します。ブラウザーの Cookie だけでは、これらのエンドポイントを認証できません。この API は独立した開発者キーを発行しません。 |
| リクエスト本文 | 本文を定義するエンドポイントでは、`Content-Type: application/json` を付けて JSON を送信します。 |
| 表示言語 | カードと作者の閲覧は `lang` を受け付けます。カードのテキストは、未指定時に `Accept-Language` の最初の値、次に中国語を使用します。 |
| コンテンツ言語 | `zone` は一覧を `zh`、`en`、`ja`、`ko`、`all` で絞り込みます。既定値は `zh` です。表示言語とは別の設定です。 |
| 識別子 | カードの `id` とメンバーの `handle` は公開識別子です。不透明な値として扱い、API が返した値を使用してください。 |
| タイムスタンプ | 数値のタイムスタンプは Unix ミリ秒です。コメントの `createTime` は ISO 8601 文字列です。 |

認証済みのリクエストは、ログイン中のメンバーとして実行します。リクエストに ID を追加して別のメンバーを選ぶことはできません。非公開の取得結果を共有キャッシュに保存してはいけません。

## 閲覧とページ分割

カード検索と一覧のフィルターには `GET /v1/cards` を使用します。`tag` を繰り返すと、選択したすべてのタググループを必須条件にします。`hide` はカテゴリキーのカンマ区切りリストです。明示的に選択したタグは非表示カテゴリより優先されます。`author` フィルターには公開ハンドルを使い、`zone` は無視されます。

カード・タグ・作者の一覧では `offset` と `limit` を使用し、`hasNext` が次のページの有無を示します。カードの `total` は `null` の場合があるため、ページ分割の判断をこの値だけに依存させないでください。お気に入り、フォロー、フォロー中の作者のフィードは 1 ページ 24 件です。コメントと返信は 1 から始まる `page` を使用し、1 ページ 20 件です。

公開一覧の結果には掲載中のカードを含みます。カードへの直接リンクでは、利用可能なプレビューを返す場合もあります。リンクにアクセスできても、コミュニティ審査に合格済みとは限りません。非表示または利用できないカードは省略するか、404 を返します。成人向けコンテンツには、サイトの年齢・表示設定を有効にした認証済みメンバーであることが必要です。アクセス権なしで直接リクエストすると、403 と `adult_content` を返します。

## コメントとメンバーのコレクション

コメントはコミュニティのカードに属します。API はトップレベルのコメントと、各コメントの下にある 1 つの返信スレッドに対応します。コメントは前後の空白を除去した後で Unicode 文字 1–500 文字とし、メンバーごとに 1 分間で最大 6 件投稿できます。

コメントの投稿者、カードの作者、権限を持つモデレーターがコメントを削除できます。トップレベルコメントを削除すると、返信も非表示になります。「いいね」と取り消しは冪等です。

お気に入りにはカードの `id`、フォローには作者の `handle` を使用します。`GET` は現在の状態を取得し、`PUT` は追加、`DELETE` は削除します。フィードにはフォロー中の作者の作品を含みます。通知を閲覧できるのは宛先のメンバーのみです。既読にする操作で他人の通知へのアクセス権を得ることはありません。

## コミュニティ API のエラー

エラーは 2xx 以外の HTTP ステータスと JSON の `error` 文字列を使用し、追加の `detail` オブジェクトを含む場合もあります。文字列はコードまたは短い文です。クライアントは処理時に HTTP ステータスを保持してください。

| ステータス | 意味 |
|---|---|
| 400 | 空のコメントやタグ数超過など、入力が不足しているか無効です。 |
| 401 | 認証がないか、有効ではなくなっています。 |
| 403 | メンバーは操作を実行できないか、要求したコンテンツにアクセスできません。 |
| 404 | 呼び出し元は要求したリソースを利用できません。 |
| 429 | `comment_rate_limited` など、レート制限を超えました。 |
| 5xx | サービスがリクエストを完了できませんでした。 |

このリファレンスの対象は、閲覧とメンバー同士の交流機能です。スタッフの審査、アカウント復旧、公開ワークフロー、内部の自動処理は対象外です。

## サービス連携

サービス API は、別途設定した `<API_BASE>` を使用します。主なリソースは `/open/v1` 配下にあり、OAuth とディスカバリーはリファレンスに記載したパスを使用します。コミュニティの `/v1` とサービスの `/open/v1` は、オリジン、認証コンテキスト、データの所有権が異なります。

| 分野 | クライアント契約 |
|---|---|
| ユーザー認証 | PKCE を使う OAuth 認可コードフロー、トークンの更新・失効、`GET /open/v1/me`。 |
| カード作成 | カード詳細、作者所有の一覧、文書更新、開始メッセージ、表示素材、Lorebook、メディア。 |
| 会話 | 開始・再開、WebSocket メッセージ、履歴、操作状態、停止、再接続。 |
| プレイヤーデータ | ペルソナ、返信設定、アーカイブ、記憶、メモ帳。所有権と公開された対応範囲に従います。 |
| ホスティングと審査 | 文書化された作者の資格情報とサーバー保管の発行者資格情報による、バージョンと判断結果の交換。コミュニティの審査と掲載は、引き続きコミュニティが決定します。 |

### 認可と非公開データ

クライアントは `/oauth/register` で許可するコールバックを登録し、PKCE の `S256`、`state`、対象リソースを `/oauth/authorize` に送って、返されたコードを `/oauth/token` で交換します。サービス API のリソースは `<API_BASE>/open/v1` です。更新と失効にはリファレンスのエンドポイントを使用します。トークンは許可されたスコープとリソースでのみ有効です。

ユーザーの呼び出しには `Authorization: Bearer <access_token>` を送信します。`role.read` には作者の非公開カード指示と Lorebook が含まれる場合があります。`role.write` は、対象のメディア操作を含むリソース変更を許可します。`chat.play` はクレジットを消費しうる会話操作を許可します。連携側は認可時にこれらの影響を提示し、非公開の操作ごとに所有権を確認する必要があります。

公開カードへのアクセス権は、編集や非公開データのエクスポートを許可するものではありません。コミュニティのメンバーハンドル、カード番号、サービスのリソース ID はそれぞれ異なる対象を識別します。各エンドポイントに必要な識別子を使用してください。要求される場合の `X-Hosting-Key` はサーバー保管の発行者資格情報で、ブラウザーのコードに渡してはいけません。個人用 API キーは任意の機能で、形式と発行方法はこのリファレンスの対象外です。

### 会話のライフサイクル

1. `POST /open/v1/conversation/start` は会話を開くか再開します。モデルの返信は生成しません。
2. `POST /open/v1/conversation/ws-ticket` はユーザーの Bearer トークンで、短期間有効な使い捨てチケットを取得します。
3. クライアントは `/open/v1/conversation/ws` を開き、認証フレーム、ターンのフレームの順で送ります。フレーム、イベント、完了、再送のフィールドは、チケットエンドポイントの **WebSocket プロトコル** 節に記載しています。
4. 履歴と操作状態のエンドポイントで永続的な結果を取得できます。`POST /open/v1/conversation/stop` はキャンセルを要求します。最終的な操作状態から結果を判断してください。

再接続では、別の有料ターンを送らず、ストリームの識別子と再送位置を再利用する必要があります。任意のエージェント継続機能では、サービスが進捗の保持を報告した場合のみ `resumeFromOperationId` を使用します。継続を拒否された場合、黙って新しい有料リクエストに切り替えてはいけません。

### 任意の機能とエラー

返信設定には `responseSettingsVersion=1` が必要です。メディアの検索、並べ替え、作者指定の相対パスには、対応する機能がレスポンスで示されている必要があります。複数の返信候補やエージェント準備もサービスの対応に依存します。パスが存在するだけでは、機能が有効とは判断できません。

価格、残高、モデルの利用可否、ストレージ上限、保持方針は接続先サービスが決定します。クライアントは返された機能・費用情報を使用し、必要な場合は有料操作の確認を得てください。返信完了、部分的な出力、キャンセル、失敗は区別して扱う必要があります。

サービスのエラーと認証失敗は、エンドポイント別のスキーマと連携リファレンスの「補足事項」に従います。上記のコミュニティ用エラー形式とは別です。不明な任意の機能は、サービス名から推測せず、利用不可のままにしてください。
