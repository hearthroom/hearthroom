## 能交給 Agent 的事

Agent 依官方寫卡技能工作：釐清你的需求（只在不同理解會產生不同卡片時才向你確認），把卡寫成資料夾、推成試玩卡，自行檢查與試玩，再回報還能改進的地方。每一項都附一句可以直接輸入的提示詞。

### 從一個點子寫出整張卡

> 「寫一張修仙卡：我是被逐出宗門的廢柴，師姐偷偷幫我，張力是她一出手就會被發現。狀態只要修為一項。先做成試玩卡，告訴我最弱的一層。」

只有模糊的想法也可以。Agent 會先與你釐清設定、人物、關係與開場白，再開始撰寫。

### 修復現有的卡

> 「匯入這張 SillyTavern 卡，告訴我為什麼聊三輪就沒話說，然後修掉。」

SillyTavern 的 PNG、JSON、CHARX 和魅魔島三件套都能直接匯入。

### 製作狀態欄、主題或整頁介面

> 「加一個顯示好感度和所在地點的狀態欄，渲染開場白給我看。」

需要畫面時，Agent 使用工具包內建的沙盒套件（把模型寫的狀態區塊畫成面板、選項鈕與主題），以 `hearthroom card check` 檢查資料夾，再以 `hearthroom card preview` 與 `card render` 檢視結果。即使沒有任何顯示規則，平台也會把回覆結尾的 [status]／[choices] 區塊畫成面板與按鈕；需要自訂樣式、主題或釘選列時才使用套件。

聊天頁本身是開源的（`hearthroom/moonstage`，本站的 `stage` 子模組）：skills 的沙盒契約由它的 `src/sandbox/` 生成，文件未涵蓋的部分，平台事實頁列出應讀取的檔案。

### 試玩並找出問題

> 「用第二個開場白玩十輪，告訴我玩家會在第幾輪失去興趣、原因是什麼。」

### 上架前的檢查

> 「檢查這張卡能不能送審，列出還要修的地方。」

## Agent 怎麼寫卡

1. **寫成資料夾**：長文是 Markdown 檔，世界書、規則和圖片各有自己的檔案，你可以直接開啟檢視或修改。
2. **推成試玩卡**：只有你看得到，最後一次更新後 3 天過期，同時最多 5 張。
3. **檢查與渲染**：依平台規則檢查字數與內容，把開場白套上規則渲染出來，確認狀態欄和版面正確。
4. **試玩**：實際與角色對話一輪，確認回覆能否延續、玩家是否接得下去。
5. **修改**：依結果修改，再推送、再試玩，直到你滿意。
6. **保存**：滿意之後存成正式的私人卡，出現在「我的卡片」。送審和公開由你在網站上決定。

## 提示詞指南

Agent 依官方技能工作，不需要你說明寫卡的方法。需要你提供的是技能裡沒有的資訊：玩家的處境、角色的聲音、你要的畫面、完成的標準，以及 Agent 可以自行決定的範圍。這一節依「你會遇到的狀況」整理，每一節說明 Agent 為什麼會這樣、該怎麼寫，並附一段可以直接複製修改的提示詞。先找符合你狀況的那一節：

- 產出的卡跟其他卡沒有分別：[給處境與張力，不只給題材](#給處境與張力不只給題材)、[用一句對白代替形容詞](#用一句對白代替形容詞)
- 狀態欄與按鈕蓋過故事：[說明畫面要哪一種、不要哪些預設](#說明畫面要哪一種不要哪些預設)
- Agent 頻繁提問，每一步都等待確認：[寫出完成標準與可自行決定的範圍](#寫出完成標準與可自行決定的範圍)
- 想法還不清楚：[想法還模糊時，先要方向](#想法還模糊時先要方向)
- 有原作、設定檔或喜歡的卡：[直接提供素材](#直接提供素材)
- 語言、用語或稱呼不對：[說明語言與稱呼](#說明語言與稱呼)
- 尺度不符預期：[說明內容尺度](#說明內容尺度)
- Agent 修改了未要求修改的內容：[一個版本只改一件事](#一個版本只改一件事)
- Agent 表示已測試，實際三輪就無法延續：[要求完整的試玩，並查看工作紀錄](#要求完整的試玩並查看工作紀錄)
- 修改後反而更差：[回報現象，不指定修法](#回報現象不指定修法)
- 只是提問，卻被直接修改：[只要意見時先說明](#只要意見時先說明)
- 新開對話要接著做：[接續上次的工作](#接續上次的工作)

### 給處境與張力，不只給題材

「寫一張好玩的女僕卡」這類指令只提供題材，Agent 會寫出該題材最常見的版本：常見的設定、常見的關係、常見的開場。技能能保證卡片的結構，不能替你決定這張卡的看點。看點來自兩件事：玩家是誰、面對什麼（處境），以及什麼事情懸而未決（張力）。開始撰寫前，Agent 會先說明這個題材一般會怎麼寫、這張卡打算有什麼不同；不同意時在這一步提出，不必等它寫完。

可以這樣寫：

```text
女僕卡。玩家是剛繼承老宅的年輕屋主；她是前任屋主留下的管家，知道這棟房子每一件不能說的事。張力：她守著的秘密，會隨玩家取得的信任一件一件交出來，但每交出一件，她自己就少一樣可以留下的理由。先說明你打算如何與一般的女僕卡不同，再開始。
```

最後一句是關鍵：它讓 Agent 先把「一般版本」說出來，你才有機會在動工前改方向。

### 用一句對白代替形容詞

「對白自然一點」「有個性」「嘴硬心軟」這類形容，每個人的理解都不同，Agent 只能套用最常見的解讀。一句你想要的對白，就能定義語氣、句長、稱呼與保留的程度，比任何形容詞精確。

可以這樣寫：

```text
她的語氣參考這句：「少爺，那扇門的鑰匙，我想您還不需要。」短句、敬語、不解釋理由，話說完就停。照這個語氣寫三句不同場合的對白給我看，確認後再寫整張卡。
```

提供對白樣本時，一句就夠；三句以上 Agent 會開始模仿句型而不是語氣。

### 說明畫面要哪一種、不要哪些預設

卡片的畫面分兩種：故事為主、畫面輔助；或玩法與數值綁定、畫面為核心。沒有說明時，Agent 會依題材套用常見的做法：好感度條、每則回覆附兩到四個按鈕、把情緒做成數值。「不要太像 AI」無法對應到具體的模式，Agent 無從判斷你指的是哪一個；直接點名不要的預設做法才有效。另外，即使沒有任何顯示規則，平台也會把回覆結尾的 [status]／[choices] 區塊畫成面板與按鈕；是否需要畫面，與是否需要撰寫規則是兩個問題。

可以這樣寫：

```text
這是陪伴卡，故事為主，關閉畫面後也要能閱讀。不要好感度條、不要每則回覆附選項按鈕、不要把情緒做成數值。只在回覆結尾保留一行：她現在在哪裡、幾點。
```

玩法綁定數值的卡則反過來說明：

```text
這是求生卡，畫面是核心。要顯示的狀態只有水位、糧食、燃料三項，每一項都要有玩家能做的動作改變它；每輪結尾附兩到四個選項。沒有玩家能改變的數值不要顯示。
```

### 寫出完成標準與可自行決定的範圍

Agent 停下來提問，通常不是因為任務困難，而是不清楚做到哪裡算完成、哪些事可以不經確認。「先寫設定給我看，再寫人物，再寫開場白」會讓它每一步都停下來等你。寫出完成的標準與它可以自行決定的範圍（包括點數上限），其餘交給它處理。

可以這樣寫：

```text
完成的標準：推成試玩卡、你自己試玩過十輪、告訴我最弱的一層。推送與修改試玩卡不需要確認；點數 50 以內自行安排，超過再問我。只有送審、公開，或會寫出完全不同的卡的選擇，才需要問我。
```

這段也會讓 Agent 較少對模糊的要求發問；如果你希望它多確認，刪掉最後一句。

### 想法還模糊時，先要方向

想法還不清楚時，「你看著辦」會把所有決定交出去，拿回來的多半是題材最常見的版本；在還沒看到方向前就要求成品，則會浪費一整張卡的工夫。請 Agent 先給幾個方向，各用一句話說明玩家在玩什麼、張力在哪，你選一個再往下。

可以這樣寫：

```text
末日題材。先給我三個方向，各用一句話說明玩家在玩什麼、張力在哪，不要寫卡。我選一個你再開始。
```

### 直接提供素材

二創的原作、你整理的設定檔、你喜歡的卡，都是 Agent 寫不出來的資訊。「像那部動畫裡那個冷淡的學姊」要求它憑印象重建，結果會偏；直接交出素材，並說明哪些必須保留、哪些可以改。附上喜歡的卡時，說明你要的是它的哪一部分（節奏、開場、對白密度），不然 Agent 會連題材一起模仿。

可以這樣寫：

```text
原作是《〔作品名〕》的〔角色名〕，設定檔附在後面。必須保留：她對學弟的稱呼方式、「先做再說」的習慣。可以改：時間線移到畢業後第一年。另外附一張我喜歡的卡，我要的是它開場白的節奏，不是題材。
```

### 說明語言與稱呼

卡片的語言、用語習慣、角色對玩家的稱呼，Agent 不會自動知道；「用中文寫」沒有說明是繁體還是簡體、台灣用語還是其他。一開始說清楚，省下事後逐欄修改。

可以這樣寫：

```text
全卡繁體中文、台灣用語，不混簡體。角色稱玩家「你」，不用「您」；玩家的名字由玩家自己填，卡裡不要預設。
```

### 說明內容尺度

「不要太色」「不要太過」沒有範圍，Agent 無法判斷界線在哪。說明預設的尺度、玩家主動時可以回應到哪裡、不可跨越的底線，Agent 才能同時遵守平台規範與你的意圖。

可以這樣寫：

```text
預設全年齡，角色不主動推進親密關係。玩家主動時，可以回應到牽手與擁抱為止，再往前就用劇情轉開。平台規範的部分由你把關，有衝突時以規範為準並告訴我。
```

### 一個版本只改一件事

「開場白太長、她太快示好、世界觀太薄、名字也換一下」會讓 Agent 同時修改多處，事後無法判斷哪項修改有效，也容易改到你沒要求的地方。每個版本只指定一件事，其餘請 Agent 列出來先不動。

可以這樣寫：

```text
這個版本只處理「她太快示好」。其他你注意到的問題列出來，先不動。改完告訴我修改了哪些檔案、各改了什麼。
```

### 要求完整的試玩，並查看工作紀錄

「你測過了嗎」得到的回答多半是「測過了」，而 Agent 自行試玩兩輪，只能確認開場白可以運作；卡片能否延續要看十輪之後，較弱的模型最先出現問題。完整的試玩會消耗點數，Agent 會先告知費用。試玩結束後，除了它的總結，也請查看卡片資料夾中的 `README.md`：這是 Agent 的工作紀錄，包含每個版本的決定、否決的方向與證據。

可以這樣寫：

```text
用一個較弱的模型和一個較強的模型各試玩 10–20 輪，每次新開對話。告訴我從第幾輪開始無法延續、原因是什麼，並把結果記進 README.md。開始前先告知點數。
```

### 回報現象，不指定修法

「把定義第二段改短」是在替 Agent 開藥方；你看到的是遊玩時的效果，Agent 看到的是整張卡的結構，原因往往不在你以為的那一段。描述你觀察到的現象，請它找原因，並要求與上一版用同一組對話比較，而不是只回報「已修正」。

可以這樣寫：

```text
第三輪她就主動示好了，我希望慢很多。請找出原因再修改；修改後用同一組對話與上一版比較給我看。
```

### 只要意見時先說明

「這張卡是不是該走劇情路線？」看起來是提問，但 Agent 無法確定你是在問，還是在要求它改；兩者混在一起時，它會選擇執行修改。只想聽取意見時，明確說明只需要意見。

可以這樣寫：

```text
先不要修改任何檔案。這張卡走劇情或陪伴，各有什麼代價？說明後等我決定。
```

### 接續上次的工作

新開一個對話時，Agent 不記得上次做了什麼；「繼續改那張卡」會讓它從頭推測。卡片資料夾裡的 `README.md` 是它的工作紀錄，請它先讀再動。

可以這樣寫：

```text
接續 cards/maid 這張卡。先讀資料夾裡的 README.md，告訴我上一版做到哪裡、還有哪些待辦，再開始。
```

### 發出指令前的檢查

- 玩家是誰、面對什麼，是否只用題材名稱帶過？
- 角色的聲音，是否只有形容詞而沒有一句樣本？
- 畫面要哪一種、不要哪些預設，是否說明了？
- 完成的標準與可自行決定的範圍（含點數上限），是否寫出來了？
- 這一則指令，是否只要求一件事？

## 點數與界線

- 起草、推送、檢查和渲染都不消耗點數。
- 試玩會消耗點數，Agent 會先徵求你的同意。
- Agent 只會修改試玩卡和你自己的私人卡，不會替你送審或公開。
