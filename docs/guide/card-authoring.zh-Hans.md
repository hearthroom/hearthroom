# 写卡指南

这份指南整理了网页编辑器各分区的写法、世界书与卡片变量的设置方式、公开送审条件，以及沙箱聊天页的显示规则与互动脚本规格（`/zh-Hans/guide.md`）。

## 最快做出第一张卡

第一次打开创建角色卡页面时，左边虽然列了好几个分区，但其实只要填好四个必填项就能保存试聊；手头有其他平台导出的旧卡，也能直接拖进来自动填好。

### 手写新卡的四个必填项

想先让角色开口说话，按顺序填好这四处即可：

1. “**基本资料**”**分区 → “角色名称”**：角色的名字。
2. “**基本资料**”**分区 → “形象”下的“背景图（竖版）”**：建议使用 9:16 竖图，这张图会同时用作首页卡片封面、聊天头像与导出 PNG 的卡图。上传框画有虚线安全区，把角色的脸和主体放在框内，不同屏幕裁切时才不会切到头；手头没图也可以直接点生成按钮，用充值积分让 AI 当场画一张。
3. “**角色设定**”**分区 → “角色设定”**：写清楚角色是谁、和玩家是什么关系、怎么说话、处在什么境况里。
4. “**开局**”**分区 → “开场白”**：对话开始时角色对玩家说的第一段话。

四项填好并保存后，编辑页右侧的“**对话测试**”面板就会开放，不用离开编辑页就能直接跟角色试聊。在宽屏显示器上，拖动“对话测试”面板左缘的把手可以自由拉宽预览画面；如果你中途改了左边的字段，记得点一下测试面板上的“存档并重载”，右边才会用上最新改动。

### 从其他平台导入旧卡

新建角色卡时，“基本资料”分区最上方有导入区域，支持把其他工具做好的卡直接搬进来：

| 来源 | 导入方式与带入内容 |
|---|---|
| SillyTavern | 将 PNG、JSON 或 CHARX 角色卡拖进导入区。角色设定、开场白、世界书与正则脚本会自动填入对应字段；PNG 卡片自带的立绘会设为竖版背景，若卡内另附主背景则优先采用主背景。 |
| 魅魔岛（MMD）三件套 | 分别导入规则文件（含 `chatVersion`）、开场白与人设文件。标记为新版沙箱的规则文件会自动选用“沙箱”聊天页。 |
| AI 风月／RiliAI | 导入角色卡或配置 JSON，自动带入人设、开场网页、世界书、内置样式与变量设置。 |

导入完成后，先保存并在右侧“对话测试”确认开局画面、状态面板与文字显示正常，再决定可见范围或送审。

## 认识编辑器的各个分区

编辑器左边按写卡到上架的顺序分成八个分区，有些字段只给逛卡片页的玩家看，有些则会在每一轮对话送进 AI，动笔前先分清楚才不会浪费对话空间。

| 左侧分区 | 里面有哪些字段 | 谁会看到、什么时候填 |
|---|---|---|
| **基本资料** | **角色名称**、**角色自称**（设定里写 `{{char}}` 时会换成这个名字，留空就用角色名称）、**主要语言**。 **形象**：**背景图（竖版）**，展开“横版背景与分享图”可补宽屏用的 16:9 **横版背景**与发到 Discord／LINE／X 时显示的 1200×630 **分享图**。 **卡片展示**：**一句话简介**（首页卡片显示前两行、卡片页标题下显示前三行）、**介绍**（卡片页专属的 Markdown 说明区，可切换“撰写／预览”，适合放玩法说明、登场角色图鉴与更新记录，**只给玩家看，不会送进 AI 对话**）、**标签**。 | 新建卡片时先填名称、语言与竖图；准备分享或公开上架前，再把简介、介绍与分类标签补齐。 |
| **角色设定** | **角色设定**（核心人设、关系与世界规则，只进模型，不对玩家公开）、**对话示例**（用一问一答示范角色的语气和句长，写两三轮最能定住说话味道，写太多反而容易绑死）。 展开“回复格式与额外指示”可填**输出格式**（规定段落结构或括号动作写法）与**额外指示**（每轮对话最后附上的简短提醒，适合放最容易被模型忘掉的一两条规矩）。 | 每张卡的核心。先把角色设定与两三组对话示例写扎实，比填满进阶字段更有用。 |
| **世界**（实验性） | **启用世界模式**：让一张卡容纳多位独立角色。大世界观写在“角色设定”，这里负责添加各个角色，每位角色各有所有人都知道的“侧写”、只有他自己看得到的“完整设定”与“私有世界书”，每回合由世界先裁定谁在场再各自开口。 | 目前还在实验阶段，适合自己测试体验，正式公开的卡片建议先不要开。 |
| **开局** | **开局呈现**二选一： 1. **开场白**：由角色先发出第一条消息，可添加多段备选开场白让玩家挑，也能在下方加**建议的第一句**（玩家点选后会填进输入框）。 2. **开场网页**：在新对话最上方显示一页自定义 HTML 画面搭配**第一句选项**，玩家点选项就开始（网页内容只给玩家看，不会送进模型）。 | 每张卡必填其一。一般剧情与陪伴卡选“开场白”；想做游戏标题画面、选出身或挑路线的卡，可以选“开场网页”或在开场白套用显示规则。 |
| **世界书** | 创建或导入世界书，管理单条设定的关键词、常驻开关与语义召回。 | 当角色背景、地点、支线人物写超过几千字，不想每轮都塞满模型记忆时使用。 |
| **显示** | **聊天页**（“沙箱（推荐）”或“传统”）与**显示规则**（点“设置正则”管理匹配替换规则与顶部功能栏）。 | 纯文字对话卡不用动这里；想把特定标记转成状态栏、选项按钮或自定义界面时再设。 |
| **进阶** | **卡片样式**（调整气泡、输入框、背景颜色与字体，或贴入整张卡共用的自定义 CSS）与**卡片变量**（追踪好感度、背包、任务等精确数值并画成面板）。 | 想换聊天室配色，或做养成、跑团、经营这类数值不能算错的卡时展开设置。 |
| **发布** | **可见范围**（“仅自己”、“知道链接的人”、“公开”）、玩家投票与计数管理、**开启工坊**（作者 DLC 与玩家扩展包）、**还缺什么**检查表与**填写分级问卷**。 | 决定谁能玩这张卡，以及准备公开送审时检查字数门槛与分级。 |

## 用世界书管理长篇设定

当地名、登场人物、阵营规矩越写越多，全部塞进“角色设定”会占满每一轮的对话空间；把这些“聊到才需要想起来”的背景拆进“世界书”，AI 在长篇对话里才记得住真正重要的剧情。

进到“世界书”分区点“建一本”（或点“导入世界书文件”带入酒馆、RiliAI 的世界书 JSON），就能逐条添加设定。每一条设定有两种带入对话的方式：

- **常驻（每轮都带）**：勾选后，无论玩家聊什么，这一条都会固定放进对话开头的缓存区（同时计入公开送审的 3,000 字有效字数）。适合放整张卡随时不能忘的核心规则，建议保持精简；如果常驻条目太多装不下模型额度，排在前面的条目会优先保留。
- **关键词与语义召回（默认）**：不勾常驻时，填好“关键词”（多个词用顿号分隔，也支持 `/pattern/flags` 正则表达式；若再填“次要关键词”，则需两边同时命中才触发）。玩家或角色提到关键词时，该条设定就会带进对话；另外系统默认开启“**语义召回**”，就算没精准说出关键词，只要当下话题语义相关，也会在额度内自动挑进来。

如果你写的是推理真相、后期反转或隐藏支线，不希望前两轮因为话题擦边就被“语义召回”提前翻出来，只要把那一条的“**语义召回**”**关掉**，它就会严格等到关键词命中时才出现。单条内容建议控制在 500 字左右、一件事一条，标题直接写清楚内容（比如“黑市药商老陈”，不要写“人物 03”），开启深入准备（Agent 模式）时角色也能按标题主动查阅。

## 加上状态栏、选项按钮与卡片变量

想在回复底下显示当前地点、好感度或行动选项，最省事的做法连正则表达式都不用写；如果做养成、经营或跑团卡，需要严格计算金钱与道具数量，再开启“卡片变量”交给系统记账。

### 免写规则的内置状态栏与选项按钮

只要在“角色设定”或“输出格式”里交代 AI 在每条回复末尾按下面的格式输出，聊天页就会自动把它们画成整齐的状态面板与可点击的选项按钮（玩家点按钮会把文字填进输入框）：

```text
[status]
地点: 旧城区钟楼
时间: 23:40
警戒值: 35/100
[/status]

[choices]
推开暗门往下走
留在原地听脚步声
[/choices]
```

数值写成 `35/100` 或百分比时，系统会自动画成进度条。只有当你想把面板改成卡片专属的美术风格时，才需要自己写显示规则覆盖它。

### 用“卡片变量”精确记住好感度、金钱与背包

如果只靠文字让 AI 自己记“当前剩 130 枚金币、包里有两瓶药水”，聊久之后模型很容易算错，玩家退回上一句或重新生成回复时数字也会乱掉。展开“进阶”分区点“**添加卡片变量**”，可以把这类数据交给系统精确管理：

1. **定义初始骨架**：用 JSON 写好一开始有哪些字段与初始值（不知道怎么写可以直接点“插入示例”，套用现成的“好感度”、“背包”或“任务”模板）。每一轮都会把当前数值送给模型，字段越精简越省额度、回复也越快。
2. **填写“变量规则”**：用白话写给 AI 看什么情况该加减哪个值（例如：“只有送出对方真正喜欢的礼物时好感度才增加，单次最多 +5；买东西时扣减对应金币”）。AI 会在每轮回复末尾自动附上隐藏的更新指令，玩家重新生成或退回消息时，数值也会自动回到对应那一轮的状态。
3. **设计“面板皮肤”（选填）**：用 Handlebars 语法（如 `{{affection}}`、`{{#each bag}}`）写一段 HTML 与 CSS，玩家在聊天页就能点开面板查看当前数值与本轮变化；下方“面板预览”可以实时检查画面。

## 自定义聊天外观、显示规则与聊天页

想给角色卡换一套气泡与背景配色，到“进阶”分区的“卡片样式”就能直接挑颜色；如果要把 AI 输出的文字标记变成自定义面板、按钮或互动画面，则在“显示”分区设置聊天页与正则规则。

### 用“卡片样式”调整配色与字体

展开“进阶”分区的“**卡片样式**”，可以直接设置气泡、输入框、发送键、背景底色与字体，或在下方的“自定义 CSS”贴入整张卡共用的样式（不必加 `<style>` 标签，也不必填匹配文字，打开聊天页时应用一次，上限为 512 KB）。如果是从 AI 风月搬过来的整体美化 CSS，直接贴在这里就能自动对应到本站的气泡与输入框。

### 常用外观变量

下面这组 CSS 变量在“沙箱”与“传统”两种聊天页都有效，写在“卡片样式”的 `.canvas-root` 里就能统一调整卡片外观：

| 外观位置 | 变量名称 |
|---|---|
| AI 气泡底色 | `--lt-canvas-bubble-ai-bg` |
| 气泡文字颜色（AI 与玩家共用） | `--lt-canvas-bubble-fg` |
| 玩家气泡底色 | `--lt-canvas-bubble-user-bg` |
| 输入框底色 | `--lt-canvas-composer-field-bg` |
| 发送键底色 | `--lt-canvas-send-bg` |
| 强调色 | `--lt-canvas-accent` |
| 字体（完整的 CSS `font-family` 列表） | `--lt-canvas-font` |
| 对话背景色 | `--lt-canvas-bg` |

```css
.canvas-root {
  --lt-canvas-bubble-ai-bg: #243447;
  --lt-canvas-bubble-fg: #f2f2f5;
  --lt-canvas-bubble-user-bg: #37465b;
  --lt-canvas-composer-field-bg: #1e2938;
  --lt-canvas-send-bg: #355a7c;
  --lt-canvas-accent: #8fc9ff;
  --lt-canvas-font: system-ui, sans-serif;
  --lt-canvas-bg: #121b28;
}
```

魅魔岛（MMD）原有的 `--background-color`、`--primary-font-color` 与 `--input-background-color` 变量同样可以继续使用。变量只会影响采用该变量的元素；如果卡片的 CSS 已经直接对某个元素写死颜色，直接指定的颜色会优先，而且“显示规则”里的样式也会盖过“卡片样式”的设置。

### 用“显示规则”把文字标记换成自定义画面

在“显示”分区点“**设置正则**”，可以创建多条查找与替换规则。消息显示到画面上之前，会从上往下依次应用所有启用的规则（模型不会看到转换后的 HTML）：

- **应用于**：每条规则可勾选应用在“AI 回复”、“玩家消息”或“系统消息”。新建规则默认只勾“AI 回复”；旧规则若没有这项设置则保持三种都应用；酒馆导入的规则会按原本的玩家／AI 设置自动换算。若三种都不勾仍可保存，该规则不会改写对话消息，但仍会展开顶部的“功能栏”。
- **匹配（查找）**：可以填一段固定字符串（如 `《状态栏》`），或填 `/pattern/flags` 格式的正则表达式（如 `/<status>([\s\S]*?)<\/status>/g`）。使用正则表达式时，替换内容里可用 `$1`、`$2` 取用括号捕获的文字，而且匹配模式里的中文会自动同时匹配简体与繁体字形。
- **替换内容（取代）**：可写任意 HTML，也能放 `<style>` 与 `<script>`。所有启用规则里的 `<style>` 会在开卡时合并成同一份样式表，每段 `<script>` 每张卡执行一次。
- **功能栏**：规则编辑器上方的“功能栏”会固定钉在消息列表顶端，只显示给玩家看、不会送给 AI。常见做法是在功能栏里放入触发词（例如 `【状态栏】【美化】`），再交给下方的规则展开成顶部面板或侧边菜单。
- **可用宏**：替换内容支持 `{{user}}`（玩家的称呼）与 `{{char}}`（角色名称，设有角色自称时用自称）。
- **容量与实时测试**：单条规则替换内容上限为 512 KB（超过 256 KB 时编辑器会提醒可能影响流畅度，但仍可保存），整份规则上限为 32 MB（超出时编辑器会显示超出量）。写好后可以直接把一段 AI 回复贴进规则编辑器右边的“**测试**”栏，当场查看应用全部规则或单条规则后的效果。

### 沙箱聊天页与传统聊天页

在“显示”分区的“**聊天页**”可以切换两种运行环境，两边的聊天界面（页眉、消息、输入区、面板）长得一样，差别在于卡片样式与脚本跑在哪里：

- **沙箱（推荐，新卡默认）**：卡片的样式与脚本运行在独立隔离的页面里，可以自由改造整个聊天画面（与魅魔岛 MMD 新版沙箱兼容），同时保护玩家的登录状态不被脚本读取，发送消息、重新生成等会扣积分的操作也只响应玩家本人的点击。
- **传统**：规则直接套在网站原本的聊天页上，没有沙箱的 `sdk` 能力。只有在导入的老卡切到沙箱后显示异常时才需要改回传统。

把既有卡片切到“沙箱”后，打开右侧“对话测试”检查顶部功能栏、开场白里的面板、浮动按钮与菜单是否正常（贴齐画面左右边缘的窄侧边按钮栏，聊天页也会自动把对话栏往内缩，避免遮挡文字）。多数卡片不用改就能直接跑；若有脚本需要调整，可查阅末章的[从传统页迁移](#从传统页迁移)。

## 可见范围、送审条件与工坊扩展

卡片写好之后不一定要马上公开，你可以先设成只有自己或拿到链接的朋友能玩；准备发到站上榜单积累热度、领取聊天返点与榜单奖金时，再到“发布”分区补齐分类标签与分级问卷。

### 三种可见范围

在“发布”分区的“**可见范围**”可以随时切换：

| 可见范围 | 谁能打开这张卡 | 适用场景 |
|---|---|---|
| **仅自己** | 只有作者本人，以及之前已经玩过这张卡的老玩家可以继续对话；新玩家打不开，也不会出现在任何公开列表。 | 自己私下玩，或暂时收起不让新玩家进入。 |
| **知道链接的人** | 不会出现在首页、排行榜与搜索结果，也不用先经过审核；只要拿到卡片链接的人都能直接打开游玩与评论，玩到的是你最新保存的内容。 | 公开前请朋友帮忙试玩，或在小圈子里私下分享。 |
| **公开** | 送审通过后出现在首页、分类与搜索结果，新玩家玩到的是已过审的稳定版本。其他玩家在卡上聊天你就能分到积分返点，新发布的卡也会自动参加日榜、周榜与月榜奖金结算。 | 正式上架发表作品。 |

### 公开送审的三个条件

“发布”分区的“**还缺什么**”面板会自动帮你检查公开上架前必备的项目：

1. **至少选一个官方分类或玩法标签**：在“基本资料 → 标签”下方的分类选择器里至少挑一个（自己手打的自定义标签可照留，但不算进这项门槛）。
2. **有效字数超过 3,000 字**：“角色设定”加上“已启用的世界书常驻条目”合计至少要有 3,001 个有效字，两边可以互相补足。中英文字母与数字均按字符计算；空白、标点符号、表情符号、HTML／样式／脚本标签与模板变量不计入，开场白、对话示例、额外指示与非常驻的世界书条目也不计入门槛。
3. **填写分级问卷**：点“填写分级问卷”，照卡片里实际写到的设定、图片，以及故事最深会走到哪种尺度如实勾选（按台湾游戏软件分级标示在卡片页，成人级卡片只对已开启成人内容开关的玩家显示；包含恋爱交往或结婚情节的卡片至少为 12+）。

卡片公开之后，你在编辑器里保存修改只会更新你自己的草稿，不会马上动到线上玩家正在玩的版本；等改完确认无误再次送审通过，新版才会正式上线。更新送审时默认不发通知，勾选通知并附上更新说明才会推送给收藏与关注你的人（每张卡每 3 天最多发送一次更新通知）。

### 开启工坊（作者 DLC 与玩家扩展包）

在“发布”分区打开“**开启工坊**”开关（默认关闭）后，卡片页会多出“工坊”分页：原作者自己可以发布**作者 DLC**（追加额外开场白、显示规则与世界书条目），其他玩家也能为这张卡制作**玩家扩展包**（仅限追加世界书条目，单个扩展包的常驻世界书上限为 1,500 字，且玩家扩展包完全读不到原卡私有的角色设定、世界书与正则规则）。

## 沙箱互动脚本与兼容性参考

当你想在卡片里写 JavaScript 脚本控制输入框、做跨设备存读档、接全服玩家投票，或是把旧版传统页的卡片搬进沙箱时，可以在这一章查阅完整的节点选择器、`sdk` 方法、事件与错误码。

### 节点选择器与沙箱专用 CSS 变量

沙箱页提供固定的 `data-chat` 与 `data-slot` 属性，与魅魔岛（MMD）新版沙箱规格一致，同一份脚本可在两边运行。请用下列属性选取节点，不要依赖网站内部的 class 名称：

| 选择器 | 说明 |
|---|---|
| `[data-chat="root"]` | 聊天画面的根节点。`data-theme` 为 `dark`／`light`；`data-composer` 表示输入区是否显示。 |
| `[data-chat="message"]` | 单条消息容器。`data-from` 为 `ai`／`user`；`data-state` 为 `pending`／`streaming`／`done`；`data-msg-id` 为服务器端的消息 ID。 |
| `[data-chat="message-body"]` | 消息正文（应用显示规则后的 HTML）。 |
| `[data-slot="statusbar"]` | 顶部功能栏容器。 |
| `[data-slot="left"]`／`[data-slot="right"]` | 左右侧边栏停靠槽。放进这里的元素视为该侧停靠侧边栏，对话栏会自动让出宽度。 |
| `[data-chat="author-stage"]` | 作者舞台层。调用 `sdk.stage.open('content')` 覆盖消息区，`open('full')` 覆盖整页。 |
| `[data-chat="input"]` | 消息输入框。 |
| `[data-chat="composer"]` | 底部输入区整体容器。 |

除了双页共用的[常用外观变量](#常用外观变量)之外，沙箱壳的颜色与尺寸另外由 `--chat-*` 系列 CSS 变量定义（例如 `--chat-bg`、`--chat-text`、`--chat-accent`、`--chat-bubble-ai-bg`），在根节点覆写即可整体换色；这组变量只在沙箱聊天页有效。

### `sdk` 方法一览

| 方法 | 说明 |
|---|---|
| `sdk.input.get()` / `set(text)` / `add(text)` / `insert(text)` / `clear()` / `focus()` / `blur()` / `getCursor()` / `setCursor(pos)` | 读写与控制底部输入框文字及光标位置。 |
| `sdk.composer.show()` / `hide()` / `visible()` | 显示、隐藏底部输入区，或查询当前是否显示。 |
| `sdk.message.send(text)` | 以玩家身份发送消息。若不在玩家本人的点击事件当下调用，系统会先弹出确认窗口。 |
| `sdk.message.edit(id, text)` | 改写指定消息（`data-msg-id`）并重新发送，同样需经玩家点击或确认。 |
| `sdk.save.get(key)` / `set(key, value)` / `remove(key)` / `keys()` | 跨设备永久存档。每张卡每位玩家最多 10 个 key；key 限英文字母、数字、`_`、`-`；单笔 JSON 值上限 64 KB。 |
| `sdk.cache.get(key)` / `set(key, value)` / `remove(key)` | 单次开页暂存，刷新或离开页面后清空。 |
| `sdk.stage.open(mode)` / `close()` / `el()` / `visible()` | 开关与获取作者舞台节点（`mode` 为 `'content'` 或 `'full'`）。 |
| `sdk.role.get()` | 获取角色名称与头像网址。 |
| `sdk.user.get()` | 获取玩家称呼、头像与界面语言（`locale`，例如 `zh-Hans`）。 |
| `sdk.text.convert(text)` / `sdk.text.ready()` | 将脚本自己画在画面上的文字转为玩家当前的简繁字形，转换规则与聊天页处理回复正文一致；卡片语言与玩家字形相同时原样返回。字典加载完成前 `convert` 会先原样返回，`ready()` 会在字典就绪时完成（不需转换时立即完成）。 |
| `sdk.model.get()` | 获取玩家当前选用的模型信息 `{ name, cost }`：`name` 为顶栏显示的“模型名 · 线路名”，`cost` 为下一轮预估积分（动态计价模型为区间字符串，如 `127–251`）；平台尚未传入前两者皆为空字符串。若要让玩家切换模型，请引导点击输入区的模型按钮。 |
| `sdk.generation.get()` | 查询当前这一轮生成等待状态 `{ phase, since, outcome }`。 `phase` 为 `idle`、`preparing`（刚发出尚无回应）、`summarizing`（平台正在压缩整理长篇剧情，在第一个字出现前可能耗时数十秒）、`thinking`（模型思考中、正文尚未开始；不支持思考的模型无此阶段）或 `writing`（正文流式输出中）；`since` 为进入该阶段的毫秒时间戳（不含思考内容原文）。 `outcome` 在正常结束或生成中为 `null`；上一轮未正常完成时，返回聊天页显示在消息下方的状态卡 `{ kind, label, sub, actions }`。`kind` 可能为 `model-error`、`network-error`、`server-error`、`rate-limit`、`quota`（积分不足）、`filtered`、`length-cap`、`stopped`、`compact-retryable`、`outcome-unconfirmed`（结果确认中，无按钮，完成后自动更新）或 `interrupted`（Agent 准备尚未跑完）；`label` 与 `sub` 为玩家语言的说明文字；`actions` 为可用按钮数组 `[{ action, label }]`，`action` 值为 `retry`、`continue`、`switch-model`、`model-settings`、`capacity`、`refresh`、`retry-stream-off`、`edit-message`、`switch-lane`、`resend-traditional`。最后四项仅出现在 `filtered` 状态卡：`retry-stream-off` 会先关闭本段对话的流式输出再重试、`edit-message` 打开被拦截的消息供玩家修改并取代原消息重发、`switch-lane` 打开模型菜单并停在当前模型的其他线路、`resend-traditional` 将含简体字的被拦截消息整句转为繁体后直接取代重发（同一条仅提供一次）。 |
| `sdk.generation.act(action)` | 触发上述状态卡上的指定按钮（传入 `outcome.actions` 内的 `action`），效果与玩家亲手点击平台状态卡相同（例如重试会沿用原消息，不会多发一条）。必须在玩家点击事件当下调用（否则拒绝并返回 `UNAUTHORIZED`，不会弹窗询问）；当前状态卡未提供该动作返回 `INVALID_ARGS`；生成中返回 `BUSY`；每分钟最多调用 3 次，返回 Promise。 |
| `sdk.archive.list()` / `save(title?)` / `fork(messageId)` / `open(id)` / `start(opening?)` / `rename(id, title)` / `remove(id)` | 操作平台的对话存档（每张卡最多 20 段，含当前这段，跨设备同步）。`open` 读取指定存档（原进度保留在列表中）；`save` 把当前进度留一份并取名，返回 `{ id, current }`（`id` 为保留下来的旧存档，后续在复制出的 `current` 继续游玩）；`fork` 从指定消息（气泡的 `serverId`）另开一段分支；`start` 另开新对话（`0` 为主开场白，`1` 以上为对应备选开场白）；`list` 返回 `{ items, count, limit }`，每项含 `id, title, isCurrent, messageCount, lastMessage, createTime, lastUpdateTime`。会改动存档的操作请在玩家点击当下调用并搭配卡片自制确认画面；不在点击当下调用时，系统会弹窗询问玩家。 |
| `sdk.on(event, handler)` | 订阅聊天页事件。 |
| `sdk.debug.log(...args)` | 输出调试日志；在聊天页网址加上 `?sdkDebug=1` 即可打开调试面板查看。 |

### 事件、执行规则与错误码

| 事件名称 | 触发时机与载荷 |
|---|---|
| `ready` | 开页时既有消息全部挂载完成后触发一次（不补发）。 |
| `message:new` | 新消息建立时触发。 |
| `message:mount` | 消息节点挂载进画面时触发（晚订阅会收到已挂载消息的补发）。 |
| `message:stream` | AI 流式输出文字更新时触发。 |
| `message:done` | 单条消息输出完成时触发（晚订阅会收到已完成消息的补发）。 |
| `message:unmount` | 消息节点从画面移除时触发。 |
| `input:change` | 输入框文字变更时触发。 |
| `conversation:switch` | 读档、存档、分支或开新对话切换会话后触发，载荷为 `{ conversationId }`。 |
| `theme:change` | 切换深色／浅色主题时触发。 |
| `back` | 玩家按下页眉返回键时触发。 |
| `stage:close` | 作者舞台关闭时触发。 |
| `dispose` | 页面即将卸载时触发。 |
| `model:change` | 玩家更换模型，或下一轮预估积分变动（如调整上下文长度、思考深度）时触发，载荷同 `sdk.model.get()`。 |
| `generation:phase` | 生成等待阶段改变时触发，载荷为 `{ phase, since }`（不补发，晚到的脚本请先调用 `sdk.generation.get()`）。 |
| `generation:outcome` | 上一轮异常状态卡出现或因重试收起时触发，载荷同 `sdk.generation.get().outcome`，可能为 `null`（不补发）。 |
| `share:change` | 分享设置或玩家推荐码晚一步加载完成时触发（无载荷，请重新读取 `sdk.share`）。 |

脚本执行时遵循四条规则：

- 开页加载既有对话时，每条消息依次触发 `message:new`、`message:mount`、`message:done`，全部跑完后触发一次 `ready`。
- 在消息事件处理函数（以及消息气泡内的点击／输入事件处理函数）里调用 `document.querySelector` 等查询方法时，只会搜索**该条消息气泡**；在处理函数外部调用才是整份 `document`。
- 沙箱脚本无法对外部网址发起网络请求（`fetch` 等），但外部 `<script src="https://…">`、图片与字体文件可以正常加载。
- 一般错误码：`UNAUTHORIZED`（玩家拒绝确认或非点击当下调用受限操作）、`RATE_LIMITED`（调用过于频繁）、`INVALID_ARGS`（参数不合法或超过容量上限）、`HOST_DENIED`（宿主页拒绝此操作）、`BUSY`（正在生成回复中）、`LIMIT_REACHED`（对话存档已满；`err.data` 为 `{ count, limit }`，请提示玩家先删一段旧存档）、`NOT_SUPPORTED`（当前环境不支持此功能）。

### 可靠的消息历史（`sdk.history`）

需要根据完整对话记录重建游戏状态时，沙箱卡可使用 `sdk.history`（传统卡为 `stage.history`），不要依赖画面上随滚动装卸的 DOM 气泡：

- **探测与分页读取**：先检查 `history?.capabilities().available`（旧版宿主页与离线预览可能不支持）。调用 `list({ cursor, revision, content: true })` 只会读取当前玩家在这张卡当前对话的记录；续读下一页时必须沿用第一页拿到的 `revision`，将各页累积到收到 `complete: true` 的最后一页后，才采用整份清单（中途遇到 `HISTORY_STALE` 代表对话已变动，需放弃半途结果从头读起）。
- **消息关联（`replyTo`）与状态判定**：每条记录都带有 `replyTo: string | null`。AI 回复的 `replyTo` 指向触发这条回复的玩家消息 `id`（仅供该段对话内部对照的标识字符串，与这份 history 共用同一组 ID，目标消息可能位于另一分页）；玩家消息、开场白与无法核实关联的旧数据／分支复制消息填 `null`（旧宿主也可能省略此栏，请一律视为未知，不要靠前后相邻顺序猜测）。重新生成会建立新的玩家与 AI 消息 ID，新回复指向新的玩家 ID；手动编辑 AI 回复会保留原 ID 与 `replyTo`；退回会移除舍弃的消息；若玩家消息被删除而 AI 回复仍保留，该回复的 `replyTo` 会变为 `null`。一般接续原回复文字的续写（`contine`／`continue_response`）仍不支持；继续已保存的 Agent 准备进度则会沿用原本的玩家消息 ID。开启 `content: true` 取回的正文，只包含已经输出完毕、画面上看得到的原文（不含思考过程、还在流式输出中的文字，或因内容审核隐藏的文字），请用 `item.complete` 判断回复是否完整结束，不要把中断或失败的回复当成成功存档点。
- **订阅变更（`onChange`）**：调用 `onChange(callback)` 会返回取消订阅函数。每次变更项带有 `{ op, id, replyTo, replacementId? }`（`add`／`update` 的 `replyTo` 为读取当下可核实的关联，`remove` 一律为 `null`；从未挂载进画面或已卸载的消息被真正删除时一样会收到变更，单纯滚出可视区的 `message:unmount` 不算删除）。收到第一包事件时，请先把卡片推算的衍生状态标为待确认，等重新取回完整清单后再计算（就算只收到玩家消息删除，相关 AI 回复的关联也可能一并变成未知）。旧游标、`reset` 或 `unavailable` 代表未知，不是空历史。其他设备在前台每 15 秒及切回前台时会检查更新；离开卡片时记得取消订阅。`revision` 与上述对话内 ID 都不是玩家账号身份。

### 全服投票、共斗计数与分享回流（`sdk.shared`）

在规则文件 `rules.json` 的 `sharedState` 声明过的投票题目与计数器，由所有玩这张卡的玩家共用同一份统计，通过 `sdk.shared`（传统卡为 `window.stage.shared`）读写：

- **`read(keys)`**：接收单个 key 或最多 16 个 key，返回 `{ [key]: { kind: 'poll', counts, total, mine? } | { kind: 'counter', total, mine?, goal?, reachedAt?, previous? } }`。未声明的 key 不在结果里；`mine` 为玩家自己投的选项或贡献（未登录访客没有）；计数器的 `total`、`mine` 与排行榜每一期重新开始，`previous` 为上一期的总数。
- **`vote(key, option)`**：返回 `{ mine }`。同一题每人每天最多投或改 10 次，第一次投票也算；重复投给同一个选项不计次。
- **`add(key, delta)`**：加上 `1` 到该计数器 `maxStep` 之间的整数，返回 `{ total, mine, reachedAt }`。
- **`leaderboard(key, { limit })`**：返回本期贡献最多的玩家 `{ items: [{ rank, name, value }], mine? }`（默认 10 名、最多 50 名，以公开昵称显示，不列出测试账号）。

所有人都能读；写入需要已登录且玩过这张卡的玩家（开过一段对话即可）。数字不会主动推送，请自行重读，间隔至少 10 秒。作者可以在自己任何一张卡上测试（含全新私卡与 CLI 试玩卡），作者自己的数字与正式玩家分开；作者草稿试玩（`?mode=source`）与测试账号也各有独立的一份数字，不混进正式统计，可在编辑页“发布”分区的“玩家投票与计数”或用 `hearthroom card state` 查看、暂停与清零。

若想做“把题目分享给朋友填、收回统计解锁内容”的玩法，可为声明了 `share: true` 的投票调用异步方法 `sdk.share.tallyLink(code, pollKey)`（请在点击前准备好链接；同一组情境码与投票会拿回同一条 `?share=~XXXXXXXX` 短链接，每位玩家每天最多 20 条，90 天内有效）。朋友打开后，`sdk.share.context` 是情境码，`sdk.share.poll` 是可回答的题目 `{ key, options }`（没有时为 `null`），用 `sdk.share.respond(option)` 作答（每条链接各记一份，与主投票分开）。分享者用 `sdk.share.results()` 读取自己发出的链接，每笔为 `{ context, pollKey, total, counts, updatedAt }`：`total` 实时更新，`counts` 要满 3 位朋友回答才出现并每天更新一次。卡片不会知道谁分享、谁回答；可依数字解锁卡内内容，但不会发放平台积分。沙箱与传统两种页面使用同一组错误码：`SHARED_DISABLED`（平台或作者已暂停）、`NOT_DECLARED`、`OPTION_INVALID`、`NOT_ELIGIBLE`（还没玩过此卡，或回答自己的链接）、`UNAUTHORIZED`（未登录）、`RATE_LIMITED`（稍后再试）、`LIMIT_REACHED`（`err.data.reason` 为 `goal` 或 `limit`）与 `HOST_DENIED`（旧版游玩页；查看过去的对话或审核试玩时只读；从未送审也没设过可见范围的试玩卡无法用 `tallyLink` 生成回流链接，因为别人打不开）。

### 分享图片、复制文案与带情境的分享链接

- **分享图片与复制文案（浏览器原生能力）**：HTTPS 卡片框架由宿主页委派 `web-share` 与 `clipboard-write` 权限（不委派 `clipboard-read`）。脚本可在玩家点击按钮后调用 `navigator.share`（接收事先准备好的图片 `File` 与文字）、`navigator.clipboard.write` 搭配 `ClipboardItem`（写入 PNG）或 `navigator.clipboard.writeText`（写入文案）；这些是浏览器原生能力，不是新增的 `sdk` 方法或 HTTP 接口。提供按钮前请先检查 `navigator.share`、`navigator.canShare({ files: [file] })`、`navigator.clipboard.write` 与 `ClipboardItem`，并在点击前就准备好文件以保留用户点击激活状态。支持情况取决于浏览器、操作系统、权限与接收 App，分享后不保证图片与文字都会同时保留；请捕获拒绝与取消，不支持或被拒时改提供下载图片与可选取的文案，玩家取消后不要自动重开分享面板。本地不透明来源的预览仍可能拒绝调用，请在目标设备的实际跨源卡片上验证。
- **带情境码的分享链接（`sdk.share`）**：调用 `sdk.share.link(code)`（传统卡为 `window.stage.share.link`）会同步返回这张卡的分享链接 `/cards/<卡号>`，带上已登录玩家的推荐码，给了情境码时再加上 `?share=<code>`（请在点击前生成链接，在点击处理函数内交给 `navigator.share`；推荐码较晚取得时会触发 `share:change` 事件，届时可重读更新链接）。朋友从这条链接开卡时，脚本可由 `sdk.share.context` 读回同一个情境码（没有带码或正在查看过去的对话时为 `null`），做出“你朋友选了这个，轮到你接手”的互动。情境码只收 1 至 64 个英文字母、数字与 `.`、`_`、`-` 且开头须为英文字母或数字（不合规则时沙箱卡抛出 `SHARE_CONTEXT_INVALID`，传统卡得到 `null`）；平台只负责传递字符串，不会送进模型、也不含玩家数据，而且任何人都能手输网址，请只接受卡片自己定义的代码，朋友是否已有存档由卡片自行判断（例如查 `sdk.archive.list()`；未登录访客没有存档）。`sdk.share.audience` 表示谁打得开这条链接：`author`（仅自己可见的卡，新朋友打不开）、`link` 或 `public`。平台关闭分享开关时 `sdk.share.enabled` 为 `false`，`context` 为 `null` 且 `link()` 返回普通卡片链接。另可用 `sdk.share.qr(text)` 获取 `{ size, path }`（`size` × `size` 格的 SVG path）画进分享图。作者可用 `?mode=source&share=<code>` 在草稿上测试。

### 侧边栏自动避让（`--lt-dock`）与样式兼容细节

- **固定侧边栏避让**：贴齐画面左右边缘、宽度约 48px 以内的固定按钮栏，聊天页会自动把中间对话栏往内缩（沙箱与传统页皆适用；全屏弹窗、居中面板与更宽的区域不会自动缩进）。想手动指定或关闭避让时，直接在侧边栏最外层元素的 `style` 属性写入 `--lt-dock`（写在行内 `style` 对所有卡片格式都有效）：

| `--lt-dock` 值 | 效果 |
|---|---|
| `left`／`right` | 强制视为停靠在该侧的侧边栏，不必贴齐边缘，宽度上限放宽到对话栏的 30%。 |
| `none` | 不为这个元素让出空间。若写在 `:root` 上则整张卡停用自动避让（SillyTavern 格式卡片的显示规则样式只作用在消息内，写在 `:root` 无效）。 |

```html
<div id="my-sidebar" style="position: fixed; left: 0; top: 30%; --lt-dock: left;">…</div>
```

若扣除侧边栏后对话栏剩余宽度不足原本的 75%，系统不会缩进；实际让出的宽度会写在 `<html>` 的 `--lt-canvas-dock-left` 与 `--lt-canvas-dock-right`（未缩进时不存在），可供卡片对齐自己的元素。

- **卡片样式与显示规则的兼容层级**：AI 风月写法的 CSS 放在“进阶 → 卡片样式”（CLI 为 `card.css`，上限 512 KiB UTF-8 字节）时，系统会自动把 `#customized-answer-content`、`#ai-chat-input`、`#ai-send-button` 等已知风月选择器对应到本站的气泡、输入框与发送键，作者不必手选来源，同一段 CSS 也能混用风月与本站选择器（`.mes` 不会被误判为酒馆来源标记；旧卡若想应用最新风月兼容效果可重新导入）。“显示规则”里的 `<style>` 则保持既有 `cssDialect` 与已编译样式标记，没有标记时按原卡片格式决定作用范围（酒馆格式只作用在消息气泡内，其他格式照写生效），不会自动对应风月选择器。整体样式优先级从低到高为：平台默认与主题 ＜ 卡片样式 ＜ 显示规则里的样式；已导入的旧卡在打开与保存时会保留原有的样式设置与优先级。

### 从传统页迁移

传统聊天页常用的选择器（`.mes` 消息容器、`.mes_text` 消息正文、`.mes.Ai`／`.mes.User` 发言方、`#msglistview` 消息列表、`.chat-scope-box` 对话区）在沙箱页里全部保留：

- 只用到 CSS 样式与纯文字／HTML 替换的卡片，切到沙箱后直接可用，不必改规则。
- 用 `<img onerror="…">` 启动脚本的写法在沙箱一样有效，放在“功能栏”或“开场白”里的启动片段都会执行。
- 原本直接去读写网站顶栏、输入框等外部节点的脚本，请改用上方的 `sdk` 方法。
- `localStorage` 在沙箱内仍可使用，但只保存在该张卡自己的隔离源下；需要跨手机与电脑保留进度时，请改用 `sdk.save.*`。

### 疑难排解

| 遇到的情况 | 原因与处理方式 |
|---|---|
| 改了设定或规则，右边“对话测试”没变 | 测试面板跑的是上一次保存的版本，点面板上的“存档并重载”就会更新。 |
| 第一次开卡画面空白十几秒 | 浏览器首次加载沙箱环境资源较慢，之后有缓存就会变快；若超过 20 秒仍空白会跳出提示，刷新页面即可。 |
| 卡片自带的导览或遮罩盖住画面、滑不动 | 这是卡片脚本自带的新手引导层，点画面上的“跳过”或关闭按钮即可。 |
| 规则里的脚本完全没反应 | 在聊天网址后面加上 `?sdkDebug=1` 打开调试面板，查看脚本报错与 `sdk.debug.log` 输出。 |
| `sdk.save` 存档失败 | 检查 key 是否只含英文字母、数字、`_`、`-`，单笔数据是否超过 64 KB，以及这张卡的 key 总数是否已满 10 个。 |
| 对话气泡左右两侧变得比预期窄 | 卡片里贴近画面边缘的装饰元素被自动识别成侧边栏了，在该元素的 `style` 加上 `--lt-dock: none` 即可恢复。 |
