# カード作成ガイド

このガイドでは、キャラクターカードの構成、2 種類のチャットページの違い、ルールとスクリプトの書き方、他のプラットフォームからインポートする際の注意点を説明します。

## カードの構成

| 項目 | 説明 |
|---|---|
| 名前・縦長背景・横長背景（任意） | 縦長画像は PNG 書き出しとチャットのアイコンにも使います。 |
| 紹介文 | ランキングのカードに表示される要約です。 |
| 人物像 | キャラクターの素性、話し方、世界観。 |
| 最初のメッセージ | 会話の最初のメッセージ。複数の候補を設定できます。 |
| 世界設定 | キーワードで呼び出される補足設定。 |
| ルール | 正規表現ルール。返答中の特定のテキストをレイアウト、ステータスバー、ボタンに変換します。 |
| チャットページ | カードが使うチャットページ：サンドボックスまたは従来。新規カードの既定はサンドボックスです。 |

カードを保存すると、編集ページ右側の「会話テスト」パネルでそのまま会話できます。画面が広い場合、パネル左端のハンドルをドラッグするとプレビューの幅を変更できます。

## チャットページ

2 種類のチャットページは同じ画面（ヘッダー、メッセージ、入力欄、パネル）を使います。違いは、カードのルールとスクリプトがどこで実行されるかです。

### サンドボックス

カードの画面とスクリプトは、サイト本体から隔離されたページで実行されます。

- スタイルとスクリプトでチャット画面全体を変更できます。
- スクリプトはプレイヤーのログイン状態にアクセスできません。
- 送信や再生成など、ポイントを消費する操作はプレイヤー本人のクリックにのみ反応します。

### 従来

ルールをサイトのチャットページに直接適用します。既存のカードがサンドボックスで正しく動作しない場合にのみ使用してください。

### 切り替え

編集ページ「基本」セクションの「チャットページ」で切り替えます。既存のカードをサンドボックスに切り替えたら、「会話テスト」を開き、機能バー、最初のメッセージ内のパネル、フローティングボタン、メニュー、各パネルの表示が以前と同じか確認してください。ほとんどのカードは変更不要です。表示されない効果がある場合は「従来ページからの移行」を参照してください。

### サイドバー

画面の左右端に固定されたボタン列がメッセージに重なる場合、チャットページはメッセージ列を内側に寄せ、メッセージが隠れないようにします。サンドボックスと従来のチャットページの両方に適用されます。

自動判定の対象は、画面端に接していて幅がおよそ 48px 以内の列だけです。全画面のダイアログ、中央に浮かぶパネル、幅の広い列は対象外です。サイドバーの最も外側の要素に CSS 変数 `--lt-dock` を設定すると、判定を上書きできます。要素の `style` 属性に書けば、どのカード形式でも有効です。

| 値 | 効果 |
|---|---|
| `left`／`right` | その側にドッキングしたサイドバーとして扱います。画面端に接している必要はなく、幅の上限はメッセージ列の 30% まで広がります。 |
| `none` | この要素のためにスペースを空けません。`:root` に設定するとカード全体で自動調整を行いません（SillyTavern 形式のカードのスタイルはメッセージ内にのみ適用されるため、`:root` は無効です）。 |

```html
<div id="my-sidebar" style="position: fixed; left: 0; top: 30%; --lt-dock: left;">…</div>
```

スペースを空けた結果、メッセージ列の幅が元の 75% 未満になる場合は調整しません。実際に空けた幅は `<html>` の `--lt-canvas-dock-left`、`--lt-canvas-dock-right` に書き込まれ（調整しないときは存在しません）、カード自身の要素の位置合わせに使えます。

## ルール

ルールは「検索」と「置換」で構成されます。返答のテキストは表示前にすべてのルールを順に通過します。

### 検索

固定文字列（例：`《ステータス》`）または正規表現（例：`/<status>([\s\S]*?)<\/status>/g`）。正規表現を使う場合、置換内容の `$1`、`$2` はキャプチャグループに対応します。

### 置換

任意の HTML。`<style>` と `<script>` を含められます。すべてのルールの `<style>` は 1 つのスタイルシートに結合して適用され、各 `<script>` はカードごとに 1 回実行されます。

### 機能バー

ルールエディターの「機能バー」は、メッセージ一覧の上に固定表示される内容です。プレイヤーにのみ表示され、モデルには送られません。通常はここにトリガー語（例：`【ステータス】【装飾】`）を置き、ルールで実際のパネルに展開します。

### マクロ

| マクロ | 値 |
|---|---|
| `{{user}}` | プレイヤーの呼び名 |
| `{{char}}` | キャラクター名 |

### 制限

- 1 つのルールは 256 KB までです。
- ルール全体が上限を超えると、エディターが超過量を表示します。

ルールエディターの「テスト」欄にサンプルの返答を貼り付けると、ルール適用後の結果をすぐに確認できます。

## サンドボックス作者 API

サンドボックスページは、固定のノード属性と `sdk` オブジェクトを提供します。魅魔島（MMD）の新版サンドボックスと同一で、同じスクリプトが両方のプラットフォームで動作します。

### ノード

ノードは class 名ではなく `data-chat` 属性で選択してください。

| セレクター | 説明 |
|---|---|
| `[data-chat="root"]` | チャット画面のルート。`data-theme` は `dark`／`light`、`data-composer` は入力欄の表示状態。 |
| `[data-chat="message"]` | 1 件のメッセージ。`data-from` は `ai`／`user`、`data-state` は `pending`／`streaming`／`done`、`data-msg-id` はサーバー側のメッセージ ID。 |
| `[data-chat="message-body"]` | メッセージ本文（ルール適用後の HTML）。 |
| `[data-slot="statusbar"]` | 機能バー。 |
| `[data-slot="left"]`／`[data-slot="right"]` | 左右のサイドバーの位置。ここに置いた内容はその側にドッキングしたサイドバーとして扱われ、メッセージ列がスペースを空けます（「サイドバー」を参照）。 |
| `[data-chat="author-stage"]` | 作者ステージ。`sdk.stage.open('content')` はメッセージ領域を、`open('full')` はページ全体を覆います。 |
| `[data-chat="input"]` | 入力ボックス。 |
| `[data-chat="composer"]` | 入力欄。 |

### CSS 変数

色とサイズは `--chat-*` 変数で定義されます（例：`--chat-bg`、`--chat-text`、`--chat-accent`、`--chat-bubble-ai-bg`）。ルートノードで上書きすると全体の配色を変更できます。

### sdk

| メソッド | 説明 |
|---|---|
| `sdk.input.get()` / `set(text)` / `add(text)` / `insert(text)` / `clear()` / `focus()` / `blur()` / `getCursor()` / `setCursor(pos)` | 入力ボックスの読み書き。 |
| `sdk.composer.show()` / `hide()` / `visible()` | 入力欄の表示・非表示。 |
| `sdk.message.send(text)` | プレイヤーとしてメッセージを送信します。プレイヤーのクリックイベント内からの呼び出しでない場合、先にプレイヤーへ確認します。 |
| `sdk.message.edit(id, text)` | 指定したメッセージを書き換えて再送します。同様に確認が必要です。 |
| `sdk.save.get(key)` / `set(key, value)` / `remove(key)` / `keys()` | セーブ。カードごと・プレイヤーごとに最大 10 キー。キーは英数字、`_`、`-` のみ。1 値あたり最大 64 KB。デバイスをまたいで保持されます。 |
| `sdk.cache.get(key)` / `set(key, value)` / `remove(key)` | 一時保存。現在のページ読み込み中のみ有効です。 |
| `sdk.stage.open(mode)` / `close()` / `el()` / `visible()` | 作者ステージ。 |
| `sdk.role.get()` | キャラクター名とアバター。 |
| `sdk.user.get()` | プレイヤーの呼び名、アバター、表示言語（`locale`、例：`zh-Hans`）。 |
| `sdk.text.convert(text)` / `sdk.text.ready()` | スクリプトが描く文字を、返信と同じ方法でプレイヤーの中国語字形（簡体・繁体）に変換します。カードの言語がプレイヤーと同じ字形なら、そのまま返します。辞書の読み込み前は `convert` がそのまま返し、`ready()` は読み込み完了時（変換不要なら即時）に完了します。 |
| `sdk.model.get()` | プレイヤーが選んでいるモデル：`{name, cost}`。`name` はモデル名（ヘッダーの「モデル名 · ルート名」）、`cost` は次のターンの推定ポイント（動的料金では範囲、例：`127–251`）。ページから届くまではどちらも空文字列です。モデル一覧を開くには入力欄のモデルボタンを押します。 |
| `sdk.generation.get()` | このターンが何を待っているか：`{phase, since}`。`phase` は `idle`、`preparing`（送信直後でまだ何も返っていない）、`summarizing`（プラットフォームがここまでの物語を整理中。最初の一文字より前で、数十秒かかることも）、`thinking`（モデルが思考中で本文はまだ。思考しないモデルにはない）、`writing`（本文をストリーミング中）のいずれか。`since` はその段階に入った時刻（ミリ秒）。段階だけで、思考の内容は含みません。ほかに `outcome`：前のターンが正常に終わらなかったとき、チャット画面がその下に出すカードを `{kind, label, sub, actions}` で返します。正常に終わったときや生成中は `null`。`kind` は `model-error`、`network-error`、`server-error`、`rate-limit`、`quota`（ポイント不足）、`filtered`、`length-cap`、`stopped`、`compact-retryable`、`outcome-unconfirmed`（結果が届くのを待っている。ボタンはなく、届けば自動で表示）、`interrupted`（Agent のターンが終わっていない）のいずれか。`label`・`sub` はそのカードに出るプレイヤーの言語の文。`actions` は `[{action, label}]` で、`action` は `retry`、`continue`、`switch-model`、`model-settings`、`capacity`、`refresh`、`retry-stream-off`、`edit-message`、`switch-lane`、`resend-traditional` のどれかです。最後の 4 つは `filtered` のカードにだけ出ます。`retry-stream-off` はこの会話のストリーミング出力をオフにしてから再試行し、`edit-message` は止められたメッセージを編集状態で開き（送信するとそのメッセージを置き換えます）、`switch-lane` はモデルメニューを開いて今のモデルの別の回線を表示し、`resend-traditional` は止められたメッセージに簡体字が含まれるとき、全体を繁体字に変換してそのメッセージの代わりに送信します（同じメッセージには 1 回だけ）。 |
| `sdk.generation.act(action)` | そのカードのボタン（`outcome.actions` の `action`）を押します。プレイヤーがプラットフォームのカードを押したのと同じ動きで、再試行は同じメッセージを使い、二重に送りません。プレイヤーがクリックしている最中にだけ呼べます（それ以外は `UNAUTHORIZED`、確認は出ません）。カードにないボタンは `INVALID_ARGS`、生成中は `BUSY`、1 分に 3 回まで。Promise を返します。 |
| `sdk.archive.list()` / `save(title?)` / `fork(messageId)` / `open(id)` / `start(opening?)` / `rename(id, title)` / `remove(id)` | プラットフォームの会話セーブ（カードごとに最大 20 件、現在の会話を含む、端末をまたいで共有）。`open` はロード（現在の進行はそのまま一覧に残ります）、`save` は現在の進行に名前を付けて残し `{id, current}` を返す、`fork` は特定のメッセージ（吹き出しの `serverId`）から分岐、`start` は新規開始（0＝メインの開幕、1..＝別の開幕）、`list` は `{items, count, limit}` を返し、各行に `id, title, isCurrent, messageCount, lastMessage, createTime, lastUpdateTime` があります。変更する操作はプレイヤーのクリック中に呼び、カード自身の確認画面を使ってください。クリック外ではページが先に確認します。 |
| `sdk.on(event, handler)` | イベントの購読。 |
| `sdk.debug.log(...args)` | デバッグパネルに出力します。URL に `?sdkDebug=1` を付けるとパネルが表示されます。 |

### イベント

| イベント | タイミング |
|---|---|
| `ready` | 既存メッセージがすべてマウントされた後に 1 回発火。 |
| `message:new` | メッセージが作成された。 |
| `message:mount` | メッセージノードが画面にマウントされた。 |
| `message:stream` | ストリーミング出力が更新された。 |
| `message:done` | メッセージが完了した。 |
| `message:unmount` | メッセージノードが削除された。 |
| `input:change` | 入力ボックスの内容が変わった。 |
| `conversation:switch` | 会話が切り替わった（ロード、セーブ、分岐、新規開始の後）。ペイロードは `{ conversationId }`。 |
| `theme:change` | ダーク／ライトが切り替わった。 |
| `back` | プレイヤーが戻るを押した。 |
| `stage:close` | 作者ステージが閉じた。 |
| `dispose` | ページがアンロードされる直前。 |
| `model:change` | プレイヤーがモデルを切り替えた、または次のターンのポイントが変わった（コンテキスト長・思考の深さ）。ペイロードは `sdk.model.get()` と同じ。 |
| `generation:phase` | 待ちの段階が変わった。ペイロードは `{phase, since}`。再送はないので、後から動くスクリプトは `get()` を呼んでください。 |
| `generation:outcome` | 前のターンの結果が変わった（失敗のカードが出た、再試行で消えた）。ペイロードは `sdk.generation.get().outcome` と同じで、`null` のこともあります。再送はありません。 |

### 実行モデル

- ページを開くと、既存の各メッセージについて `message:new`、`message:mount`、`message:done` が順に発火し、最後に `ready` が発火します。
- メッセージのマウント後に `message:mount` または `message:done` を購読したハンドラーには、マウント済みメッセージ分が再送されます。
- イベントハンドラー内の `document.querySelector` はそのメッセージ内のみを検索します。ハンドラー外では通常の `document` です。
- スクリプトから外部 URL へリクエストを送ることはできません。外部の `<script src="https://…">`、画像、フォントは通常どおり読み込めます。

### エラーコード

| コード | 説明 |
|---|---|
| `UNAUTHORIZED` | プレイヤーが確認を要する操作を拒否した。 |
| `RATE_LIMITED` | 呼び出しが多すぎる。 |
| `INVALID_ARGS` | 引数が不正。 |
| `HOST_DENIED` | ホストページが操作を拒否した。 |
| `BUSY` | 生成中。 |
| `LIMIT_REACHED` | 会話セーブが上限に達した。`err.data` は `{ count, limit }`。プレイヤーに一件削除してもらいます。 |
| `NOT_SUPPORTED` | 現在の環境では利用できない機能。 |

## 従来ページからの移行

従来ページではルールがサイトのチャットページに直接適用されます。作者がよく使うセレクターは `.mes`（メッセージ）、`.mes_text`（本文）、`.mes.Ai`／`.mes.User`（発言者）、`#msglistview`（一覧）、`.chat-scope-box`（チャット領域）です。これらはサンドボックスページにも存在します。

- スタイルとテキスト置換のみのカードは変更不要です。
- `<img onerror="…">` でスクリプトを起動する方法はサンドボックスでも使えます。機能バーや最初のメッセージに置いたエンジン断片は実行されます。
- サイトページの他の領域を直接読み書きするスクリプトは、代わりに `sdk` を使ってください。
- `localStorage` はサンドボックスでも使えますが、データはカード自身のオリジン下にのみ保存されます。デバイスをまたいで保持するには `sdk.save.*` を使ってください。

## インポート

| ソース | 方法 |
|---|---|
| SillyTavern | PNG または JSON のキャラクターカードを「基本」セクションにドロップします。人物像、最初のメッセージ、世界設定、正規表現スクリプトが自動入力され、PNG 内の立ち絵を縦長背景に使います。メイン背景が別にある場合はそちらを優先します。 |
| 魅魔島（MMD）3 点セット | ルールファイル（`chatVersion` を含む）、最初のメッセージ、人物像をそれぞれインポートします。新版サンドボックス向けと記されたルールファイルは、サンドボックスのチャットページを自動的に選択します。 |

インポート後は「会話テスト」で表示を確認してから保存・公開してください。

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| カードを開いてから十数秒間画面が空白 | 初回はサンドボックスページのリソース読み込みに時間がかかります。2 回目以降はキャッシュから読み込まれます。20 秒を超えても空白の場合は通知が表示されるので、ページを再読み込みしてください。 |
| カードのガイドやオーバーレイが画面を覆ってスクロールできない | カード自身のチュートリアル層です。そのスキップボタンを押してください。 |
| スクリプトが動かない | URL に `?sdkDebug=1` を付けてデバッグパネルを開くと、スクリプトのエラーと `sdk.debug.log` の出力を確認できます。 |
| セーブに失敗する | キーが英数字、`_`、`-` のみであること、値が 64 KB 未満であること、カードのキー数が 10 未満であることを確認してください。 |
| メッセージの両側が想定より狭い | 画面端に接した要素がサイドバーと判定されています。その要素に `--lt-dock: none` を追加してください。 |

## 画像とテキストの共有

カードのスクリプトは、プレイヤーがボタンを押したときに画像とテキストを共有できます。HTTPS のカードフレームにはホストが `web-share` と `clipboard-write` を委譲します。`navigator.share` には準備済みの画像 `File` とテキストを渡せます。`navigator.clipboard.write` と `ClipboardItem` で PNG を、`navigator.clipboard.writeText` で説明文を書き込めます。これはブラウザーの機能であり、新しい `sdk` メソッドや HTTP エンドポイントではありません。

ファイルはクリック前に準備し、クリックハンドラーから直接呼び出してユーザーアクティベーションを保ってください。操作を表示する前に `navigator.share`、`navigator.canShare({ files: [file] })`、`navigator.clipboard.write`、`ClipboardItem` を確認します。対応状況はブラウザー、OS、権限、受信アプリに依存し、画像とテキストの両方が共有先に残るとは限りません。拒否とキャンセルを処理し、利用できない場合は画像のダウンロードと選択できる説明文を用意します。キャンセル後に共有画面を自動で開き直さないでください。ホストは `clipboard-read` を委譲しません。ローカルの不透明オリジンのプレビューでは拒否される場合があるため、対象端末の実際のクロスオリジンカードで確認してください。

## コンテキスト付きの共有リンク

カードのスクリプトは、コンテキストコード付きの共有リンクを作れます。友だちがそのリンクからカードを開くと同じコードを受け取れるので、「友だちはこれを選んだ。次はあなた」といった演出ができます。`sdk.share.link(code)`（クラシックカードでは `window.stage.share.link`）は、このカードの共有リンクを同期的に返します。リンク先はカードページ `/cards/<number>` で、ログイン中のプレイヤーの紹介コードが付き、コードを渡すと `?share=<code>` が加わります。リンクはクリック前に作っておき、クリックハンドラーの中で `navigator.share` に渡してください。

友だち側では `sdk.share.context` でコードを読めます。コードがないとき、または過去の会話を見ているときは `null` です。コードは英数字と `.`、`_`、`-` からなる 1–64 文字の ASCII で、先頭は英数字です。規則に合わない場合、サンドボックスカードは `SHARE_CONTEXT_INVALID` を投げ、クラシックカードは `null` を受け取ります。プラットフォームはコードを届けるだけです。モデルには送られず、プレイヤーの情報も含みません。誰でも手入力できるので、カード自身が定義したコードだけを受け付けてください。友だちがすでにセーブを持っているかどうかはカードが判断します（例：`sdk.archive.list()`。ゲストにはセーブがありません）。

`sdk.share.audience` はリンクを開ける人を示します：`author`（非公開カード。新しい友だちは開けません）、`link`、`public`。プラットフォームのスイッチがオフのとき、`sdk.share.enabled` は false、`context` は `null` になり、`link()` はコンテキストなしの通常リンクを返します。`sdk.share.qr(text)` は共有画像用に `{ size, path }`（`size` × `size` マスの SVG path）を返します。紹介コードの取得が遅れた場合は `share:change` が発生します。作者は `?mode=source&share=<code>` で下書きを試せます。


## 確定したメッセージ履歴

ページの作者 API は sandbox の `sdk.history` と classic の `stage.history` です。まず `capabilities().available` を確認してください。旧ホストやプレビューでは利用できない場合があります。`list({cursor,revision,content:true})` が読むのは現在のプレイヤー、カード、会話だけです。続きのページも最初のページと同じ revision で取得してください。全ページを蓄積し、最後のページで `complete:true` を確認してから、履歴全体を使ってください。

`onChange(callback)` は購読解除関数を返し、未 mount・hollow 済みのメッセージの実際の削除も通知します。viewport unmount は削除ではありません。イベントの最初の部分を受け取った時点で派生状態を未確認にし、完全なリストを取得してから再計算してください。無効な cursor、reset、unavailable は不明状態であり、空の履歴ではありません。

任意の本文は終了したメッセージの表示可能な原文だけで、thinking、生成途中の本文、moderation で隠された本文は含みません。`item.complete` は部分的・失敗した返答を成功扱いにしません。revision と不透明 ID はプレイヤーの識別子ではありません。

別端末の変更は前面表示中に 15 秒ごと、および復帰時に確認します。カード終了時に購読を解除してください。

## 投票・協力カウンター・共有への回答

`rules.json` の `sharedState` で宣言した投票とカウンターは、このカードを遊ぶ全員で共有されます。読み書きには `sdk.shared`（クラシックカードでは `window.stage.shared`）を使います。

- `read(keys)` はキー 1 つ、または最大 16 個を受け取り、`{ [key]: { kind: 'poll', counts, total, mine? } | { kind: 'counter', total, mine?, goal?, reachedAt?, previous? } }` を返します。宣言されていないキーは結果に含まれません。`mine` はプレイヤー自身の選択や貢献で、ゲストにはありません。`previous` は前の期間の合計です。
- `vote(key, option)` は `{ mine }` を返します。1 つの投票につき、最初の投票を含めて 1 日 10 回まで投票・変更できます。同じ選択肢を選び直しても回数には数えません。
- `add(key, delta)` は 1 からそのカウンターの `maxStep` までの整数を加え、`{ total, mine, reachedAt }` を返します。
- `leaderboard(key, { limit })` は `{ items: [{ rank, name, value }], mine? }` を返します。今期もっとも貢献したプレイヤー（既定 10 人、最大 50 人）を公開ニックネームで示し、テストアカウントは載りません。カウンターの `total`、`mine`、ランキングは期間ごとにリセットされます。

読み取りは誰でもできます。書き込みには、ログインしていて、このカードを遊んだことのある（会話を 1 つ始めていれば十分です）プレイヤーが必要です。数値はカードに自動で届かないので、必要に応じて読み直してください。間隔は 10 秒以上空けてください。作者は、新しい非公開カードや CLI で作った試遊カードを含め、自分のどのカードでも試せます。作者の数値はプレイヤーの数値と分けて記録されます。

共有への回答は共有リンクの上に成り立っています。`sdk.share.tallyLink(code, pollKey)` は、`share: true` で宣言した投票に、プラットフォームの短縮コード（`?share=~XXXXXXXX`）付きリンクを作ります。非同期なので、クリック前に用意しておいてください。同じコードと投票の組み合わせなら同じリンクが返り、1 人 1 日 20 本まで、リンクは 90 日間有効です。友だちがリンクを開くと、`sdk.share.context` にコード、`sdk.share.poll` に答えられる質問 `{ key, options }`（ないときは `null`）が入り、`sdk.share.respond(option)` で答えます。この回答はリンクごとに記録され、投票そのものの票とは別に扱われます。共有した人は `sdk.share.results()` で自分のリンクを読みます。各項目は `{ context, pollKey, total, counts, updatedAt }` で、`total` はリアルタイム、`counts` は 3 人以上が答えると表示され、1 日 1 回更新されます。誰が共有し、誰が答えたかはカードにはわかりません。カードはこの数値でカード内のコンテンツを解放できますが、プラットフォームのポイントが付与されることはありません。

エラーコードは両方のページで共通です：`SHARED_DISABLED`（プラットフォームまたは作者が一時停止中）、`NOT_DECLARED`、`OPTION_INVALID`、`NOT_ELIGIBLE`（まだ遊んでいない、または自分のリンクに答えようとした）、`UNAUTHORIZED`（未ログイン）、`RATE_LIMITED`（少し待って再試行）、`LIMIT_REACHED`（`err.data.reason` は `goal` か `limit`）、`HOST_DENIED`（古いプレイページ。過去の会話や審査用の試遊では読み取りのみ。審査に出したことも公開範囲を設定したこともないカード、たとえば試遊カードでは、ほかの人が開けないため `tallyLink` で回答用リンクを作れません）。作者の試遊（`?mode=source`）とテストアカウントは、プレイヤーとは別の数値を持ちます。編集画面の「プレイヤーの投票とカウント」または `hearthroom card state` で確認、一時停止、リセットできます。
