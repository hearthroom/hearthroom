# カード作成ガイド

このガイドでは、Web エディタの各セクションの書き方、世界設定とカード変数の使い方、公開審査の条件、そしてサンドボックス画面の表示ルールとスクリプト仕様をまとめています（`/ja/guide.md`）。

## 最短で最初の1枚を作って話してみる

左のサイドバーには8つのセクションが並んでいますが、会話を始めるために必須なのは4項目だけです。別サイトから書き出した既存のカードが手元にあれば、ファイルをドロップするだけで一括入力もできます。

### 新規作成で必須になる4つの項目

まずはキャラクターと話せる状態にするため、次の4つだけを埋めます：

1. 「**基本情報**」**→「キャラクター名」**：キャラクターの名前です。
2. 「**基本情報**」**→「ビジュアル」の「背景（縦）」**：9:16 の縦長イラストを推奨します。カード一覧の表紙、チャットのアイコン、PNG 書き出しの画像として兼用されます。アップロード枠にある点線の安全領域に顔や主要なモチーフを収めておくと、どの画面比率でも見切れません。手元に画像がなければ、その場でチャージしたポイントを使って AI 生成もできます。
3. 「**キャラ設定**」**→「キャラクター設定」**：何者で、どんな口調で話し、プレイヤーとどんな関係・状況にあるのかを書きます。
4. 「**始まり方**」**→「最初のメッセージ」**：会話が始まったときにキャラクターが最初に送るメッセージです。

この4つを入力して保存すると、画面右側の「**会話テスト**」パネルが使えるようになり、編集画面を開いたまま会話できます。横幅の広い画面では「会話テスト」の左端にあるハンドルをドラッグしてプレビュー幅を広げられます。左側の項目を書き換えたあとは、テストパネル上の「保存して読み込み直す」を押すと最新の変更が反映されます。

### 他のサイトで作ったカードを読み込む

新規作成時、「基本情報」の一番上にあるインポート欄に他ツールのカードファイルをそのままドロップできます：

| 読み込み元 | 手順と反映される内容 |
|---|---|
| SillyTavern | PNG・JSON・CHARX カードをドロップすると、キャラクター設定、最初のメッセージ、世界設定、正規表現スクリプトが対応する欄へ自動で入ります。PNG 内の立ち絵は「背景（縦）」に設定され、メイン背景が別途含まれている場合はそちらが優先されます。 |
| MMD 3ファイルセット | ルールファイル（`chatVersion` 入り）、導入ファイル、設定ファイルをそれぞれ読み込みます。新サンドボックス指定のルールファイルは自動で「サンドボックス」チャットページを選びます。 |
| AI 風月 / RiliAI | カードや設定の JSON を読み込むと、設定本文、最初のページ、世界設定、組み込みスタイル、カード変数が反映されます。 |

読み込み後は一度保存し、右側の「会話テスト」で冒頭の表示やステータスパネル、文字の装飾が崩れていないか確かめてから公開範囲を選びます。

## エディタの各セクションの役割

左側の8セクションは、作成から公開までの流れに沿って並んでいます。カードページを訪れた人だけが見る紹介用の欄と、毎ターンの会話で AI に送られる欄が分かれているため、役割を押さえておくと会話コンテキストを無駄に消費せずに済みます。

| セクション | 含まれる項目 | 誰が見るか・いつ使うか |
|---|---|---|
| **基本情報** | **キャラクター名**、**キャラクターの自称**（設定内の `{{char}}` がこの名前に置き換わります。空欄ならキャラクター名）、**主な言語**。 **ビジュアル**：**背景**（縦）のほか、「横長の背景と共有画像」を開くとワイド画面用の 16:9 **横向き背景**（任意）と Discord・LINE・X 用の 1200×630 **シェア画像**（任意）を追加できます。 **カードの見せ方**：**ひとこと紹介**（一覧カードで2行、カードページのタイトル下で3行まで表示）、**紹介**（カードページ専用の Markdown 欄。「書く / プレビュー」を切り替えられ、遊び方や登場人物紹介、画像、更新履歴を載せられます。**閲覧者にだけ表示され、AI との会話には一切送られません**）、**タグ**。 | 最初は名前・言語・縦背景だけで十分です。共有や公開の前に、ひとこと紹介・紹介・タグを整えます。 |
| **キャラ設定** | **キャラクター設定**（AI にだけ送られる非公開のコア設定・関係性・世界のルール）、**会話例**（ユーザーとキャラクターのやり取りを2〜3往復入れて口調や文の長さを固定します。入れすぎると展開が硬直します）。 「出力の形式と念押し」を開くと、**出力の形式**（段落構成や地の文・括弧の書き方）と**毎回の念押し**（毎ターンの末尾に添える短いリマインダー。AI が特に忘れやすい1〜2個のルール向き）を設定できます。 | カードの心臓部です。細かい詳細項目を埋めるより、まずはキャラクター設定と2〜3組の会話例を練るのが効果的です。 |
| **世界**（実験的） | **ワールドモードを有効にする**：1枚のカードに複数の独立したキャラクターを登場させます。共通の世界観は「キャラクター設定」に書き、ここでは各キャラクターの公開プロフィール、本人しか知らない詳細設定、個別の世界設定を登録します。毎ターンまず世界側が誰がその場にいるかを判定してから各キャラが発言します。 | 現在は実験段階の機能です。手元での試遊向きであり、一般公開するカードでの利用はまだ推奨していません。 |
| **始まり方** | 次の2つから選びます： 1. **最初のメッセージ**：キャラクター側から最初に話しかける形式です。複数の別パターン導入を追加したり、下に**おすすめの一言**（タップすると入力欄に入る候補）を置いたりできます。 2. **最初のページ**：新しい会話の最上部に独自の HTML 画面と**最初の選択肢**を表示し、プレイヤーが選択肢を押して始める形式です（ページ内容はプレイヤーにだけ見え、AI には送られません）。 | どちらか一方が必須です。通常の会話・ストーリー系は「最初のメッセージ」、タイトル画面やルート選択から始めたいときは「最初のページ」（または導入への表示ルール適用）を選びます。 |
| **世界設定** | 「作る」または「世界設定ファイルを読み込む」から、項目ごとのキーワード・常時オン・意味ベースの呼び出しを管理します。 | 地名やサブキャラ、用語設定が数千文字を超え、毎ターン全部を送ると重くなるときに使います。 |
| **表示** | **チャットページ**（「サンドボックス（推奨）」または「従来」）と**表示ルール**（「正規表現を設定」から検索・置換ルールや上部の機能バーを編集）。 | テキストだけのカードなら触らなくて構いません。特定の記号をステータス欄やボタン、独自 UI に変えたいときに使います。 |
| **詳細設定** | **カードのスタイル**（吹き出し・入力欄・背景色・フォントの変更や、カード全体に効くカスタム CSS）と**カード変数**（好感度・所持金・持ち物・クエストなどの正確な数値管理とパネル表示）。 | チャット画面の配色を変えたいときや、育成・TRPG・経営など正確な数値計算が要るカードで開きます。 |
| **公開** | **公開範囲**（「自分のみ」「リンクを知っている人」「公開」）、プレイヤーの投票とカウント管理、**ワークショップをオンにする**（作者DLC とプレイヤー拡張）、**足りないもの**チェックリスト、**レーティングを設定**。 | 誰に遊ばせるかを決めるときや、一般公開の審査に出す前の最終確認で使います。 |

## 長い設定は「世界設定」に切り分ける

地名や登場人物、陣営の決まりごとが増えるにつれてすべてを「キャラクター設定」に書き足していくと、毎ターンの会話枠が設定だけで埋まってしまいます。「話題に出たときだけ思い出せばいい設定」を**世界設定**（Lorebook）へ逃がしておくと、長編になっても AI が直近のストーリー展開をしっかり覚えていられます。

「世界設定」セクションで「作る」（または SillyTavern や RiliAI の JSON を「世界設定ファイルを読み込む」）を選ぶと、項目を1件ずつ追加できます。会話への読み込み方には2通りあります：

- **常時オン（毎ターン）**：オンにすると、会話の内容に関わらず毎ターン先頭のキャッシュ領域へ入ります（公開審査の 3,000 文字要件にもカウントされます）。絶対に忘れてはいけない根本ルールだけに絞り、短く保つのがコツです。枠を超えた場合はリストの上にある項目が優先されます。
- **キーワードと意味ベースの呼び出し（既定）**：「常時オン」をオフにして**キーワード**（複数指定や `/pattern/flags` の正規表現に対応。**副キーワード**も入れた場合は両方が揃ったときのみ発火）を設定します。プレイヤーや返信にキーワードが出ると読み込まれるほか、既定でオンになっている「**意味ベースの呼び出し**」により、単語が完全一致しなくても文脈が近い項目を予算内で自動的に拾い上げます。

推理ものの犯人や終盤のどんでん返し、隠しルートなど、序盤で似た話題が出た拍子に先回りして読まれると困る項目は、その項目の「**意味ベースの呼び出し**」**をオフ**にしておけばキーワードが直接出たときだけ解禁されます。1項目あたりおよそ500文字前後・1テーマに絞り、項目名は中身がすぐ分かる名前（「闇医者の陳」など。「人物03」は不可）にしておくと、エージェント準備モードでキャラクター自身が項目名から検索するときも見つけやすくなります。

## ステータス欄・選択肢ボタン・カード変数を付ける

返信の下に現在地や好感度、次の行動ボタンを出したいだけなら、正規表現を書く必要すらありません。所持金やアイテム数などを1の位まで正確に計算させたいときは、「カード変数」をオンにしてシステム側に管理させます。

### 正規表現なしで使える標準の `[status]` と `[choices]`

「キャラクター設定」または「出力の形式」で、毎回の返信末尾に次の形式で出力するよう指示するだけで、チャットページ側で自動的にステータスパネルとタップ可能な選択肢ボタン（押すと入力欄に文字が入ります）として描画されます：

```text
[status]
現在地: 旧市街の時計塔
時刻: 23:40
警戒度: 35/100
[/status]

[choices]
隠し扉を押して階段を下りる
その場に留まって足音を聴く
[/choices]
```

`35/100` のような分数やパーセント表記は自動でプログレスバーになります。カード専用のデザインに作り替えたいときだけ、表示ルールを書いて上書きしてください。

### 「カード変数」で好感度・所持金・持ち物を正確に管理する

「所持金130枚、ポーション2本」といった数値を文章だけで AI に覚えさせていると、会話が長引いたときに計算がずれたり、再生成や巻き戻しで数字が食い違ったりします。「詳細設定」を開いて「**カード変数を追加**」を押すと、数値をシステム側で正確に保持できます：

1. **JSON で初期構造を決める**：最初に持つ項目名と初期値を JSON で定義します（迷ったら「例を挿入」から好感度・持ち物・クエストのひな形をそのまま入れられます）。現在値は毎ターン送られるため、項目を絞るほど軽くて速くなります。
2. 「**変数ルール**」**を書く**：どんな展開のときにどの値をいくつ増減させるかを普通の文章で書きます（例：「相手が本当に喜ぶ贈り物をしたときだけ好感度を増やし、1回あたり最大+5まで。買い物をしたら代金を引く」）。AI が返信末尾に見えない更新命令を添えるようになり、プレイヤーが返信を再生成したり前のメッセージへ戻したりした際も、その時点の数値へ自動で巻き戻ります。
3. 「**パネルのスキン**」**を作る（任意）**：Handlebars 記法（`{{affection}}` や `{{#each bag}}` など）を使って HTML と CSS を書くと、チャット画面から開閉できる専用ステータスパネルになります。下の「パネルのプレビュー」でその場で見た目を確認できます。

## チャット画面の配色・表示ルール・チャットページ

カード全体の吹き出し色やフォントを手軽に変えるなら「詳細設定」の「カードのスタイル」、AI が出力した記号を独自パネルやスクリプト付き画面に変換するなら「表示」セクションを使います。

### 「カードのスタイル」で配色とフォントを変える

「詳細設定 → カードのスタイル」を開くと、吹き出し・入力欄・送信ボタン・背景色・フォントを直接指定できるほか、下の「カスタム CSS」にカード全体へ効く CSS をそのまま貼り付けられます（`<style>` タグや検索パターンは不要で、チャットを開いたときに1回適用されます。上限 512 KB）。AI 風月向けに書かれた全体装飾 CSS も、ここに貼れば当サイトの吹き出しや入力欄へ自動でマッピングされます。

### よく使う外観変数

次の CSS 変数は「サンドボックス」「従来」どちらのチャットページでも共通して使え、「カードのスタイル」内で `.canvas-root` に指定するとカード全体の基本配色を揃えられます：

| 見た目 | 変数名 |
|---|---|
| AI 吹き出しの背景色 | `--lt-canvas-bubble-ai-bg` |
| 吹き出しの文字色（AI・プレイヤー共通） | `--lt-canvas-bubble-fg` |
| プレイヤー吹き出しの背景色 | `--lt-canvas-bubble-user-bg` |
| 入力欄の背景色 | `--lt-canvas-composer-field-bg` |
| 送信ボタンの背景色 | `--lt-canvas-send-bg` |
| アクセントカラー | `--lt-canvas-accent` |
| フォント（CSS の `font-family` リスト） | `--lt-canvas-font` |
| チャット背景色 | `--lt-canvas-bg` |

```css
.canvas-root {
  --lt-canvas-bubble-ai-bg: #243447;
  --lt-canvas-bubble-fg: #f2f2f5;
  --lt-canvas-bubble-user-bg: #37465b;
  --lt-canvas-composer-field-bg: #1e2938;
  --lt-canvas-send-bg: #355a7c;
  --lt-canvas-accent: #8fc9ff;
  --lt-canvas-font: system-ui, sans-serif;
  --lt-canvas-bg: #121b28;
}
```

MMD 従来の変数（`--background-color`、`--primary-font-color`、`--input-background-color`）も引き続き使えます。変数はそれを参照している要素に効くため、個別のセレクタで直接色を書いている箇所が優先され、また「表示ルール」内のスタイルは「カードのスタイル」より優先されます。

### 「表示ルール」でテキストの記号を独自 UI に変換する

「表示」セクションの「**正規表現を設定**」を開くと、複数の検索・置換ルールを順番に並べられます。メッセージが画面に出る直前に上から順に通され、変換後の HTML が AI に送られることはありません：

- **適用対象**：ルールごとに「AI の返信」「プレイヤーのメッセージ」「システムメッセージ」のどれに当てるかを選べます。新規作成時は「AI の返信」のみオンになっており、対象指定のない古いルールは3種類すべてに当たり、SillyTavern からのインポート時は元の設定に合わせて自動で振り分けられます。3つとも外したまま保存することもでき、その場合は本文には当たらず上部の「機能バー」の展開にだけ使われます。
- **検索**：固定文字列（例：`《ステータス》`）または `/pattern/flags` 形式の正規表現（例：`/<status>([\s\S]*?)<\/status>/g`）を指定します。正規表現のキャプチャグループは置換側で `$1`、`$2` として参照でき、パターン内の漢字は繁体字・簡体字の両方に自動マッチします。
- **置換内容**：任意の HTML に加え、`<style>` や `<script>` も書けます。有効なルール内の `<style>` はカード読み込み時に1枚のスタイルシートへ統合され、`<script>` はカードごとに1回実行されます。
- **機能バー**：メッセージ一覧の上部に固定表示される領域で、プレイヤーにだけ見え AI には送られません。ここに `【ステータス】【装飾】` のようなトリガー文字列を置いておき、下のルールでパネルやメニューへ展開するのが定番の使い方です。
- **マクロ**：置換内容では `{{user}}`（プレイヤーの呼び名）と `{{char}}`（キャラクター名、自称がある場合は自称）が使えます。
- **サイズ上限とテスト**：1ルールの置換内容は最大 512 KB（256 KB を超えると動作が重くなる旨の注意が出ますが保存は可能）、ルール全体で最大 32 MB です（超過時は超過量が表示されます）。ルール編集画面の右にある「**テスト**」欄にサンプルの返信文を貼り付ければ、全ルールまたは単一ルールの適用結果をその場で確認できます。

### サンドボックス画面と従来画面の違い

「表示 → チャットページ」では2つの動作モードを切り替えられます。どちらも基本の見た目（ヘッダー、メッセージ、入力欄、各種パネル）は同じで、カードのスタイルとスクリプトがどこで動くかが異なります：

- **サンドボックス（推奨・新規カードの既定）**：隔離された専用フレーム内でスタイルとスクリプトを実行します。画面全体のデザイン変更が可能（MMD の新サンドボックス API と互換）でありながら、プレイヤーのログイン状態には触れられず、送信や再生成などポイントを使う操作もプレイヤー自身のクリックにしか反応しないため安全です。
- **従来**：サイト本体のチャットページ上にそのままルールを当てます（サンドボックスの `sdk` は使えません）。読み込んだ古いカードがサンドボックスでうまく動かないときだけ切り替えます。

既存のカードを「サンドボックス」へ切り替えたら、右側の「会話テスト」を開いて機能バーや導入内のパネル、フローティングボタン、メニューの表示を確認してください（画面の左右端に寄せた細い固定ボタン列がある場合は、吹き出しと重ならないようメッセージ欄が自動で内側へよけます）。大半のカードはそのまま動きますが、手直しが必要な場合は末尾の[従来のページからの移行](#従来のページからの移行)を参照してください。

## 公開範囲・審査条件・ワークショップ拡張

作りかけのカードは自分専用やリンク限定のまま好きなだけ手元に置けます。トップページやランキングに載せて他プレイヤーの会話から還元ポイントを受け取りたいときに、「公開」セクションのチェック項目を揃えて審査へ出します。

### 3つの公開範囲

「公開」セクションの「**公開範囲**」からいつでも切り替えられます：

| 公開範囲 | 開ける人 | 向いている場面 |
|---|---|---|
| **自分のみ** | 作者本人と、すでにこのカードで会話を始めたことのある既存プレイヤーだけが続きを遊べます。新規の人は開けず、一覧や検索にも出ません。 | 自分だけで遊ぶときや、新規の流入をいったん止めたいとき。 |
| **リンクを知っている人** | トップページ・ランキング・検索には載らず、審査も不要です。URL を知っている人なら誰でも最新の保存内容で遊べてコメントも残せます。 | 一般公開の前に友だちへテストプレイを頼むときや、身内での共有。 |
| **公開** | 審査に通ると新着・カテゴリ・検索に並び、プレイヤーは承認済みの安定版を遊べます。他プレイヤーが遊ぶたびにポイント還元が入り、新規公開カードは日次・週次・月次ランキング賞金の対象にもなります。 | 完成した作品をコミュニティへ公開するとき。 |

### 公開審査に必要な3つの条件

「公開」セクションの「**足りないもの**」パネルで、提出前に必要な項目を自動で確認できます：

1. **公式のカテゴリ／プレイスタイルタグを1つ以上選ぶ**：「基本情報 → タグ」の下にある候補一覧から最低1つ選びます（自由入力のカスタムタグも併用できますが、必須条件のカウントには入りません）。
2. **有効文字数が 3,000 文字を超えていること**：「キャラクター設定」と有効な世界設定の「常時オン（毎ターン）」項目の合計で、**3,001 文字以上**の有効文字が必要です（文字と数字をカウントし、空白・句読点・記号・絵文字・HTML／スタイル／スクリプトタグ・テンプレート変数は除外。最初のメッセージ・会話例・毎回の念押し・「常時オン」以外の世界設定も対象外です）。
3. **レーティング質問票への回答**：「レーティングを設定」を押し、設定文・イラスト・想定される展開のうち最も強い表現に合わせて正直に回答します（台湾のゲームソフト審査基準に基づきカードページへ表示され、成人向けカードは成人向け表示をオンにした人にのみ表示されます。恋愛・交際・結婚を含むカードは 12+ 以上になります）。

公開後にエディタで内容を書き換えて保存しても、更新されるのはあなたの下書きだけで、公開中のバージョンには影響しません。再審査に出して承認された時点で新しい版に切り替わります。更新審査は既定では通知を送らず、通知にチェックを入れて更新内容を添えたときだけブックマーク登録者とフォロワーに通知されます（1枚のカードにつき3日に1回まで）。

### ワークショップをオンにする（作者DLC とプレイヤー拡張）

「公開」セクションで「**ワークショップをオンにする**」（既定はオフ）を切り替えると、カードページに「ワークショップ」タブが現れます。原作者自身は**作者DLC**（追加の導入メッセージ、表示ルール、世界設定）を公開でき、他のプレイヤーは**プレイヤー拡張**（世界設定の項目のみ追加可能。1つの拡張につき有効な常時オン項目は 1,500 文字までで、元カードの非公開設定・世界設定・正規表現ルールを読み取ることは一切できません）を作って共有できます。

### ノードセレクタとサンドボックス専用 CSS 変数

サンドボックス画面には MMD の新サンドボックスと同じ `data-chat`／`data-slot` 属性が用意されており、同じスクリプトが両方で動きます。内部の class 名ではなく、次の属性で要素を取得してください：

| セレクタ | 説明 |
|---|---|
| `[data-chat="root"]` | チャット画面のルート要素。`data-theme` は `dark`／`light`、`data-composer` は入力欄の表示状態を表します。 |
| `[data-chat="message"]` | 1件のメッセージ要素。`data-from` は `ai`／`user`、`data-state` は `pending`／`streaming`／`done`、`data-msg-id` はサーバー側のメッセージ ID です。 |
| `[data-chat="message-body"]` | メッセージ本文（表示ルール適用後の HTML）。 |
| `[data-slot="statusbar"]` | 上部の機能バー領域。 |
| `[data-slot="left"]`／`[data-slot="right"]` | 左右のサイドバー配置スロット。ここに入れた要素は固定サイドバーとして扱われ、メッセージ欄が自動で内側へ縮みます。 |
| `[data-chat="author-stage"]` | 作者ステージ領域。`sdk.stage.open('content')` でメッセージ領域、`open('full')` で画面全体を覆います。 |
| `[data-chat="input"]` | メッセージ入力欄。 |
| `[data-chat="composer"]` | 下部の入力エリア全体。 |

両ページ共通の[よく使う外観変数](#よく使う外観変数)とは別に、サンドボックスシェルの色とサイズは `--chat-*` 系の CSS 変数（`--chat-bg`、`--chat-text`、`--chat-accent`、`--chat-bubble-ai-bg` など）で定義されており、ルート要素で上書きすれば画面全体の配色をまとめて変更できます（サンドボックス専用）。

|---|---|

| `sdk.message.edit(id, text)` | 指定メッセージ（`data-msg-id`）を書き換えて再送信します。同様に確認ルールが適用されます。 |
| `sdk.save.get(key)` / `set(key, value)` / `remove(key)` / `keys()` | 端末間で引き継がれる永続セーブ。カード×プレイヤーごとに最大 10 キー、キー名は英数字・`_`・`-` のみ、1つの JSON 値につき最大 64 KB。 |
| `sdk.cache.get(key)` / `set(key, value)` / `remove(key)` | そのページを開いている間だけ有効な一時キャッシュ。 |
| `sdk.stage.open(mode)` / `close()` / `el()` / `visible()` | 作者ステージの開閉・要素取得（`mode` は `'content'` または `'full'`）。 |
| `sdk.role.get()` | キャラクターの名前とアイコン URL を取得します。 |
| `sdk.user.get()` | プレイヤーの呼び名・アイコン・表示言語（`locale`、例：`zh-Hans`）を取得します。 |
| `sdk.text.convert(text)` / `sdk.text.ready()` | スクリプト側で描画する中国語テキストをプレイヤーの繁体字／簡体字設定へ変換します（返信本文と同じ変換方式。書体が同じ場合や辞書読み込み前はそのまま返し、`ready()` は辞書準備完了時または変換不要時に完了します）。 |
| `sdk.model.get()` | プレイヤーが現在選んでいるモデル `{ name, cost }` を返します。`name` はヘッダー表示の「モデル名 · 回線名」、`cost` は次ターンの消費ポイント目安（動的価格では `127–251` のような範囲文字列。未到着時はどちらも空文字列）。モデル変更を促す際は入力エリアのモデルボタンを案内してください。 |
| `sdk.generation.get()` | 現在ターンの生成待ち状態 `{ phase, since, outcome }` を返します。 `phase` は `idle`、`preparing`（送信直後で応答待ち）、`summarizing`（最初の文字が出る前にプラットフォーム側で長編の要約圧縮中。数十秒かかる場合があります）、`thinking`（思考中・本文未出力。非思考モデルでは発生しません）、`writing`（本文ストリーミング中）のいずれかで、`since` はその段階に入ったミリ秒時刻です（思考テキスト自体は含みません）。 `outcome` は正常終了時や生成中は `null` で、直前のターンが途中で止まった場合はメッセージ下に表示されるステータスカード `{ kind, label, sub, actions }` が入ります。`kind` は `model-error`、`network-error`、`server-error`、`rate-limit`、`quota`（ポイント不足）、`filtered`、`length-cap`、`stopped`、`compact-retryable`、`outcome-unconfirmed`（結果確認中・ボタンなし・確定後に自動更新）、`interrupted`（エージェント準備が未完了）のいずれか。`label` と `sub` はプレイヤー言語の文言、`actions` は `[{ action, label }]` で、`action` は `retry`、`continue`、`switch-model`、`model-settings`、`capacity`、`refresh`、`retry-stream-off`、`edit-message`、`switch-lane`、`resend-traditional` のいずれかを取ります。後ろの4つは `filtered` カード専用で、`retry-stream-off` はこの会話のストリーミングを切って再試行、`edit-message` はブロックされた発言を編集して差し替え送信、`switch-lane` はモデルメニューを開いて現在モデルの別回線にフォーカス、`resend-traditional` は簡体字を含むブロック発言を繁体字へ変換して差し替え再送（1発言につき1回のみ）します。 |
| `sdk.generation.act(action)` | 上記ステータスカードのボタン（`outcome.actions` 内の `action`）を実行します。プラットフォームのカードを直接押したときと同じ挙動になり、再試行でも発言が二重送信されません。プレイヤーのクリックイベント内でのみ呼び出せ（それ以外は確認なしで `UNAUTHORIZED`）、提供されていない操作は `INVALID_ARGS`、生成中は `BUSY`、毎分3回まで。Promise を返します。 |
| `sdk.archive.list()` / `save(title?)` / `fork(messageId)` / `open(id)` / `start(opening?)` / `rename(id, title)` / `remove(id)` | プラットフォームの会話セーブ枠（進行中のものを含めカードごとに最大20枠、端末間同期）を操作します。`open` は元の進行状況を一覧に残したまま別セーブを開きます。`save` は現在の進行状況を名前付きで残して複製側で続行し、`{ id, current }` を返します（`id` が保存された旧会話）。`fork` は吹き出しの `serverId` から分岐を作成、`start` は新規開始（`0`＝メイン導入、`1`以上＝サブ導入）、`list` は `{ items, count, limit }`（各要素は `id, title, isCurrent, messageCount, lastMessage, createTime, lastUpdateTime`）を返します。セーブを変更する操作はプレイヤーのクリック内で呼び出し、カード側の確認画面を添えてください（クリック外ではシェル側が確認を出します）。 |
| `sdk.on(event, handler)` | イベントを購読します。 |
| `sdk.debug.log(...args)` | デバッグパネルへ出力します。URL に `?sdkDebug=1` を付けるとパネルを表示できます。 |

### イベント・実行ルール・エラーコード

| イベント | 発火タイミング |
|---|---|
| `ready` | ページ読み込み時、既存メッセージのマウントが一通り終わった直後に1回発火（再送なし）。 |
| `message:new` | 新しいメッセージが作られたとき。 |
| `message:mount` | メッセージ要素が画面にマウントされたとき（後から購読した場合もマウント済み分が再送されます）。 |
| `message:stream` | ストリーミング出力が更新されたとき。 |
| `message:done` | メッセージが完了したとき（後から購読した場合も完了済み分が再送されます）。 |
| `message:unmount` | メッセージ要素が画面から取り除かれたとき。 |
| `input:change` | 入力欄の内容が変わったとき。 |
| `conversation:switch` | ロード・セーブ・分岐・新規開始で会話が切り替わった後。ペイロードは `{ conversationId }`。 |
| `theme:change` | ダーク／ライトテーマが切り替わったとき。 |
| `back` | プレイヤーが戻るボタンを押したとき。 |
| `stage:close` | 作者ステージが閉じたとき。 |
| `dispose` | ページが破棄される直前。 |
| `model:change` | モデル変更、または次ターンの見積もりポイントが変わったとき（コンテキスト長や思考深度の変更を含む）。ペイロードは `sdk.model.get()` と同じ。 |
| `generation:phase` | 生成待ちの段階が変わったとき。ペイロードは `{ phase, since }`（再送されないため、遅れて初期化するスクリプトは `sdk.generation.get()` を呼んでください）。 |
| `generation:outcome` | 異常終了カードが出たとき、または再試行で消えたとき。ペイロードは `sdk.generation.get().outcome` と同じで `null` の場合もあります（再送なし）。 |
| `share:change` | 共有設定や紹介コードが遅れて取得できたとき（ペイロードなし。`sdk.share` を読み直してください）。 |

実行ルールと基本エラーコード：

- ページを開いた際、既存の各メッセージは `message:new` → `message:mount` → `message:done` の順に発火し、最後に `ready` が1回発火します。
- メッセージ系イベントのハンドラ内（およびメッセージ吹き出し内のクリック・入力ハンドラ内）では、`document.querySelector` などの検索対象は**そのメッセージ吹き出しの中だけ**に限定されます。ハンドラの外では通常の `document` 全体になります。
- スクリプトから外部 URL への通信（`fetch` など）はできませんが、外部の `<script src="https://…">`・画像・フォントは通常通り読み込めます。
- エラーコード：`UNAUTHORIZED`（確認が必要な操作をプレイヤーが拒否した、またはクリック外で呼んだ）、`RATE_LIMITED`（呼び出し頻度の上限超過）、`INVALID_ARGS`（引数不正またはサイズ上限超過）、`HOST_DENIED`（ホスト側が操作を拒否）、`BUSY`（返信を生成中）、`LIMIT_REACHED`（会話セーブ枠が上限に到達。`err.data` は `{ count, limit }` のため古いセーブの削除を促してください）、`NOT_SUPPORTED`（現在の環境では非対応）。

### 信頼できるメッセージ履歴（`sdk.history`）

スクロールで出し入れされる画面上の DOM ではなく、会話全体の正確な履歴からゲーム状態を組み立てるには、サンドボックスの `sdk.history`（従来ページでは `stage.history`）を使います：

- **対応確認とページ取得**：まず `history?.capabilities().available` を確認します（古いホストやオフラインプレビューでは非対応の場合があります）。`list({ cursor, revision, content: true })` は現在のプレイヤー・現在のカード・現在の会話だけを読み取ります。2ページ目以降は最初のページで得た `revision` をそのまま渡し、`complete: true` の最終ページを受け取るまで全ページを繋いでから採用してください（途中で `HISTORY_STALE` が返った場合は会話が変化しているため破棄して最初から読み直します）。
- **返信の紐付け（`replyTo`）と完了判定**：各項目は `replyTo: string | null` を持ちます。`role: 'ai'` の場合、その返信を引き起こしたプレイヤー発言の履歴 `id`（この会話内だけで照合に使う不透明な識別子で、別ページにある場合もあります）が入ります。プレイヤー発言・導入メッセージ・紐付けを検証できない古い履歴や分岐コピーでは `null` になります（古いホストではフィールド自体が省略されることもあるため、前後の並び順から推測せず不明として扱ってください）。再生成するとプレイヤーと AI 両方に新しい ID が振られ、新しい返信は新しいプレイヤー ID を指します。AI 返信の手動編集では ID と `replyTo` が維持され、巻き戻しでは破棄された発言が消え、プレイヤー発言だけ消えて AI 返信が残った場合はその `replyTo` が `null` になります。元の返信文へ追記するタイプの続き生成（`contine`／`continue_response`）は非対応ですが、保存されたエージェント準備の再開では元のプレイヤー発言 ID が引き継がれます。`content: true` で返る本文は確定済みの表示テキストのみ（思考過程・ストリーミング途中の文字・モデレーション非表示分は含みません）なので、必ず `item.complete` を確認し、途中停止や失敗した返信を完了状態のセーブポイントとして扱わないでください。
- **変更通知（`onChange`）**：`onChange(callback)` は購読解除関数を返します。各変更要素は `{ op, id, replyTo, replacementId? }` を持ちます（`add`／`update` の `replyTo` は読み取り時点で検証できた紐付け、`remove` は常に `null`。一度もマウントされていないメッセージの削除でも通知されますが、スクロールによる `message:unmount` は削除ではありません）。イベントの最初のチャンクを受け取ったら派生状態をいったん保留にし、完全な `list()` を読み直してから再計算してください（プレイヤー発言の削除だけでも AI 返信側の紐付けが不明に変わることがあるためです）。古いカーソルや `reset`、`unavailable` は状態不明を意味し、空の履歴ではありません。別端末での更新はフォアグラウンド時に15秒ごとおよび復帰時に確認されます。カード終了時は購読を解除してください。`revision` と履歴 ID はプレイヤーのアカウント識別子ではありません。

### 全体投票・共闘カウンター・シェア集計（`sdk.shared`）

`rules.json` の `sharedState` で宣言した投票とカウンターは、そのカードを遊ぶ全プレイヤーで数値が共有され、`sdk.shared`（従来ページは `window.stage.shared`）から読み書きできます：

- **`read(keys)`**：1つまたは最大16個のキーを受け取り、`{ [key]: { kind: 'poll', counts, total, mine? } | { kind: 'counter', total, mine?, goal?, reachedAt?, previous? } }` を返します。未宣言のキーは含まれず、`mine` はそのプレイヤー自身の投票先または貢献値（未ログインのゲストにはありません）、カウンターの `total`・`mine`・ランキングは期間ごとにリセットされ、`previous` に前期の合計が入ります。
- **`vote(key, option)`**：投票して `{ mine }` を返します。1つの設問につき1人1日最大10回まで投票・変更でき（初回も含む）、同じ選択肢への再投票は回数を消費しません。
- **`add(key, delta)`**：`1` からそのカウンターの `maxStep` までの整数を加算し、`{ total, mine, reachedAt }` を返します。
- **`leaderboard(key, { limit })`**：今期の貢献ランキング `{ items: [{ rank, name, value }], mine? }` を返します（既定10名・最大50名、公開ニックネーム表示、テストアカウントは除外）。

読み取りは誰でも可能で、書き込みにはログイン済みかつこのカードで一度でも会話を開いたプレイヤーであることが必要です。数値は自動プッシュされないため、10秒以上の間隔を空けて再取得してください。作者は自分のどのカード（新規の非公開カードや CLI の試用カードを含む）でも試すことができ、作者自身の数値は一般プレイヤーとは別枠になります。また下書き試遊（`?mode=source`）とテストアカウントもそれぞれ独立した数値を持つため本番集計に混ざりません。編集画面「公開」セクションの「プレイヤーの投票とカウント」または `hearthroom card state` から確認・一時停止・リセットが行えます。

「友だちにリンクを送って投票してもらい、集まった回答数でカード内要素を解放する」といった仕組みを作る場合は、`share: true` を付けた投票に対して非同期メソッド `sdk.share.tallyLink(code, pollKey)` を呼びます（クリック前に準備しておきます。同じ状況コードと投票の組み合わせには同じ `?share=~XXXXXXXX` 短縮リンクが返り、1人1日20本まで、90日間有効）。リンクを開いた友だちは `sdk.share.context` で状況コード、`sdk.share.poll` で設問 `{ key, options }`（なければ `null`）を読み取り、`sdk.share.respond(option)` で回答します（カード本体の投票とは別にリンク単位で集計されます）。共有した本人は `sdk.share.results()` で自分の発行リンク一覧 `[{ context, pollKey, total, counts, updatedAt }]` を取得でき、`total` は即時反映、選択肢別の `counts` は3人以上が回答すると表示され1日1回更新されます。誰が共有し誰が答えたかは双方に伝わりません。集計数に応じてカード内コンテンツを解放できますが、サイトのポイントが付与されることはありません。両ページ共通のエラーコードは `SHARED_DISABLED`（サイトまたは作者が一時停止中）、`NOT_DECLARED`、`OPTION_INVALID`、`NOT_ELIGIBLE`（このカード未プレイ、または自分のリンクに回答しようとした）、`UNAUTHORIZED`（未ログイン）、`RATE_LIMITED`（時間をおいて再試行）、`LIMIT_REACHED`（`err.data.reason` が `goal` または `limit`）、`HOST_DENIED`（古いプレイ画面、過去ログ閲覧や審査試遊での読み取り専用状態、または一度も審査提出も公開範囲設定もしていない試用カード等での `tallyLink` 呼び出し）です。

### 画像・テキストの共有と状況コード付きシェアリンク

- **画像とテキストの共有（ブラウザ標準 API）**：HTTPS のカードフレームにはホスト側から `web-share` と `clipboard-write` 権限が委譲されています（`clipboard-read` は委譲されません）。プレイヤーのクリックハンドラ内で `navigator.share`（事前生成した画像 `File` とテキスト）、`navigator.clipboard.write`＋`ClipboardItem`（PNG 書き込み）、`navigator.clipboard.writeText`（テキストコピー）を直接呼べます。これらはブラウザ機能であり、新しい `sdk` メソッドや HTTP エンドポイントではありません。操作ボタンを出す前に `navigator.share`・`navigator.canShare({ files: [file] })`・`navigator.clipboard.write`・`ClipboardItem` の対応状況を判定し、ユーザー操作の有効状態を保つためファイルはクリック前に用意しておいてください。OS・ブラウザ・権限・受け取り側アプリによって挙動が異なり、共有後に画像とテキストの両方が残るとは限りません。拒否やキャンセルを捕捉し、非対応時や拒否時は画像のダウンロードと選択可能なテキスト表示へフォールバックさせ、キャンセル後に共有シートを自動で開き直さないでください。ローカルの不透明オリジンでのプレビューでは拒否される場合があるため、対象端末の実際のクロスオリジン環境で確認してください。
- **状況コード付きシェアリンク（`sdk.share`）**：`sdk.share.link(code)`（従来ページは `window.stage.share.link`）は、ログイン中プレイヤーの紹介コード付きのカード URL `/cards/<番号>`（`code` を渡した場合はさらに `?share=<code>` 付き）を同期的に返します（クリック前に生成してクリックハンドラ内で `navigator.share` に渡してください。紹介コードが遅れて届いた場合は `share:change` が発火します）。友だちがそのリンクからカードを開くと、`sdk.share.context` で同じ状況コードを読み取れるため（コードなしや過去ログ閲覧中は `null`）、「友だちはこの選択をした、次はあなたの番」といった演出が作れます。状況コードは英数字で始まる 1〜64 文字の英数字および `.`・`_`・`-` のみ有効です（違反時はサンドボックスで `SHARE_CONTEXT_INVALID` 例外、従来ページで `null`）。プラットフォームは文字列を届けるだけで AI には送らずプレイヤー情報も含まないうえ、URL を手打ちすることもできるため、カード側で定義したコードだけを受け入れ、友だちに既存セーブがあるかどうかは `sdk.archive.list()` 等で判定してください（未ログインのゲストにセーブはありません）。`sdk.share.audience` はリンクを開ける対象（`author`＝自分のみのカードで新しい友だちは開けない、`link`、`public`）を表し、共有機能オフ時は `sdk.share.enabled` が `false`、`context` が `null`、`link()` は通常 URL を返します。`sdk.share.qr(text)` は `{ size, path }`（`size`×`size` グリッドの SVG パス）を返し、シェア画像内の QR コード描画に使えます。下書きでは `?mode=source&share=<code>` でテストできます。

### サイドバー自動回避（`--lt-dock`）とスタイル互換仕様

- **固定サイドバーの自動余白**：画面の左右端に接する幅 48px 程度までの固定ボタン列がある場合、サンドボックス・従来ページともにメッセージ欄が自動で内側へ縮みます（全画面モーダルや中央パネル、幅の広いバーは対象外）。判定を上書きしたいときは、サイドバー最外要素の `style` 属性に `--lt-dock` を直接指定します（インライン `style` ならどのカード形式でも効きます）：

| `--lt-dock` の値 | 効果 |
|---|---|
| `left`／`right` | 画面端に接していなくてもその側の固定サイドバーとして扱い、幅の上限をメッセージ欄の 30% まで広げます。 |
| `none` | この要素のために余白を空けません。`:root` に書いた場合はカード全体で自動調整を無効化します（SillyTavern 形式の表示ルール内スタイルはメッセージ内に限定されるため `:root` は効きません）。 |

```html
<div id="my-sidebar" style="position: fixed; left: 0; top: 30%; --lt-dock: left;">…</div>
```

余白を空けるとメッセージ欄の幅が元の 75% 未満になる場合は調整されません。実際に空けられた幅は `<html>` の `--lt-canvas-dock-left`・`--lt-canvas-dock-right` に書き出されるため（未調整時は存在しません）、カード側の要素の位置合わせに使えます。

- **カードのスタイルと表示ルールの優先順位・互換性**：AI 風月記法の CSS を「詳細設定 → カードのスタイル」（CLI では `card.css`、上限 512 KiB UTF-8）に置くと、`#customized-answer-content`・`#ai-chat-input`・`#ai-send-button` などの既知セレクタが自動で当サイトの吹き出し・入力欄・送信ボタンへ対応付けられ、風月用と当サイト用のセレクタを混在させられます（`.mes` が SillyTavern 判定に使われることもありません。古い風月カードで最新の互換処理を効かせたい場合は再インポートしてください）。一方、「表示ルール」内の `<style>` は保存済みの `cssDialect` やコンパイル済みマーカーを維持し、指定がなければ元のカード形式（SillyTavern 形式はメッセージ内のみ、その他は記述通り）に従って適用され、風月セレクタの自動変換は行いません。優先順位は低い方から「サイト既定とテーマ ＜ カードのスタイル ＜ 表示ルール内のスタイル」となり、インポート済みの既存カードを開いて保存し直しても元の設定と優先順位はそのまま保たれます。

### 従来のページからの移行

従来のページでよく使われていたセレクタ（`.mes` メッセージ枠、`.mes_text` 本文、`.mes.Ai`／`.mes.User` 発言者、`#msglistview` 一覧、`.chat-scope-box` 会話領域）はサンドボックス画面にもすべて用意されています：

- CSS 装飾とテキスト／HTML 置換だけを使っているカードは、そのまま変更なしで動きます。
- `<img onerror="…">` でスクリプトを起動する書き方もサンドボックスでそのまま動作し、「機能バー」や「最初のメッセージ」に置いた起動コードも実行されます。
- サイト本体のヘッダーや外部領域を直接書き換えていたスクリプトは、上の `sdk` メソッドへ置き換えてください。
- `localStorage` はサンドボックス内でも使えますが、カード固有の隔離オリジン内にだけ保存されます。スマホと PC をまたいでデータを残したい場合は `sdk.save.*` を使ってください。

### トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| 設定やルールを直したのに右の「会話テスト」が変わらない | テストパネルは最後に保存された版で動いています。パネル上部の「保存して読み込み直す」を押してください。 |
| カードを初めて開いたとき10秒以上真っ白になる | 初回はサンドボックス用リソースの読み込みに時間がかかり、2回目以降はキャッシュで速くなります。20秒を過ぎても真っ白な場合は案内が出るので再読み込みしてください。 |
| カード独自のガイドやオーバーレイで画面がスクロールできない | カード側のチュートリアル層が表示されています。画面内の「スキップ」や閉じるボタンを押してください。 |
| ルール内のスクリプトがまったく動かない | チャット URL に `?sdkDebug=1` を付けてデバッグパネルを開き、エラー表示と `sdk.debug.log` の出力を確認してください。 |
| `sdk.save` の保存に失敗する | キー名が英数字・`_`・`-` のみか、1つの値が 64 KB 以下か、そのカードのキー数が 10 個に達していないかを確認してください。 |
| メッセージの左右幅が思ったより狭くなる | 画面端に寄せて配置した装飾要素がサイドバーと判定されています。その要素の `style` に `--lt-dock: none` を付けてください。 |
