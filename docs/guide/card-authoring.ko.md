# 카드 작성 가이드

이 가이드는 캐릭터 카드의 구성, 두 가지 채팅 페이지의 차이, 규칙과 스크립트 작성법, 다른 플랫폼에서 가져올 때 확인할 사항을 설명합니다.

## 카드의 구성

| 항목 | 설명 |
|---|---|
| 이름, 세로 배경, 가로 배경(선택) | 세로 이미지는 PNG 내보내기와 채팅 프로필에도 사용됩니다. |
| 소개 | 랭킹 카드에 표시되는 요약입니다. |
| 인물 | 캐릭터의 신원, 말투, 세계관. |
| 첫 메시지 | 대화의 첫 메시지. 여러 후보를 설정할 수 있습니다. |
| 세계관 | 키워드로 호출되는 보조 설정. |
| 규칙 | 정규식 규칙. 답변의 특정 텍스트를 레이아웃, 상태 바, 버튼으로 변환합니다. |
| 채팅 페이지 | 카드가 사용하는 채팅 페이지: 샌드박스 또는 기존. 새 카드의 기본값은 샌드박스입니다. |

카드를 저장하면 편집 페이지 오른쪽의 "대화 테스트" 패널에서 바로 대화할 수 있습니다. 넓은 화면에서는 패널 왼쪽 가장자리의 손잡이를 드래그해 미리보기 너비를 조절할 수 있습니다.

## 채팅 페이지

두 채팅 페이지는 같은 화면(헤더, 메시지, 입력창, 패널)을 사용합니다. 차이는 카드의 규칙과 스크립트가 어디에서 실행되는지입니다.

### 샌드박스

카드의 화면과 스크립트는 사이트와 분리된 격리 페이지에서 실행됩니다.

- 스타일과 스크립트로 채팅 화면 전체를 수정할 수 있습니다.
- 스크립트는 플레이어의 로그인 상태에 접근할 수 없습니다.
- 전송, 재생성처럼 포인트를 소비하는 동작은 플레이어 본인의 클릭에만 반응합니다.

### 기존

규칙을 사이트의 채팅 페이지에 직접 적용합니다. 기존 카드가 샌드박스에서 제대로 동작하지 않을 때만 사용하세요.

### 전환

편집 페이지 "기본" 섹션의 "채팅 페이지" 옵션에서 전환합니다. 기존 카드를 샌드박스로 전환한 뒤 "대화 테스트"를 열어 기능 바, 첫 메시지 안의 패널, 플로팅 버튼, 메뉴, 각 패널이 이전과 같이 표시되는지 확인하세요. 대부분의 카드는 수정이 필요 없습니다. 빠진 효과가 있으면 "기존 페이지에서 이전"을 참고하세요.

### 사이드바

화면 좌우 끝에 고정된 버튼 막대가 메시지를 가리면, 채팅 페이지가 메시지 열을 안쪽으로 좁혀 메시지가 가려지지 않게 합니다. 샌드박스와 기존 채팅 페이지 모두에 적용됩니다.

자동 판단은 화면 끝에 붙어 있고 너비가 약 48px 이하인 막대만 처리합니다. 전체 화면 대화상자, 가운데에 떠 있는 패널, 더 넓은 막대는 처리하지 않습니다. 사이드바의 가장 바깥 요소에 CSS 변수 `--lt-dock`을 설정하면 판단을 덮어쓸 수 있습니다. 요소의 `style` 속성에 쓰면 모든 카드 형식에서 동작합니다.

| 값 | 효과 |
|---|---|
| `left`／`right` | 해당 쪽에 도킹된 사이드바로 취급합니다. 화면 끝에 붙어 있지 않아도 되며, 너비 상한이 메시지 열의 30%로 늘어납니다. |
| `none` | 이 요소를 위해 공간을 비우지 않습니다. `:root`에 설정하면 카드 전체에서 자동 조정을 하지 않습니다(SillyTavern 형식 카드의 스타일은 메시지 안에만 적용되므로 `:root`는 효과가 없습니다). |

```html
<div id="my-sidebar" style="position: fixed; left: 0; top: 30%; --lt-dock: left;">…</div>
```

공간을 비운 뒤 메시지 열 너비가 원래의 75% 미만이 되면 조정하지 않습니다. 실제로 비운 너비는 `<html>`의 `--lt-canvas-dock-left`, `--lt-canvas-dock-right`에 기록되며(조정하지 않을 때는 없음), 카드 자체 요소를 맞추는 데 쓸 수 있습니다.

## 규칙

규칙은 "찾기"와 "바꾸기"로 구성됩니다. 답변 텍스트는 표시되기 전에 모든 규칙을 순서대로 거칩니다.

### 찾기

고정 문자열(예: `《상태》`) 또는 정규식(예: `/<status>([\s\S]*?)<\/status>/g`). 정규식을 사용할 때 바꾸기 내용의 `$1`, `$2`는 캡처 그룹에 대응합니다.

### 바꾸기

임의의 HTML. `<style>`과 `<script>`를 포함할 수 있습니다. 모든 규칙의 `<style>`은 하나의 스타일시트로 합쳐져 적용되고, 각 `<script>`는 카드당 한 번 실행됩니다.

### 기능 바

규칙 편집기의 "기능 바"는 메시지 목록 위에 고정 표시되는 내용입니다. 플레이어에게만 표시되며 모델에는 전달되지 않습니다. 보통 여기에 트리거 단어(예: `【상태】【꾸미기】`)를 두고 규칙으로 실제 패널로 펼칩니다.

### 매크로

| 매크로 | 값 |
|---|---|
| `{{user}}` | 플레이어의 호칭 |
| `{{char}}` | 캐릭터 이름 |

### 제한

- 규칙 하나는 최대 128 KB입니다.
- 규칙 전체가 상한을 넘으면 편집기가 초과량을 표시합니다.

규칙 편집기의 "테스트" 칸에 샘플 답변을 붙여 넣으면 규칙 적용 결과를 바로 확인할 수 있습니다.

## 샌드박스 작성자 API

샌드박스 페이지는 고정된 노드 속성과 `sdk` 객체를 제공합니다. 魅魔島(MMD)의 새 샌드박스와 동일하며, 같은 스크립트가 두 플랫폼에서 모두 동작합니다.

### 노드

노드는 class 이름이 아니라 `data-chat` 속성으로 선택하세요.

| 선택자 | 설명 |
|---|---|
| `[data-chat="root"]` | 채팅 화면의 루트. `data-theme`은 `dark`/`light`, `data-composer`는 입력창 표시 여부. |
| `[data-chat="message"]` | 메시지 하나. `data-from`은 `ai`/`user`, `data-state`는 `pending`/`streaming`/`done`, `data-msg-id`는 서버 측 메시지 ID. |
| `[data-chat="message-body"]` | 메시지 본문(규칙 적용 후의 HTML). |
| `[data-slot="statusbar"]` | 기능 바. |
| `[data-chat="author-stage"]` | 작성자 스테이지. `sdk.stage.open('content')`는 메시지 영역을, `open('full')`은 페이지 전체를 덮습니다. |
| `[data-chat="input"]` | 입력 상자. |
| `[data-chat="composer"]` | 입력창. |

### CSS 변수

색상과 크기는 `--chat-*` 변수로 정의됩니다(예: `--chat-bg`, `--chat-text`, `--chat-accent`, `--chat-bubble-ai-bg`). 루트 노드에서 덮어쓰면 전체 배색을 바꿀 수 있습니다.

### sdk

| 메서드 | 설명 |
|---|---|
| `sdk.input.get()` / `set(text)` / `add(text)` / `insert(text)` / `clear()` / `focus()` / `blur()` / `getCursor()` / `setCursor(pos)` | 입력 상자 읽기·쓰기. |
| `sdk.composer.show()` / `hide()` / `visible()` | 입력창 표시·숨김. |
| `sdk.message.send(text)` | 플레이어 자격으로 메시지를 보냅니다. 플레이어의 클릭 이벤트 안에서 호출된 것이 아니면 먼저 플레이어에게 확인합니다. |
| `sdk.message.edit(id, text)` | 지정한 메시지를 고쳐 쓰고 다시 보냅니다. 마찬가지로 확인이 필요합니다. |
| `sdk.save.get(key)` / `set(key, value)` / `remove(key)` / `keys()` | 저장. 카드당·플레이어당 최대 10개 키. 키는 영숫자, `_`, `-`만 허용. 값 하나는 최대 64 KB. 기기 간에 유지됩니다. |
| `sdk.cache.get(key)` / `set(key, value)` / `remove(key)` | 임시 저장. 현재 페이지 로드 동안만 유효합니다. |
| `sdk.stage.open(mode)` / `close()` / `el()` / `visible()` | 작성자 스테이지. |
| `sdk.role.get()` | 캐릭터 이름과 아바타. |
| `sdk.user.get()` | 플레이어 호칭과 아바타. |
| `sdk.on(event, handler)` | 이벤트 구독. |
| `sdk.debug.log(...args)` | 디버그 패널에 기록합니다. URL에 `?sdkDebug=1`을 붙이면 패널이 표시됩니다. |

### 이벤트

| 이벤트 | 시점 |
|---|---|
| `ready` | 기존 메시지가 모두 마운트된 뒤 한 번 발생. |
| `message:new` | 메시지가 생성됨. |
| `message:mount` | 메시지 노드가 화면에 마운트됨. |
| `message:stream` | 스트리밍 출력이 갱신됨. |
| `message:done` | 메시지가 완료됨. |
| `message:unmount` | 메시지 노드가 제거됨. |
| `input:change` | 입력 상자 내용이 바뀜. |
| `conversation:switch` | 대화가 전환됨. |
| `theme:change` | 다크/라이트가 전환됨. |
| `back` | 플레이어가 뒤로 가기를 누름. |
| `stage:close` | 작성자 스테이지가 닫힘. |
| `dispose` | 페이지가 언로드되기 직전. |

### 실행 모델

- 페이지를 열면 기존 각 메시지에 대해 `message:new`, `message:mount`, `message:done`이 순서대로 발생하고, 마지막에 `ready`가 발생합니다.
- 메시지가 마운트된 뒤에 `message:mount` 또는 `message:done`을 구독한 핸들러에는 이미 마운트된 메시지분이 다시 전달됩니다.
- 이벤트 핸들러 안의 `document.querySelector`는 해당 메시지 안만 검색합니다. 핸들러 밖에서는 일반 `document`입니다.
- 스크립트는 외부 URL로 요청을 보낼 수 없습니다. 외부 `<script src="https://…">`, 이미지, 글꼴은 정상적으로 로드됩니다.

### 오류 코드

| 코드 | 설명 |
|---|---|
| `UNAUTHORIZED` | 플레이어가 확인이 필요한 동작을 거부함. |
| `RATE_LIMITED` | 호출이 너무 잦음. |
| `INVALID_ARGS` | 인자가 잘못됨. |
| `HOST_DENIED` | 호스트 페이지가 동작을 거부함. |
| `BUSY` | 생성 중. |
| `NOT_SUPPORTED` | 현재 환경에서 지원하지 않는 기능. |

## 기존 페이지에서 이전

기존 페이지에서는 규칙이 사이트의 채팅 페이지에 직접 적용됩니다. 작성자가 흔히 쓰는 선택자는 `.mes`(메시지), `.mes_text`(본문), `.mes.Ai`/`.mes.User`(화자), `#msglistview`(목록), `.chat-scope-box`(채팅 영역)입니다. 이 선택자들은 샌드박스 페이지에도 존재합니다.

- 스타일과 텍스트 치환만 사용하는 카드는 수정이 필요 없습니다.
- `<img onerror="…">`로 스크립트를 시작하는 방식은 샌드박스에서도 동작합니다. 기능 바나 첫 메시지에 둔 엔진 조각은 실행됩니다.
- 사이트 페이지의 다른 영역을 직접 읽고 쓰는 스크립트는 대신 `sdk`를 사용하세요.
- `localStorage`는 샌드박스에서도 사용할 수 있지만, 데이터는 카드 자신의 출처(origin) 아래에만 저장됩니다. 기기 간에 유지하려면 `sdk.save.*`를 사용하세요.

## 가져오기

| 출처 | 방법 |
|---|---|
| SillyTavern | PNG 또는 JSON 캐릭터 카드를 "기본" 섹션에 끌어다 놓습니다. 인물, 첫 메시지, 세계관, 정규식 스크립트가 자동으로 채워지고, PNG 안의 일러스트를 세로 배경으로 사용합니다. 별도 메인 배경이 있으면 우선 사용합니다. |
| 魅魔島(MMD) 3종 세트 | 규칙 파일(`chatVersion` 포함), 첫 메시지, 인물을 각각 가져옵니다. 새 샌드박스용으로 표시된 규칙 파일은 샌드박스 채팅 페이지를 자동으로 선택합니다. |

가져온 뒤 "대화 테스트"에서 표시를 확인한 다음 저장하고 공개하세요.

## 문제 해결

| 증상 | 조치 |
|---|---|
| 카드를 연 뒤 십여 초 동안 화면이 비어 있음 | 처음에는 샌드박스 페이지의 리소스 로드가 느립니다. 이후에는 캐시에서 로드됩니다. 20초가 지나도 비어 있으면 안내가 표시되며, 페이지를 새로 고치세요. |
| 카드의 안내나 오버레이가 화면을 덮어 스크롤할 수 없음 | 카드 자체의 튜토리얼 층입니다. 그 건너뛰기 버튼을 누르세요. |
| 스크립트가 동작하지 않음 | URL에 `?sdkDebug=1`을 붙여 디버그 패널을 열면 스크립트 오류와 `sdk.debug.log` 출력을 확인할 수 있습니다. |
| 저장 실패 | 키가 영숫자, `_`, `-`만 포함하는지, 값이 64 KB 미만인지, 카드의 키 수가 10개 미만인지 확인하세요. |
| 메시지 양쪽이 예상보다 좁음 | 화면 끝에 붙은 요소가 사이드바로 판단되었습니다. 그 요소에 `--lt-dock: none`을 추가하세요. |
