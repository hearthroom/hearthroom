# 카드 작성 가이드

이 가이드는 웹 편집기의 각 섹션 작성법, 세계관과 카드 변수 설정법, 공개 심사 기준, 그리고 샌드박스 채팅 페이지의 표시 규칙과 스크립트 규격을 안내해요(`/ko/guide.md`).

## 가장 빠르게 첫 카드 만들어 대화해 보기

편집 화면 왼쪽에는 여덟 개의 섹션이 있지만, 일단 저장하고 대화를 시작하는 데 꼭 필요한 항목은 네 개뿐이에요. 다른 플랫폼에서 내보낸 카드 파일이 있다면 끌어다 놓기만 해도 각 칸이 자동으로 채워져요.

### 새 카드를 만들 때 꼭 채워야 하는 네 가지

캐릭터와 바로 말을 섞어 보려면 아래 네 항목만 순서대로 채우세요:

1. **‘기본 정보’ 섹션 → ‘캐릭터 이름’**: 캐릭터의 이름이에요.
2. **‘기본 정보’ 섹션 → ‘이미지’의 ‘배경 (세로)’**: 9:16 세로 이미지를 권장해요. 랭킹 카드 표지, 채팅 프로필 아이콘, PNG 내보내기 이미지로 함께 쓰여요. 업로드 칸의 점선 안전 영역 안에 얼굴과 핵심 피사체를 두면 화면 비율이 달라져도 잘리지 않아요. 마땅한 그림이 없다면 생성 버튼을 눌러 충전 포인트로 그 자리에서 AI 이미지를 뽑을 수도 있어요.
3. **‘캐릭터 설정’ 섹션 → ‘캐릭터 설정’**: 캐릭터가 누구인지, 플레이어와 어떤 관계이고 어떤 상황인지, 어떤 말투를 쓰는지를 적어요.
4. **‘시작’ 섹션 → ‘첫 메시지’**: 대화가 시작될 때 캐릭터가 플레이어에게 건네는 첫마디예요.

네 항목을 채우고 저장하면 편집 화면 오른쪽의 **‘대화 테스트’** 패널이 열려서 페이지를 벗어나지 않고 바로 대화해 볼 수 있어요. 넓은 모니터에서는 ‘대화 테스트’ 패널 왼쪽 가장자리의 손잡이를 끌어 미리보기 폭을 넓힐 수 있고, 왼쪽 입력칸을 고친 뒤에는 테스트 패널 상단의 **‘저장하고 새로 불러오기’**를 눌러야 최신 수정본이 반영돼요.

### 다른 플랫폼에서 쓰던 카드 가져오기

새 카드를 만들 때 ‘기본 정보’ 맨 위에 있는 가져오기 영역에 다른 도구의 카드 파일을 끌어다 놓을 수 있어요:

| 출처 | 가져오는 방법과 채워지는 내용 |
|---|---|
| SillyTavern | PNG, JSON, CHARX 카드를 끌어다 놓으면 캐릭터 설정, 첫 메시지, 세계관, 정규식 스크립트가 맞는 칸에 자동으로 들어가요. PNG에 담긴 일러스트는 세로 배경으로 지정되며, 카드 안에 별도 메인 배경이 들어 있으면 메인 배경을 우선 사용해요. |
| MMD 3종 세트 | 규칙 파일(`chatVersion` 포함), 도입부 파일, 캐릭터 설정 파일을 각각 불러와요. 새 샌드박스용으로 표시된 규칙 파일은 자동으로 ‘샌드박스’ 채팅 페이지를 선택해요. |
| AI 풍월 / RiliAI | 카드 또는 설정 JSON을 가져오면 캐릭터 설정, 첫 페이지, 세계관, 내장 스타일, 변수 설정까지 함께 들어와요. |

가져오기가 끝나면 한 번 저장한 뒤 오른쪽 ‘대화 테스트’에서 첫 화면과 상태 패널, 글자 서식이 제대로 나오는지 확인하고 공개 범위나 심사 제출을 정하세요.

## 편집기 여덟 개 섹션 둘러보기

왼쪽 섹션 여덟 개는 초안 작성부터 출시까지의 순서대로 놓여 있어요. 카드 소개 페이지를 구경하는 플레이어에게만 보이는 칸과 매 턴 AI에게 전송되는 칸이 나뉘어 있으니, 역할을 구분해 두면 대화 컨텍스트를 아낄 수 있어요.

| 왼쪽 섹션 | 안에 있는 항목 | 누가 보며 언제 쓰나요 |
|---|---|---|
| **기본 정보** | **캐릭터 이름**, **캐릭터의 자칭**(설정 안의 `{{char}}`가 이 이름으로 바뀌며 비워 두면 캐릭터 이름을 써요), **주 언어**. **이미지**: **배경 (세로)** 외에 ‘가로 배경과 공유 이미지’를 펼치면 와이드 화면용 16:9 가로 배경과 Discord·LINE·X 공유 미리보기용 1200×630 **공유 이미지 (선택)**를 넣을 수 있어요. **카드 소개 화면**: **한 줄 소개**(랭킹 타일에는 두 줄, 카드 페이지 제목 아래에는 세 줄까지 표시), **소개**(카드 페이지 전용 Markdown 영역으로 ‘작성 / 미리보기’를 전환해 플레이 방법, 등장인물 도감, 이미지, 업데이트 내역을 적어요. **방문자에게만 보이며 AI 대화에는 전송되지 않아요**), **태그**. | 처음 만들 때는 이름·언어·세로 배경만 채우고, 공유하거나 공개하기 전에 한 줄 소개·소개·태그를 마무리해요. |
| **캐릭터 설정** | **캐릭터 설정**(모델에게만 전달되는 비공개 핵심 설정, 관계, 세계 규칙), **대화 예시**(문답 예시 두세 세트로 말투와 문장 길이를 잡아 주며, 너무 길게 넣으면 답변이 굳어질 수 있어요). ‘출력 형식과 덧붙일 지시’를 펼치면 **출력 형식**(문단 구조나 지문 표기법)과 **매번 덧붙일 지시**(매 턴 끝에 덧붙는 짧은 당부로, 모델이 자주 깜빡하는 규칙 한두 줄에 알맞아요)를 적을 수 있어요. | 모든 카드의 중심이에요. 고급 칸을 다 채우기보다 캐릭터 설정과 대화 예시 두세 세트를 탄탄하게 쓰는 편이 훨씬 효과적이에요. |
| **월드** (실험 기능) | **월드 모드 켜기**: 카드 한 장에 여러 독립 캐릭터를 등장시켜요. 공통 세계관은 ‘캐릭터 설정’에 적고, 여기서는 캐릭터별 공개 프로필과 본인만 아는 상세 설정 및 전용 세계관을 등록해요. 매 턴 월드가 먼저 누가 자리에 있는지 판정한 뒤 각 캐릭터가 말해요. | 아직 실험 단계 기능이라 개인 테스트용으로만 권하며, 정식 공개할 카드에는 아직 권하지 않아요. |
| **시작** | 시작 방식을 둘 중 하나로 골라요: 1. **첫 메시지**: 캐릭터가 먼저 말을 거는 방식이에요. 여러 개의 대체 첫 메시지를 추가해 플레이어가 고르게 할 수 있고, 아래에 **추천 첫마디**(누르면 입력창에 들어가는 문구)를 달 수도 있어요. 2. **첫 페이지**: 새 대화 맨 위에 직접 짠 HTML 화면과 **첫마디 선택지**를 띄워 플레이어가 선택지를 눌러 시작하는 방식이에요(**페이지 내용**은 플레이어에게만 보이며 모델에는 전송되지 않아요). | 둘 중 하나는 필수예요. 일반 스토리·대화 카드는 ‘첫 메시지’를, 게임 타이틀 화면이나 출신·루트 선택 화면을 만들고 싶을 때는 ‘첫 페이지’(또는 첫 메시지에 표시 규칙 적용)를 써요. |
| **세계관** | ‘하나 만들기’ 또는 ‘세계관 파일 가져오기’로 항목별 키워드, 상시 포함 여부, 의미 기반 회상을 관리해요. | 배경 설정이나 지명, 조연 정보가 수천 자를 넘어 매 턴 전부 보내기 부담스러울 때 써요. |
| **표시** | **채팅 페이지**(‘샌드박스 (권장)’ 또는 ‘기존’)와 **표시 규칙**(‘정규식 설정’을 눌러 찾기·바꾸기 규칙과 상단 ‘기능 바’ 관리). | 순수 텍스트 대화 카드는 건드리지 않아도 돼요. 특정 표기를 상태창, 버튼, 전용 인터페이스로 바꾸고 싶을 때 열어요. |
| **고급** | **카드 스타일**(말풍선, 입력창, 배경 색상과 글꼴을 고르거나 카드 전체에 적용되는 ‘사용자 CSS’ 붙여 넣기)과 **카드 변수**(호감도, 소지금, 가방, 퀘스트 등 정확한 수치를 추적하고 패널로 표시). | 채팅방 색감을 바꾸거나 육성·TRPG·경영처럼 수치 계산이 틀리면 안 되는 카드를 만들 때 펼쳐요. |
| **공개** | **공개 범위**(‘나만 보기’, ‘링크가 있는 사용자’, ‘공개’), **플레이어 투표 및 집계** 관리, **창작마당 켜기**(작가 DLC 및 플레이어 세계관 확장팩), **아직 없는 것** 점검표, **등급 설정**. | 누가 이 카드를 열 수 있는지 정하고, 공개 심사 전에 글자 수 기준과 등급 설문을 확인할 때 써요. |

## 긴 설정은 ‘세계관’으로 나누어 관리하기

지명, 등장인물, 세력 규칙이 늘어날수록 모든 내용을 ‘캐릭터 설정’에 몰아넣으면 매 턴 대화 공간이 설정만으로 꽉 차 버려요. 대화가 그 주제로 흘러갔을 때만 떠올리면 되는 배경을 **세계관(Lorebook)**으로 빼 두면 대화가 길어져도 AI가 중요한 줄거리를 훨씬 오래 기억해요.

‘세계관’ 섹션에서 **‘하나 만들기’**(또는 SillyTavern·RiliAI JSON을 불러오는 **‘세계관 파일 가져오기’**)를 누르면 항목을 하나씩 추가할 수 있어요. 대화에 불러오는 방식은 두 가지예요:

- **상시(매 턴)**: 켜 두면 대화 내용과 상관없이 매 턴 맨 앞 캐시 영역에 고정으로 들어가요(공개 심사의 유효 글자 수 3,000자 기준에도 합산돼요). 절대 잊으면 안 되는 핵심 규칙만 짧게 넣는 것이 좋고, 한도를 넘기면 목록 위쪽에 있는 항목부터 우선 유지돼요.
- **키워드와 의미 기반 회상(기본값)**: ‘상시(매 턴)’를 끄고 **‘키워드’**(여러 개 입력하거나 `/pattern/flags` 정규식 사용 가능, **‘보조 키워드’**까지 채우면 양쪽 모두 일치할 때만 발동)를 적어요. 플레이어나 답변에 키워드가 나오면 대화에 포함되며, 기본으로 켜져 있는 **‘의미 기반 회상’** 덕분에 정확한 단어가 안 나와도 맥락이 가까우면 예산 안에서 자동으로 함께 불러와요.

추리물의 진범이나 후반부 반전, 숨겨진 루트처럼 초반에 비슷한 화제가 스쳤다고 미리 불려 나오면 곤란한 항목은 해당 항목의 **‘의미 기반 회상’을 꺼 두세요**. 그러면 키워드가 정확히 일치할 때만 열려요. 항목 하나당 500자 안팎으로 한 가지 주제만 담고, 제목은 내용만 봐도 알 수 있게 적어야(‘인물 03’ 대신 ‘암시장 약장수 진 씨’) 에이전트 준비 모드에서 캐릭터가 제목으로 항목을 찾아볼 때도 정확히 집어내요.

## 상태창, 선택지 버튼, 카드 변수 붙이기

답변 아래에 현재 위치나 호감도, 다음 행동 선택지를 띄우는 정도라면 정규식을 한 줄도 쓸 필요가 없어요. 육성·경영·TRPG 카드처럼 돈이나 아이템 개수를 정확히 계산해야 할 때는 ‘카드 변수’를 켜서 시스템이 계산을 맡게 하면 돼요.

### 정규식 없이 바로 쓰는 내장 `[status]`와 `[choices]`

‘캐릭터 설정’이나 ‘출력 형식’에 매 답변 끝을 아래 형식으로 마무리하라고 적어 두기만 하면, 채팅 페이지가 알아서 깔끔한 상태 패널과 누를 수 있는 선택지 버튼(누르면 입력창에 문구가 채워져요)으로 그려 줘요:

```text
[status]
위치: 구시가지 시계탑
시각: 23:40
경계도: 35/100
[/status]

[choices]
비밀문을 밀고 아래층으로 내려간다
자리에 멈춰 발소리에 귀를 기울인다
[/choices]
```

`35/100` 같은 분수나 퍼센트 표기는 자동으로 진행 바로 표시돼요. 카드 고유의 디자인으로 완전히 새로 꾸미고 싶을 때만 표시 규칙을 작성해 덮어쓰면 돼요.

### ‘카드 변수’로 호감도, 소지금, 인벤토리를 정확하게 기억하기

“현재 금화 130개, 물약 2병” 같은 숫자를 일반 문장으로만 기억하게 하면 대화가 길어질수록 AI가 계산을 틀리기 쉽고, 답변을 다시 생성하거나 이전 메시지로 되돌렸을 때도 숫자가 꼬여요. ‘고급’ 섹션을 펼쳐 **‘카드 변수 추가’**를 누르면 이런 수치를 시스템이 정확하게 관리해 줘요:

1. **초기 JSON 구조 잡기**: 처음 시작할 때 어떤 항목과 초기값이 있는지 JSON으로 적어요(막막하면 **‘예시 넣기’**를 눌러 호감도, 가방, 퀘스트 예시를 바로 불러올 수 있어요). 현재 값은 매 턴 모델에 함께 전달되므로 꼭 필요한 항목만 남길수록 빠르고 가벼워요.
2. **‘변수 규칙’ 적기**: 어떤 상황에서 어떤 값을 얼마나 더하고 뺄지 일상적인 문장으로 적어요(예: “상대가 진심으로 좋아하는 선물을 줬을 때만 호감도를 올리고 한 번에 최대 +5까지. 물건을 사면 가격만큼 금화를 차감”). AI가 매 답변 끝에 숨겨진 업데이트 명령을 덧붙이며, 플레이어가 답변을 다시 생성하거나 되돌리면 변수 값도 해당 턴 상태로 자동 복구돼요.
3. **‘패널 스킨’ 꾸미기(선택)**: Handlebars 문법(`{{affection}}`, `{{#each bag}}` 등)으로 HTML과 CSS를 작성하면 플레이어가 채팅 화면에서 상태 패널을 열어 현재 값과 이번 턴 변화량을 볼 수 있어요. 아래 **‘패널 미리보기’**에서 화면을 바로 확인할 수 있어요.

## 채팅 화면 꾸미기, 표시 규칙, 채팅 페이지

말풍선이나 배경 색감과 글꼴을 손쉽게 바꾸고 싶다면 ‘고급’ 섹션의 ‘카드 스타일’을, AI가 출력한 텍스트 마커를 전용 패널이나 인터랙티브 화면으로 바꾸고 싶다면 ‘표시’ 섹션의 채팅 페이지와 정규식 규칙을 설정해요.

### ‘카드 스타일’로 배색과 글꼴 바꾸기

‘고급 → 카드 스타일’을 펼치면 말풍선, 입력창, 보내기 버튼, 대화 배경색과 글꼴을 바로 고를 수 있고, 아래 **‘사용자 CSS’**에 카드 전체에 적용할 CSS를 붙여 넣을 수도 있어요(`<style>` 태그나 찾기 패턴 없이 채팅을 열 때 한 번 적용되며, 상한은 512 KB예요). AI 풍월용으로 작성된 전체 꾸미기 CSS도 여기에 붙여 넣으면 사이트의 말풍선과 입력창 선택자에 자동으로 연결돼요.

### 자주 쓰는 스타일 변수

아래 CSS 변수는 ‘샌드박스’와 ‘기존’ 두 채팅 페이지에서 모두 동작하며, ‘카드 스타일’의 `.canvas-root` 안에 적으면 카드 전체 배색을 한 번에 맞출 수 있어요:

| 꾸미는 위치 | 변수 이름 |
|---|---|
| AI 말풍선 배경색 | `--lt-canvas-bubble-ai-bg` |
| 말풍선 글자색(AI·플레이어 공통) | `--lt-canvas-bubble-fg` |
| 플레이어 말풍선 배경색 | `--lt-canvas-bubble-user-bg` |
| 입력창 배경색 | `--lt-canvas-composer-field-bg` |
| 보내기 버튼 배경색 | `--lt-canvas-send-bg` |
| 강조 색상 | `--lt-canvas-accent` |
| 글꼴(전체 CSS `font-family` 목록) | `--lt-canvas-font` |
| 대화 배경색 | `--lt-canvas-bg` |

```css
.canvas-root {
  --lt-canvas-bubble-ai-bg: #243447;
  --lt-canvas-bubble-fg: #f2f2f5;
  --lt-canvas-bubble-user-bg: #37465b;
  --lt-canvas-composer-field-bg: #1e2938;
  --lt-canvas-send-bg: #355a7c;
  --lt-canvas-accent: #8fc9ff;
  --lt-canvas-font: system-ui, sans-serif;
  --lt-canvas-bg: #121b28;
}
```

기존 MMD 변수(`--background-color`, `--primary-font-color`, `--input-background-color`)도 그대로 쓸 수 있어요. 변수는 해당 변수를 참조하는 요소에 적용되므로 개별 선택자에 색상을 직접 박아 둔 스타일이 있으면 직접 지정한 색상이 우선하며, ‘표시 규칙’ 안의 스타일은 ‘카드 스타일’보다 우선해요.

### ‘표시 규칙’으로 텍스트 표기를 커스텀 화면으로 바꾸기

‘표시’ 섹션에서 **‘정규식 설정’**을 누르면 여러 개의 찾기·바꾸기 규칙을 순서대로 만들 수 있어요. 메시지가 화면에 그려지기 직전에 활성화된 모든 규칙을 위에서 아래로 거치며, 변환된 HTML은 모델에게 전달되지 않아요:

- **적용 대상**: 규칙마다 ‘AI 답변’, ‘플레이어 메시지’, ‘시스템 메시지’ 중 어디에 적용할지 고를 수 있어요. 새 규칙은 기본으로 ‘AI 답변’만 켜져 있고, 대상 설정이 없는 예전 규칙은 세 가지 모두에 적용되며, SillyTavern에서 가져온 규칙은 원래 설정에 맞춰 자동으로 변환돼요. 세 가지를 모두 끄고 저장할 수도 있는데, 이 경우 대화 본문은 건드리지 않고 상단 ‘기능 바’를 펼치는 데만 쓰여요.
- **찾기**: 고정 문자열(예: `《상태창》`)이나 `/pattern/flags` 형식의 정규식(예: `/<status>([\s\S]*?)<\/status>/g`)을 적어요. 정규식의 괄호 캡처 그룹은 치환 내용에서 `$1`, `$2`로 꺼내 쓸 수 있고, 패턴 안의 한자는 번체자와 간체자를 자동으로 함께 매칭해요.
- **치환 내용**: 일반 HTML은 물론 `<style>`과 `<script>`도 넣을 수 있어요. 활성 규칙들의 `<style>`은 카드를 열 때 하나의 스타일시트로 합쳐지고, 각 `<script>`는 카드를 불러올 때 한 번씩 실행돼요.
- **기능 바**: 메시지 목록 맨 위에 고정되는 영역으로, 플레이어 화면에만 보이고 AI에게는 전송되지 않아요. 기능 바에 `【상태창】【테마】` 같은 짧은 트리거 문구를 넣어 두고 아래 규칙으로 상단 패널이나 사이드 메뉴로 펼치는 방식을 자주 써요.
- **사용 가능한 매크로**: 치환 내용 안에서 `{{user}}`(플레이어 호칭)와 `{{char}}`(캐릭터 이름, 캐릭터의 자칭이 있으면 자칭)를 쓸 수 있어요.
- **용량 한도와 실시간 테스트**: 규칙 한 개의 치환 내용은 최대 512 KB(256 KB를 넘으면 느려질 수 있다는 안내가 뜨지만 저장은 가능해요), 전체 규칙 합계는 최대 32 MB예요(초과 시 초과 용량이 표시돼요). 규칙 편집기 오른쪽 **‘테스트’** 칸에 AI 답변 샘플을 붙여 넣으면 전체 규칙이나 현재 규칙 하나만 적용한 결과를 그 자리에서 바로 볼 수 있어요.

### 샌드박스 채팅 페이지와 기존 채팅 페이지

‘표시 → 채팅 페이지’에서는 두 가지 실행 환경을 전환할 수 있어요. 기본 채팅 화면(상단 헤더, 메시지, 입력창, 패널)은 똑같고 카드의 스타일과 스크립트가 어디서 실행되는지만 달라요:

- **샌드박스 (권장, 새 카드 기본값)**: 카드의 스타일과 스크립트가 분리된 격리 프레임 안에서 실행돼요. 채팅 화면 전체를 자유롭게 꾸밀 수 있으면서도(MMD 새 샌드박스 규격과 호환) 스크립트가 플레이어의 로그인 상태에 접근할 수 없고, 메시지 전송이나 재생성처럼 포인트를 쓰는 동작도 플레이어가 직접 클릭했을 때만 반응해요.
- **기존**: 사이트 본래 채팅 페이지 위에 규칙을 직접 입혀요(샌드박스 `sdk`는 쓸 수 없어요). 가져온 예전 카드가 샌드박스에서 제대로 나오지 않을 때만 사용하세요.

기존 카드를 ‘샌드박스’로 바꾼 뒤에는 오른쪽 ‘대화 테스트’를 열어 상단 기능 바, 첫 메시지 안의 패널, 플로팅 버튼과 메뉴가 잘 뜨는지 확인해 보세요(화면 좌우 끝에 붙은 좁은 고정 버튼 막대가 있으면 말풍선이 가려지지 않도록 대화 열이 알아서 안쪽으로 좁혀져요). 대다수 카드는 손보지 않고 바로 돌아가며, 스크립트 수정이 필요하면 맨 아래 [기존 페이지에서 옮겨 오기](#기존-페이지에서-옮겨-오기)를 참고하세요.

## 공개 범위, 심사 기준, 창작마당 확장팩

다 만든 카드를 바로 전체 공개할 필요는 없어요. 혼자 플레이하거나 링크를 아는 친구끼리만 먼저 돌려 본 뒤, **랭킹**에 올려 포인트 리베이트와 상금을 받고 싶을 때 ‘공개’ 섹션에서 필수 항목을 채우면 돼요.

### 세 가지 공개 범위

‘공개’ 섹션의 **‘공개 범위’**에서 언제든 바꿀 수 있어요:

| 공개 범위 | 누가 열 수 있나요 | 어울리는 상황 |
|---|---|---|
| **나만 보기** | 작가 본인과 이미 이 카드에서 대화를 시작했던 기존 플레이어만 이어서 대화할 수 있어요. 새 방문자는 열 수 없고 어떤 공개 목록에도 나오지 않아요. | 혼자 비공개로 즐기거나 새 플레이어 유입을 잠시 닫아 둘 때. |
| **링크가 있는 사용자** | 첫 화면 **랭킹**이나 검색 결과에는 나오지 않고 사전 심사도 필요 없어요. 링크를 받은 사람은 누구나 최신 저장본을 바로 플레이하고 댓글을 남길 수 있어요. | 정식 공개 전에 친구에게 테스트 플레이를 부탁하거나 소규모로 공유할 때. |
| **공개** | 심사를 통과하면 **랭킹**, 카테고리, 검색 결과에 올라가고 플레이어는 승인된 안정 버전을 플레이해요. 다른 플레이어가 대화할 때마다 작가 리베이트 포인트가 쌓이고, 새로 공개된 카드는 일간·주간·월간 랭킹 상금 정산에도 자동으로 참여해요. | 완성한 작품을 커뮤니티에 정식으로 선보일 때. |

### 공개 심사에 필요한 세 가지 기준

‘공개’ 섹션의 **‘아직 없는 것’** 패널이 공개 전에 필요한 항목을 자동으로 점검해 줘요:

1. **공식 카테고리 또는 플레이 스타일 태그 1개 이상 선택**: ‘기본 정보 → 태그’ 아래의 공식 목록에서 최소 1개를 골라요(직접 입력한 자유 태그도 함께 둘 수 있지만 필수 개수에는 포함되지 않아요).
2. **유효 글자 수 3,000자 초과**: **‘캐릭터 설정’**과 활성화된 세계관 **‘상시(매 턴)’** 항목을 합쳐 **최소 3,001자** 이상의 유효 글자 수가 필요하며 어느 쪽을 보태도 합계에 반영돼요. 한글, 한자, 영문자, 숫자는 각각 한 글자로 세고 공백, 문장 부호, 기호, 이모지, HTML·스타일·스크립트 태그, 템플릿 변수는 세지 않아요. 첫 메시지, 대화 예시, 매번 덧붙일 지시, ‘상시(매 턴)’가 꺼진 세계관 항목도 기준 합계에서 제외돼요.
3. **등급 설문 작성**: **‘등급 설정’**을 눌러 카드 안의 설정 문구, 일러스트, 이야기가 도달할 수 있는 가장 높은 수위를 기준으로 솔직하게 체크해요(대만 게임 소프트웨어 등급 기준으로 카드 페이지에 표시되며, 성인 등급 카드는 성인 콘텐츠 표시를 켠 플레이어에게만 보여요. 연애·교제나 결혼 요소가 들어간 카드는 최소 12+로 분류돼요).

카드가 공개된 뒤에 편집기에서 내용을 고쳐 저장해도 내 초안만 업데이트될 뿐 플레이어가 이용 중인 온라인 버전은 바로 바뀌지 않아요. 다시 심사를 신청해 통과된 시점에 새 버전으로 교체돼요. 업데이트 심사는 기본적으로 조용히 반영되며, 알림 발송을 체크하고 업데이트 내용을 적었을 때만 북마크한 유저와 팔로워에게 알림이 가요(카드당 3일에 최대 1회).

### 창작마당 켜기(작가 DLC와 플레이어 확장팩)

‘공개’ 섹션에서 **‘창작마당 켜기’** 스위치(기본 꺼짐)를 켜면 카드 페이지에 ‘창작마당’ 탭이 생겨요. 원작자는 직접 **DLC**(추가 도입부, 표시 규칙, 세계관 항목)를 배포할 수 있고, 다른 플레이어도 이 카드에 얹어 쓰는 **플레이어 세계관 확장팩**(세계관 항목만 추가 가능, 확장팩당 활성 상시 항목 상한 1,500자, 원작 카드의 비공개 캐릭터 설정·세계관·정규식 규칙은 일절 읽을 수 없음)을 만들어 공유할 수 있어요.

## 샌드박스 인터랙티브 스크립트 및 호환성 레퍼런스

표시 규칙 안에서 JavaScript로 입력창을 제어하거나 기기 간 세이브를 연동하고, 전체 플레이어 투표를 붙이거나 기존 페이지용 카드를 샌드박스로 옮길 때는 아래 노드 선택자, `sdk` 메서드, 이벤트, 오류 코드를 참고하세요.

### 노드 선택자와 샌드박스 전용 CSS 변수

샌드박스 페이지는 MMD 새 샌드박스와 동일한 `data-chat` 및 `data-slot` 속성을 제공하므로 스크립트 하나로 양쪽에서 모두 동작해요. 사이트 내부 class 이름에 의존하지 말고 아래 속성을 사용하세요:

| 선택자 | 설명 |
|---|---|
| `[data-chat="root"]` | 채팅 화면의 루트 노드예요. `data-theme` 값은 `dark`／`light`, `data-composer` 속성은 입력 영역 표시 여부를 나타내요. |
| `[data-chat="message"]` | 개별 메시지 컨테이너예요. `data-from`은 `ai`／`user`, `data-state`는 `pending`／`streaming`／`done`, `data-msg-id`는 서버 메시지 ID예요. |
| `[data-chat="message-body"]` | 표시 규칙이 적용된 뒤의 메시지 본문 HTML이에요. |
| `[data-slot="statusbar"]` | 상단 기능 바 컨테이너예요. |
| `[data-slot="left"]`／`[data-slot="right"]` | 좌우 사이드바 도킹 슬롯이에요. 여기에 넣은 요소는 해당 방향 도킹 사이드바로 처리되어 대화 열 너비가 자동으로 줄어들어요. |
| `[data-chat="author-stage"]` | 작가 스테이지 레이어예요. `sdk.stage.open('content')`는 메시지 영역을, `open('full')`은 페이지 전체를 덮어요. |
| `[data-chat="input"]` | 메시지 텍스트 입력창이에요. |
| `[data-chat="composer"]` | 하단 입력 영역 전체 컨테이너예요. |

두 페이지 공통인 [자주 쓰는 스타일 변수](#자주-쓰는-스타일-변수) 외에, 샌드박스 셸의 색상과 크기는 `--chat-*` 계열 CSS 변수(`--chat-bg`, `--chat-text`, `--chat-accent`, `--chat-bubble-ai-bg` 등)로 정의되어 있어 루트 노드에서 덮어쓰면 샌드박스 화면 전체 테마를 바꿀 수 있어요(샌드박스 전용).

| `sdk.stage.open(mode)` / `close()` / `el()` / `visible()` | 작가 스테이지를 열거나 닫고 엘리먼트를 가져와요(`mode`는 `'content'` 또는 `'full'`). |
| `sdk.role.get()` | 캐릭터 이름과 프로필 이미지 URL을 가져와요. |
| `sdk.user.get()` | 플레이어 호칭, 프로필 이미지, 인터페이스 언어(`locale`, 예: `zh-Hans`)를 가져와요. |

| `sdk.model.get()` | 플레이어가 현재 선택한 모델 정보 `{ name, cost }`를 반환해요. `name`은 상단 바에 표시되는 ‘모델명 · 회선명’, `cost`는 다음 턴 예상 포인트(동적 과금 회선은 `127–251` 같은 구간 문자열, 초기화 전에는 둘 다 빈 문자열)예요. 모델 변경이 필요할 때는 입력 영역의 모델 버튼을 안내하세요. |
| `sdk.generation.get()` | 현재 턴의 생성 대기 상태 `{ phase, since, outcome }`를 반환해요. `phase`는 `idle`, `preparing`(방금 전송되어 아직 출력 전), `summarizing`(첫 글자가 나오기 전 플랫폼이 장편 줄거리를 요약 압축 중이며 수십 초 걸릴 수 있음), `thinking`(모델 추론 중·본문 출력 전, 비추론 모델에는 없음), `writing`(본문 스트리밍 출력 중) 중 하나이고 `since`는 해당 단계에 진입한 밀리초 타임스탬프예요(추론 원문은 포함하지 않아요). `outcome`은 정상 완료나 생성 중일 때는 `null`이며, 직전 턴이 정상적으로 끝나지 않았을 때는 메시지 아래에 뜨는 상태 카드 `{ kind, label, sub, actions }`를 그대로 담아요. `kind`는 `model-error`, `network-error`, `server-error`, `rate-limit`, `quota`(포인트 부족), `filtered`, `length-cap`, `stopped`, `compact-retryable`, `outcome-unconfirmed`(결과 확인 중, 버튼 없음, 확인 후 자동 갱신), `interrupted`(에이전트 준비 미완료) 중 하나예요. `label`과 `sub`는 플레이어 언어로 된 안내 문구이고, `actions`는 `[{ action, label }]` 배열로 `action` 값은 `retry`, `continue`, `switch-model`, `model-settings`, `capacity`, `refresh`, `retry-stream-off`, `edit-message`, `switch-lane`, `resend-traditional` 중 하나예요. 마지막 네 개는 `filtered` 상태 카드 전용으로, `retry-stream-off`는 이번 대화의 스트리밍을 끄고 재시도, `edit-message`는 차단된 플레이어 메시지를 열어 수정 후 교체 재전송, `switch-lane`은 모델 메뉴를 열어 현재 모델의 다른 회선에 포커스, `resend-traditional`은 간체자가 포함된 차단 메시지를 번체자로 변환해 교체 재전송(메시지당 1회만 제공)해요. |
| `sdk.generation.act(action)` | 위 상태 카드의 버튼(`outcome.actions` 안의 `action`)을 실행해요. 플랫폼 상태 카드를 직접 누른 것과 동일하게 동작하여 재시도 시에도 메시지가 중복 전송되지 않아요. 반드시 플레이어 클릭 이벤트 안에서 호출해야 하며(그 외에는 확인 창 없이 `UNAUTHORIZED` 거부), 현재 상태 카드에 없는 동작은 `INVALID_ARGS`, 생성 중에는 `BUSY`를 반환하고 분당 최대 3회로 제한돼요(Promise 반환). |
| `sdk.archive.list()` / `save(title?)` / `fork(messageId)` / `open(id)` / `start(opening?)` / `rename(id, title)` / `remove(id)` | 플랫폼의 대화 세이브 슬롯(진행 중인 대화를 포함해 카드당 최대 20개, 기기 간 동기화)을 다뤄요. `open`은 기존 진행도를 목록에 남긴 채 지정한 세이브를 열고, `save`는 현재 진행도를 이름 붙여 남겨 둔 뒤 복제본(`current`)에서 플레이를 이어 가며 `{ id, current }`를 반환해요(`id`가 보존된 스냅샷). `fork`는 말풍선의 `serverId`에서 분기를 새로 열고, `start`는 새 대화를 시작하며(`0`은 기본 첫 메시지, `1` 이상은 대체 첫 메시지), `list`는 `{ items, count, limit }`(각 항목은 `id, title, isCurrent, messageCount, lastMessage, createTime, lastUpdateTime`)를 반환해요. 세이브를 바꾸는 동작은 플레이어 클릭 안에서 카드 자체 확인 화면과 함께 호출하세요(클릭 밖에서 호출하면 시스템이 확인 창을 띄워요). |
| `sdk.on(event, handler)` | 채팅 페이지 이벤트를 구독해요. |
| `sdk.debug.log(...args)` | 디버그 로그를 출력해요. 채팅 URL 뒤에 `?sdkDebug=1`을 붙이면 디버그 패널을 열어 볼 수 있어요. |

### 이벤트, 실행 규칙 및 오류 코드

| 이벤트 이름 | 발생 시점 및 페이로드 |
|---|---|
| `ready` | 페이지를 열 때 기존 메시지 마운트가 모두 끝난 직후 한 번 발생해요(재전송 없음). |
| `message:new` | 새 메시지가 생성될 때 발생해요. |
| `message:mount` | 메시지 노드가 화면에 마운트될 때 발생해요(늦게 구독해도 이미 마운트된 메시지분은 다시 전달돼요). |
| `message:stream` | AI 스트리밍 출력 텍스트가 갱신될 때 발생해요. |
| `message:done` | 단일 메시지 출력이 완료될 때 발생해요(늦게 구독해도 완료된 메시지분은 다시 전달돼요). |
| `message:unmount` | 메시지 노드가 화면에서 제거될 때 발생해요. |
| `input:change` | 입력창 텍스트가 바뀔 때 발생해요. |
| `conversation:switch` | 불러오기, 저장, 분기, 새 대화 시작으로 세션이 바뀐 뒤 발생하며 페이로드는 `{ conversationId }`예요. |
| `theme:change` | 다크／라이트 테마가 바뀔 때 발생해요. |
| `back` | 플레이어가 상단 뒤로가기 버튼을 눌렀을 때 발생해요. |
| `stage:close` | 작가 스테이지가 닫혔을 때 발생해요. |
| `dispose` | 페이지가 언로드되기 직전에 발생해요. |
| `model:change` | 플레이어가 모델을 바꾸거나 다음 턴 예상 포인트가 바뀔 때(컨텍스트 길이, 사고 깊이 변경 포함) 발생하며 페이로드는 `sdk.model.get()`과 같아요. |
| `generation:phase` | 생성 대기 단계가 바뀔 때 발생하며 페이로드는 `{ phase, since }`예요(재전송되지 않으므로 늦게 초기화되는 스크립트는 `sdk.generation.get()`을 먼저 호출하세요). |
| `generation:outcome` | 직전 턴의 비정상 상태 카드가 나타나거나 재시도로 사라질 때 발생하며 페이로드는 `sdk.generation.get().outcome`과 같고 `null`일 수 있어요(재전송 없음). |
| `share:change` | 공유 설정이나 플레이어 추천 코드가 뒤늦게 로드됐을 때 발생해요(페이로드 없음, `sdk.share`를 다시 읽으세요). |

스크립트 실행 시 네 가지 규칙이 적용돼요:

- 페이지를 열어 기존 대화를 불러올 때 각 메시지는 순서대로 `message:new`, `message:mount`, `message:done`을 발생시키고, 모두 끝난 뒤 `ready`가 한 번 발생해요.
- 메시지 이벤트 핸들러 안(그리고 메시지 말풍선 내부의 클릭·입력 핸들러 안)에서 `document.querySelector` 등을 호출하면 **해당 메시지 말풍선 내부만** 탐색해요. 핸들러 밖에서 호출할 때만 전체 `document`를 탐색해요.
- 샌드박스 스크립트는 외부 주소로 네트워크 요청(`fetch` 등)을 보낼 수 없지만, 외부 `<script src="https://…">`, 이미지, 폰트 파일은 정상적으로 불러올 수 있어요.
- 기본 오류 코드: `UNAUTHORIZED`(플레이어가 확인을 거절했거나 클릭 밖에서 제한된 동작 호출), `RATE_LIMITED`(호출 빈도 초과), `INVALID_ARGS`(잘못된 인자 또는 용량·개수 한도 초과), `HOST_DENIED`(호스트 페이지가 작업 거부), `BUSY`(답변 생성 중), `LIMIT_REACHED`(대화 세이브 슬롯 가득 참, `err.data`는 `{ count, limit }`이므로 오래된 세이브 삭제를 안내하세요), `NOT_SUPPORTED`(현재 환경에서 미지원).

### 신뢰할 수 있는 메시지 히스토리 (`sdk.history`)

스크롤에 따라 붙었다 떨어지는 화면 DOM 말풍선에 의존하지 않고 전체 대화 기록으로부터 게임 상태를 복원하려면 샌드박스 카드의 `sdk.history`(기존 카드는 `stage.history`)를 쓰세요:

- **지원 확인 및 페이지네이션 읽기**: 먼저 `history?.capabilities().available`을 확인하세요(구버전 호스트나 오프라인 미리보기에서는 지원하지 않을 수 있어요). `list({ cursor, revision, content: true })`는 현재 플레이어가 이 카드에서 진행 중인 현재 대화만 읽어 와요. 다음 페이지를 이어 읽을 때는 첫 페이지에서 받은 `revision`을 그대로 넘기고, `complete: true`가 담긴 마지막 페이지까지 모두 모은 뒤에야 전체 목록을 채택하세요(중간에 `HISTORY_STALE`이 뜨면 대화가 바뀐 것이므로 읽던 목록을 버리고 처음부터 다시 읽어야 해요).
- **메시지 연결(`replyTo`) 및 완료 판정**: 모든 항목에는 `replyTo: string | null`이 들어 있어요. AI 답변의 `replyTo`는 그 답변을 유발한 플레이어 메시지의 `id`(해당 대화 안에서만 대조용으로 쓰이는 식별 문자열이며 이전 페이지에 있을 수도 있어요)를 가리키고, 플레이어 메시지·첫 메시지·연결을 검증할 수 없는 예전 기록이나 분기 복제 메시지는 `null`이에요(구버전 호스트에서는 필드 자체가 생략될 수 있으니 앞뒤 순서로 짐작하지 말고 알 수 없음으로 처리하세요). 답변을 재생성하면 플레이어와 AI 모두 새 ID가 부여되고 새 답변은 새 플레이어 ID를 가리켜요. AI 답변을 수동 수정하면 기존 ID와 `replyTo`가 유지되고, 되돌리기를 하면 버려진 메시지가 사라지며, 플레이어 메시지만 삭제되고 AI 답변이 남으면 해당 `replyTo`는 `null`이 돼요. 기존 답변 뒤에 글자를 이어 붙이는 이어쓰기(`contine`／`continue_response`)는 지원하지 않지만, 저장된 에이전트 준비 과정을 재개할 때는 원래 플레이어 메시지 ID를 그대로 써요. `content: true`로 받은 본문에는 출력이 완전히 끝난 화면 표시용 텍스트만 담기므로(추론 과정, 스트리밍 중인 글자, 심의로 가려진 텍스트 제외), 반드시 `item.complete`를 확인하고 중단되거나 실패한 답변을 정상 세이브 지점으로 삼지 마세요.
- **변경 구독(`onChange`)**: `onChange(callback)`은 구독 해제 함수를 반환해요. 각 변경 항목은 `{ op, id, replyTo, replacementId? }`를 담아요(`add`／`update`의 `replyTo`는 읽기 시점에 검증된 연결이고 `remove`는 항상 `null`이에요. 화면에 마운트된 적 없거나 언마운트된 메시지가 실제로 삭제될 때도 알림이 오지만, 스크롤로 화면 밖으로 나간 `message:unmount`는 삭제가 아니에요). 변경 배치의 첫 조각을 받으면 파생 상태를 먼저 보류로 표시하고 전체 `list()`를 새로 끝까지 읽은 뒤 다시 계산하세요(플레이어 메시지만 삭제돼도 연결된 AI 답변의 `replyTo`가 알 수 없음으로 바뀔 수 있기 때문이에요). 오래된 커서나 `reset`, `unavailable`은 빈 기록이 아니라 상태 미확인을 뜻해요. 다른 기기에서의 변경은 포그라운드일 때 15초마다, 그리고 탭으로 돌아올 때 확인해요. 카드를 떠날 때는 구독을 해제하세요. `revision`과 대화 내 ID는 플레이어 계정 식별자가 아니에요.

### 전체 투표, 협동 카운터 및 공유 집계 (`sdk.shared`)

규칙 파일 `rules.json`의 `sharedState`에 선언한 투표 항목과 카운터는 이 카드를 플레이하는 모든 유저가 통계를 공유하며, `sdk.shared`(기존 카드는 `window.stage.shared`)로 읽고 써요:

- **`read(keys)`**: 단일 key 또는 최대 16개 key를 받아 `{ [key]: { kind: 'poll', counts, total, mine? } | { kind: 'counter', total, mine?, goal?, reachedAt?, previous? } }`를 반환해요. 선언하지 않은 key는 결과에서 빠지고, `mine`은 로그인한 플레이어 본인의 선택 또는 기여치(비로그인 방문자는 없음)이며, 카운터의 `total`·`mine`·순위표는 매 기간 새로 시작하고 `previous`에 직전 기간 합계가 남아요.
- **`vote(key, option)`**: 투표 후 `{ mine }`을 반환해요. 질문 하나당 하루 최대 10번까지 투표하거나 바꿀 수 있고(첫 투표 포함), 같은 선택지를 다시 고르는 건 횟수를 차감하지 않아요.
- **`add(key, delta)`**: `1`부터 해당 카운터의 `maxStep` 사이 정수를 더하고 `{ total, mine, reachedAt }`을 반환해요.
- **`leaderboard(key, { limit })`**: 이번 기간 기여 상위 플레이어 `{ items: [{ rank, name, value }], mine? }`를 반환해요(기본 10명, 최대 50명, 공개 닉네임 표시, 테스트 계정 제외).

읽기는 누구나 할 수 있고, 쓰기는 로그인한 상태에서 이 카드의 대화를 한 번이라도 열어 본 플레이어만 가능해요. 수치는 자동 푸시되지 않으니 최소 10초 간격을 두고 다시 읽으세요. 작가는 본인 소유의 모든 카드(새 비공개 카드와 CLI 체험 카드 포함)에서 테스트할 수 있으며 작가 본인의 수치는 일반 플레이어 집계와 분리돼요. 초안 플레이(`?mode=source`)와 테스트 계정도 각각 별도 통계를 써서 실제 집계에 섞이지 않으며, 편집 화면 ‘공개’ 섹션의 **‘플레이어 투표 및 집계’** 또는 `hearthroom card state`로 조회·일시 중지·초기화를 할 수 있어요.

“친구에게 질문을 공유해 답을 모으고 결과에 따라 카드 속 요소를 해금하는” 구성을 만들고 싶다면 `share: true`를 선언한 투표에 비동기 메서드 `sdk.share.tallyLink(code, pollKey)`를 호출하세요(클릭 전에 미리 준비해 두세요. 같은 상황 코드와 투표 조합에는 동일한 `?share=~XXXXXXXX` 단축 링크가 반환되며 플레이어당 하루 최대 20개, 90일간 유효해요). 링크를 연 친구는 `sdk.share.context`로 상황 코드를, `sdk.share.poll`로 문항 정보(`{ key, options }`, 없으면 `null`)를 읽고 `sdk.share.respond(option)`을 호출해 응답해요(메인 투표와 별도로 링크마다 따로 집계돼요). 공유한 사람은 `sdk.share.results()`로 자신이 만든 링크 목록 `[{ context, pollKey, total, counts, updatedAt }]`를 읽을 수 있는데, `total`은 즉시 반영되고 선택지별 `counts`는 3명 이상 응답해야 나타나며 하루 한 번 갱신돼요. 누가 공유했고 누가 답했는지는 양쪽 모두 알 수 없으며, 집계 수치로 카드 안 콘텐츠를 해금할 수는 있지만 사이트 포인트는 지급되지 않아요. 두 채팅 페이지는 동일한 오류 코드를 써요: `SHARED_DISABLED`(플랫폼 또는 작가가 일시 중지함), `NOT_DECLARED`, `OPTION_INVALID`, `NOT_ELIGIBLE`(이 카드를 플레이한 적 없거나 본인 링크에 응답 시도), `UNAUTHORIZED`(비로그인), `RATE_LIMITED`(잠시 후 재시도), `LIMIT_REACHED`(`err.data.reason`이 `goal` 또는 `limit`), `HOST_DENIED`(구버전 플레이 화면, 지난 대화 열람 및 심사 테스트 중 읽기 전용 상태, 또는 한 번도 심사 제출이나 공개 범위 설정을 하지 않아 남이 열 수 없는 체험 카드에서 `tallyLink` 호출).

### 이미지 공유, 문구 복사 및 상황 코드 공유 링크

- **이미지 공유와 문구 복사(브라우저 기본 API)**: HTTPS 카드 프레임에는 호스트 페이지가 `web-share`와 `clipboard-write` 권한을 위임해요(`clipboard-read`는 위임하지 않아요). 스크립트는 플레이어 클릭 핸들러 안에서 `navigator.share`(미리 준비한 이미지 `File`과 텍스트 전달), `navigator.clipboard.write`와 `ClipboardItem`(PNG 쓰기), `navigator.clipboard.writeText`(문구 복사)를 호출할 수 있어요. 이는 별도 `sdk` 메서드나 HTTP 엔드포인트가 아닌 브라우저 표준 기능이에요. 버튼을 보여 주기 전에 `navigator.share`, `navigator.canShare({ files: [file] })`, `navigator.clipboard.write`, `ClipboardItem` 지원 여부를 먼저 확인하고, 사용자 클릭 활성화 상태를 유지하기 위해 파일은 클릭 전에 미리 만들어 두세요. 브라우저·OS·권한·받는 앱에 따라 동작이 다르며 공유 후 이미지와 글이 둘 다 남는다고 보장되지 않으니, 거절이나 취소를 잡아내 미지원·거절 시에는 이미지 다운로드와 선택 가능한 텍스트로 대체하고 플레이어가 닫은 공유 시트를 자동으로 다시 열지 마세요. 로컬 불투명 오리진 미리보기에서는 호출이 거부될 수 있으니 실제 기기의 교차 출처 카드 페이지에서 확인하세요.
- **상황 코드가 담긴 공유 링크(`sdk.share`)**: `sdk.share.link(code)`(기존 카드는 `window.stage.share.link`)를 호출하면 로그인한 플레이어의 추천 코드가 붙은 카드 공유 주소 `/cards/<카드번호>`(상황 코드를 넘기면 `?share=<code>` 추가)를 동기적으로 반환해요(클릭 전에 미리 생성해 두고 클릭 핸들러 안에서 `navigator.share`에 넘기세요. 추천 코드가 늦게 도착하면 `share:change` 이벤트가 발생하므로 그때 다시 읽어 갱신하면 돼요). 친구가 이 링크로 카드를 열면 `sdk.share.context`에서 같은 상황 코드를 읽을 수 있어(코드가 없거나 지난 대화를 보는 중이면 `null`) “친구가 이 선택지를 골랐으니 이제 네 차례야” 같은 연출을 만들 수 있어요. 상황 코드는 영문자나 숫자로 시작하는 1~64자의 영숫자 및 `.`, `_`, `-`만 허용돼요(규칙에 어긋나면 샌드박스는 `SHARE_CONTEXT_INVALID` 예외를 던지고 기존 페이지는 `null`을 반환해요). 플랫폼은 문자열만 전달할 뿐 모델에 보내지 않고 플레이어 정보도 담지 않으며 누구나 주소창에 직접 입력할 수 있으므로, 카드에서 직접 정의한 코드만 허용하고 친구에게 이미 세이브가 있는지는 `sdk.archive.list()` 등으로 카드에서 직접 판단하세요(비로그인 방문자는 세이브가 없어요). `sdk.share.audience`는 링크를 열 수 있는 대상(`author`: 나만 보기 카드라 새 친구는 열 수 없음, `link`, `public`)을 알려 주며, 플랫폼 공유 스위치가 꺼져 있으면 `sdk.share.enabled`는 `false`, `context`는 `null`, `link()`는 일반 카드 주소를 반환해요. `sdk.share.qr(text)`로 `{ size, path }`(`size`×`size` 격자 SVG path)를 받아 공유 이미지 안에 QR 코드를 그릴 수도 있어요. 초안에서는 `?mode=source&share=<code>`로 테스트할 수 있어요.

### 사이드바 자동 여백(`--lt-dock`) 및 스타일 호환 세부 규칙

- **고정 사이드바 여백 확보**: 화면 좌우 가장자리에 붙어 있고 너비가 약 48px 이하인 고정 버튼 막대가 있으면 샌드박스와 기존 페이지 모두 가운데 대화 열을 자동으로 안쪽으로 좁혀 줘요(전체 화면 모달, 가운데 뜬 패널, 더 넓은 막대는 자동 조정하지 않아요). 판정을 직접 지정하거나 끄고 싶다면 사이드바 가장 바깥 요소의 인라인 `style` 속성에 `--lt-dock`을 적어 주세요(인라인 `style`에 쓰면 모든 카드 형식에서 동작해요):

| `--lt-dock` 값 | 효과 |
|---|---|
| `left`／`right` | 화면 끝에 딱 붙어 있지 않아도 해당 방향 도킹 사이드바로 취급하며, 너비 상한을 대화 열의 30%까지 넓혀요. |
| `none` | 이 요소를 위해 공간을 비우지 않아요. `:root`에 적으면 카드 전체에서 자동 여백 조정을 끄지만, SillyTavern 형식 카드의 표시 규칙 스타일은 메시지 내부에만 적용되므로 `:root`가 동작하지 않아요. |

```html
<div id="my-sidebar" style="position: fixed; left: 0; top: 30%; --lt-dock: left;">…</div>
```

사이드바를 뺀 뒤 남는 대화 열 너비가 원래의 75% 미만이 되면 여백을 비우지 않아요. 실제로 비워 준 너비는 `<html>`의 `--lt-canvas-dock-left`와 `--lt-canvas-dock-right`에 기록되므로(조정되지 않았을 때는 없음) 카드 자체 UI 위치를 맞출 때 쓸 수 있어요.

- **카드 스타일과 표시 규칙의 호환 계층**: AI 풍월 방식으로 작성된 CSS를 ‘고급 → 카드 스타일’(CLI에서는 `card.css`, 상한 512 KiB UTF-8)에 넣으면 `#customized-answer-content`, `#ai-chat-input`, `#ai-send-button` 등 알려진 풍월 선택자를 사이트의 말풍선·입력창·보내기 버튼에 자동으로 연결해 주며, 풍월 선택자와 사이트 기본 선택자를 한 CSS 안에서 섞어 써도 돼요(`.mes`를 SillyTavern 출처 표기로 오인하지 않으며, 예전 풍월 카드에 최신 호환 매핑을 적용하려면 다시 가져오면 돼요). 반면 ‘표시 규칙’ 안의 `<style>`은 저장된 `cssDialect`와 컴파일 마커를 그대로 유지하고, 마커가 없으면 원래 카드 형식(`tavern`은 메시지 본문 내부로 범위 제한, 그 외 형식은 적은 그대로 적용)을 따르며 풍월 선택자 자동 변환을 하지 않아요. 스타일 우선순위는 낮은 쪽부터 ‘플랫폼 기본값 및 테마 ＜ 카드 스타일 ＜ 표시 규칙 안의 스타일’ 순이며, 이미 가져온 기존 카드를 열어 다시 저장해도 원래 스타일 설정과 우선순위가 그대로 보존돼요.

### 기존 페이지에서 옮겨 오기

기존 채팅 페이지에서 자주 쓰던 선택자(`.mes` 메시지 컨테이너, `.mes_text` 메시지 본문, `.mes.Ai`／`.mes.User` 발화자, `#msglistview` 메시지 목록, `.chat-scope-box` 대화 영역)는 샌드박스 페이지에도 모두 그대로 준비돼 있어요:

- CSS 꾸미기와 텍스트／HTML 치환만 쓰는 카드는 규칙을 고치지 않아도 바로 동작해요.
- `<img onerror="…">`로 스크립트를 실행하는 방식도 샌드박스에서 그대로 동작하며 ‘기능 바’나 ‘첫 메시지’에 넣은 시작 코드 모두 실행돼요.
- 사이트 상단 바나 바깥 입력창 등 외부 노드를 직접 건드리던 스크립트는 위의 `sdk` 메서드로 바꿔 주세요.
- `localStorage`는 샌드박스 안에서도 쓸 수 있지만 해당 카드의 격리된 오리진 안에만 남아요. 스마트폰과 PC 사이에서 진행도를 이어 가려면 `sdk.save.*`를 사용하세요.

### 문제 해결

| 겪는 증상 | 원인 및 해결 방법 |
