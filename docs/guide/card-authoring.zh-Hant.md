# 寫卡指南

這份指南整理了網頁編輯器各分區的寫法、世界書與卡片變數的設定方式、公開送審條件，以及沙箱聊天頁的顯示規則與互動腳本規格（`/guide.md`）。

## 最快做出第一張卡

第一次打開建立角色卡頁面時，左邊雖然列了好幾個分區，但其實只要填好四個必填項目就能存檔試聊；手邊有其他平台匯出的舊卡，也能直接拖進來自動填好。

### 手寫新卡的四個必填項

想先讓角色開口說話，只要依序填這四處：

1. 「**基本資料**」**分區 →「角色名稱」**：角色的名字。
2. 「**基本資料**」**分區 →「形象」的「背景圖（直式）」**：建議使用 9:16 直圖，這張圖會同時當作首頁卡片封面、聊天室頭像與匯出 PNG 的卡圖。上傳框標有虛線安全區，把角色的臉和主體放在框內，不同螢幕裁切時才不會切到頭；手邊沒圖也可以直接點生成按鈕，用儲值點數請 AI 當場畫一張。
3. 「**角色設定**」**分區 →「角色設定」**：寫清楚角色是誰、跟玩家是什麼關係、怎麼說話、身在什麼處境。
4. 「**開局**」**分區 →「開場白」**：對話開始時角色對玩家說的第一段話。

四項填好並按下儲存後，編輯頁右邊的「**對話測試**」面板就會開放，不用離開編輯頁就能直接跟角色試聊。在寬螢幕上，拖曳「對話測試」面板左緣的把手可以自由拉寬預覽畫面；如果你中途改了左邊的欄位，記得按一下測試面板上的「存檔並重載」，右邊才會套用最新修改。

### 從其他平台匯入舊卡

新建角色卡時，「基本資料」分區最上方有匯入區塊，支援把其他工具做好的卡直接搬進來：

| 來源 | 匯入方式與帶入內容 |
|---|---|
| SillyTavern | 將 PNG、JSON 或 CHARX 角色卡拖進匯入區。角色設定、開場白、世界書與正規表示式腳本會自動填入對應欄位；PNG 卡片本身的立繪會設為直式背景，若卡內另附主背景則優先採用主背景。 |
| 魅魔島（MMD）三件套 | 分別匯入規則檔（含 `chatVersion`）、開場白與人設檔。標記為新版沙箱的規則檔會自動選用「沙箱」聊天頁。 |
| AI 風月／RiliAI | 匯入角色卡或設定 JSON，自動帶入人設、開局網頁、世界書、內建樣式與變數設定。 |

匯入完成後，先存檔並在右側「對話測試」確認開局畫面、狀態面板與文字顯示正常，再決定儲存範圍或送審。

## 認識編輯器的各個分區

編輯器左邊照著寫卡到上架的順序分成八個分區，有些欄位只給逛卡片頁的玩家看，有些則會在每一輪對話送進 AI，動筆前先分清楚才不會浪費對話空間。

| 左側分區 | 裡面有哪些欄位 | 誰會看到、什麼時候填 |
|---|---|---|
| **基本資料** | **角色名稱**、**角色自稱**（設定裡寫 `{{char}}` 時會換成這個名字，留空就用角色名稱）、**主要語言**。 **形象**：**背景圖（直式）**，展開「橫式背景與分享圖」可補寬螢幕用的 16:9 **橫式背景**與貼到 Discord／LINE／X 時顯示的 1200×630 **分享圖**。 **卡片展示**：**一句話簡介**（首頁卡片顯示前兩行、卡片頁標題下顯示前三行）、**介紹**（卡片頁專屬的 Markdown 說明區，可切換「撰寫／預覽」，適合放玩法說明、登場角色圖鑑與更新紀錄，**只給玩家看，不會送進 AI 對話**）、**標籤**。 | 新建卡片時先填名稱、語言與直圖；準備分享或公開上架前，再把簡介、介紹與分類標籤補齊。 |
| **角色設定** | **角色設定**（核心人設、關係與世界規則，只進模型，不對玩家公開）、**對話示例**（用一問一答示範角色的語氣和句長，寫兩三輪最能定住說話味道，寫太多反而容易綁死）。 展開「回覆格式與額外指示」可填**輸出格式**（規定段落結構或括號動作寫法）與**額外指示**（每輪對話最後附上的簡短提醒，適合放最容易被模型忘記的一兩條規矩）。 | 每張卡的核心。先把角色設定與兩三組對話示例寫紮實，比填滿進階欄位更有用。 |
| **世界**（實驗性） | **啟用世界模式**：讓一張卡容納多位獨立角色。大世界觀寫在「角色設定」，這裡負責新增個別角色，每位角色各有所有人都知道的「側寫」、只有他自己看得到的「完整設定」與「私有世界書」，每回合由世界先裁定誰在場再各自開口。 | 目前還在實驗階段，適合自己測試體驗，正式公開的卡片建議先不要開。 |
| **開局** | **開局呈現**二選一： 1. **開場白**：由角色先發出第一則訊息，可新增多段備選開場白讓玩家挑，也能在下方加**建議的第一句**（玩家點了會填進輸入框）。 2. **開場網頁**：在新對話最上方顯示一頁自訂 HTML 畫面搭配**第一句選項**，玩家點選項就開始（網頁內容只給玩家看，不會送進模型）。 | 每張卡必填其一。一般劇情與陪伴卡選「開場白」；想做像遊戲標題畫面、選出身或挑路線的卡，可以選「開場網頁」或在開場白套用顯示規則。 |
| **世界書** | 建立或匯入世界書，管理單筆條目的關鍵詞、常駐開關與語意召回。 | 當角色背景、地點、支線人物寫超過幾千字，不想每輪都塞滿模型記憶時使用。 |
| **顯示** | **聊天頁**（「沙箱（推薦）」或「傳統」）與**顯示規則**（點「設定正規表示式」管理尋找取代規則與頂部功能欄）。 | 純文字對話卡不用動這裡；想把特定標記轉成狀態欄、選項按鈕或自訂介面時再設。 |
| **進階** | **卡片樣式**（調整氣泡、輸入框、背景顏色與字型，或貼入整張卡共用的自訂 CSS）與**卡片變數**（追蹤好感度、背包、任務等精確數值並畫成面板）。 | 想換聊天室配色，或做養成、跑團、經營這類數值不能算錯的卡時展開設定。 |
| **發布** | **公開範圍**（「僅自己」、「有連結的人」、「公開」）、玩家投票與計數管理、**開啟工坊**（作者 DLC 與玩家擴充）、**還缺什麼**檢查表與**填寫分級問卷**。 | 決定誰能玩這張卡，以及準備公開送審時檢查字數門檻與分級。 |

## 用世界書管理長篇設定

當地名、登場人物、陣營規矩越寫越多，全部塞進「角色設定」會佔滿每一輪的對話空間；把這些「聊到才需要想起來」的背景拆進「世界書」，AI 在長篇對話裡才記得住真正重要的劇情。

進到「世界書」分區點「建一本」（或點「匯入世界書檔」帶入酒館、RiliAI 的世界書 JSON），就能逐條新增設定。每一條設定有兩種帶入對話的方式：

- **常駐（每輪都帶）**：勾選後，不論玩家聊什麼，這一條都會固定放進對話開頭的快取區（同時計入公開送審的 3,000 字有效字數）。適合放整張卡隨時不能忘的核心規則，建議保持精簡；如果常駐條目太多塞不下模型額度，排在前面的條目會優先保留。
- **關鍵詞與語意召回（預設）**：不勾常駐時，填好「關鍵詞」（多個詞用頓號分隔，也支援 `/pattern/flags` 正規表示式；若再填「次要關鍵詞」，則要兩邊同時命中才觸發）。玩家或角色提到關鍵詞時，該條設定就會帶進對話；另外系統預設開啟「**語意召回**」，就算沒精準講出關鍵詞，只要當下話題語意相關，也會在額度內自動挑進來。

如果你寫的是推理真相、後期反轉或隱藏支線，不希望前兩輪因為話題擦邊就被「語意召回」提前翻出來，只要把那一條的「**語意召回**」**關掉**，它就會嚴格等到關鍵詞命中時才出現。單條內容建議控制在 500 字左右、一件事一條，標題直接寫清楚內容（例如「黑市藥商老陳」，不要寫「人物 03」），開啟深入準備（Agent 模式）時角色也能按標題主動查閱。

## 加上狀態欄、選項按鈕與卡片變數

想在回覆底下顯示目前地點、好感度或行動選項，最簡單的方式連正規表示式都不用寫；如果做養成、經營或跑團卡，需要嚴格計算金錢與道具數量，再開啟「卡片變數」交給系統記帳。

### 免寫規則的內建狀態欄與選項按鈕

只要在「角色設定」或「輸出格式」裡交代 AI 在每則回覆最後照這個格式寫，聊天頁就會自動把它們畫成整齊的狀態面板與可點擊的選項按鈕（玩家點按鈕會把文字填進輸入框）：

```text
[status]
地點: 舊城區鐘樓
時間: 23:40
警戒值: 35/100
[/status]

[choices]
推開暗門往下走
留在原地聽腳步聲
[/choices]
```

數值寫成 `35/100` 或百分比時，系統會自動畫成進度條。只有當你想把面板改成卡片專屬的美術風格時，才需要自己寫顯示規則覆蓋它。

### 用「卡片變數」精確記住好感度、金錢與背包

如果只靠文字讓 AI 自己記「目前剩 130 枚金幣、包包裡有兩瓶藥水」，聊長之後模型很容易記錯，玩家退回上一句或重骰回覆時數字也會亂掉。展開「進階」分區點「**加入卡片變數**」，可以把這類資料交給系統精確管理：

1. **定義初始骨架**：用 JSON 寫好一開始有哪些欄位與初始值（不知道怎麼寫可以直接點「插入範例」，套用現成的「好感度」、「背包」或「任務」範本）。每一輪都會把目前的數值送給模型，欄位越精簡越省額度、回覆也越快。
2. **填寫「變數規則」**：用白話寫給 AI 看什麼情況該加減哪個值（例如：「只有送出對方真正喜歡的禮物時好感度才增加，單次最多 +5；買東西時扣減對應金幣」）。AI 會在每輪回覆結尾自動附上隱藏的更新指令，玩家重新生成或退回訊息時，數值也會自動回到對應那一輪的狀態。
3. **設計「面板皮膚」（選填）**：用 Handlebars 語法（如 `{{affection}}`、`{{#each bag}}`）寫一段 HTML 與 CSS，玩家在聊天頁就能點開面板查看目前數值與本輪變化；下方「面板預覽」可以即時檢查畫面。

## 自訂聊天外觀、顯示規則與聊天頁

想替角色卡換一套氣泡與背景配色，到「進階」分區的「卡片樣式」就能直接挑顏色；如果要把 AI 輸出的文字標記變成自訂面板、按鈕或互動畫面，則在「顯示」分區設定聊天頁與正規表示式規則。

### 用「卡片樣式」調整配色與字型

展開「進階」分區的「**卡片樣式**」，可以直接設定氣泡、輸入框、送出鍵、背景底色與字型，或在下方的「自訂 CSS」貼入整張卡共用的樣式（不必加 `<style>` 標籤，也不必設匹配文字，開啟聊天頁時套用一次，上限為 512 KB）。如果是從 AI 風月搬過來的整體美化 CSS，直接貼在這裡就能自動對應到本站的氣泡與輸入框。

### 常用外觀變數

下面這組 CSS 變數在「沙箱」與「傳統」兩種聊天頁都有效，寫在「卡片樣式」的 `.canvas-root` 裡就能統一調整卡片外觀：

| 外觀位置 | 變數名稱 |
|---|---|
| AI 氣泡底色 | `--lt-canvas-bubble-ai-bg` |
| 氣泡文字顏色（AI 與玩家共用） | `--lt-canvas-bubble-fg` |
| 玩家氣泡底色 | `--lt-canvas-bubble-user-bg` |
| 輸入框底色 | `--lt-canvas-composer-field-bg` |
| 送出鍵底色 | `--lt-canvas-send-bg` |
| 強調色 | `--lt-canvas-accent` |
| 字型（完整的 CSS `font-family` 名單） | `--lt-canvas-font` |
| 對話背景色 | `--lt-canvas-bg` |

```css
.canvas-root {
  --lt-canvas-bubble-ai-bg: #243447;
  --lt-canvas-bubble-fg: #f2f2f5;
  --lt-canvas-bubble-user-bg: #37465b;
  --lt-canvas-composer-field-bg: #1e2938;
  --lt-canvas-send-bg: #355a7c;
  --lt-canvas-accent: #8fc9ff;
  --lt-canvas-font: system-ui, sans-serif;
  --lt-canvas-bg: #121b28;
}
```

魅魔島（MMD）舊有的 `--background-color`、`--primary-font-color` 與 `--input-background-color` 變數一樣能繼續使用。變數只會影響採用該變數的元素；如果卡片的 CSS 已經直接對某個元素寫死顏色，直接指定的顏色會優先，而且「顯示規則」裡的樣式也會蓋過「卡片樣式」的設定。

### 用「顯示規則」把文字標記換成自訂畫面

在「顯示」分區點「**設定正規表示式**」，可以建立多條尋找與取代規則。訊息顯示到畫面上之前，會由上往下依序套用所有啟用的規則（模型不會看到轉換後的 HTML）：

- **套用於**：每條規則可勾選套用在「AI 回覆」、「玩家訊息」或「系統訊息」。新建規則預設只勾「AI 回覆」；舊規則若沒有這項設定則維持三種都套用；酒館匯入的規則會照原本的玩家／AI 設定自動換算。若三種都不勾仍可儲存，該規則不會改寫對話訊息，但仍會展開頂部的「功能欄」。
- **匹配（尋找）**：可以填一段固定字串（如 `《狀態欄》`），或填 `/pattern/flags` 格式的正規表示式（如 `/<status>([\s\S]*?)<\/status>/g`）。用正規表示式時，替換內容裡可用 `$1`、`$2` 取用括號抓到的文字，而且匹配樣式裡的中文會自動同時比對繁體與簡體字形。
- **替換內容（取代）**：可寫任意 HTML，也能放 `<style>` 與 `<script>`。所有啟用規則裡的 `<style>` 會在開卡時合併成同一份樣式表，每段 `<script>` 每張卡執行一次。
- **功能欄**：規則編輯器上方的「功能欄」會固定釘在訊息列表頂端，只顯示給玩家看、不會送給 AI。常見做法是在功能欄裡寫入觸發詞（例如 `【狀態欄】【美化】`），再交給下方的規則展開成頂部面板或側邊選單。
- **可用巨集**：替換內容支援 `{{user}}`（玩家的稱呼）與 `{{char}}`（角色名稱，有設角色自稱時用自稱）。
- **容量與即時測試**：單條規則替換內容上限為 512 KB（超過 256 KB 時編輯器會提醒可能影響流暢度，但仍可儲存），整份規則上限為 32 MB（超出時編輯器會標示超出量）。寫好後可以直接把一段 AI 回覆貼進規則編輯器右邊的「**測試**」欄，當場看套用全部規則或單條規則後的畫面。

### 沙箱聊天頁與傳統聊天頁

在「顯示」分區的「**聊天頁**」可以切換兩種執行環境，兩邊的聊天介面（頁首、訊息、輸入區、面板）長得一樣，差別在卡片樣式與腳本跑在哪裡：

- **沙箱（推薦，新卡預設）**：卡片的樣式與腳本跑在獨立隔離的頁面裡，可以自由改造整個聊天畫面（與魅魔島 MMD 新版沙箱相容），同時保護玩家的登入狀態不被腳本讀取，送出訊息、重新生成等會扣積分的動作也只回應玩家本人的點擊。
- **傳統**：規則直接套用在站台原本的聊天頁上，沒有沙箱的 `sdk` 能力。只有在匯入的老卡切到沙箱後顯示異常時才需要改回傳統。

把既有卡片切到「沙箱」後，打開右側「對話測試」檢查頂部功能欄、開場白裡的面板、浮動按鈕與選單是否正常（貼齊畫面左右邊緣的窄側邊按鈕列，聊天頁也會自動把對話欄往內縮，避免壓住文字）。多數卡片不必改就能直接跑；若有腳本需要調整，可查閱末章的[從傳統頁遷移](#從傳統頁遷移)。

## 公開範圍、送審條件與工坊擴充

卡片寫好之後不一定要馬上公開，你可以先設成只有自己或拿到連結的朋友能玩；準備發到站上榜單累積熱度、領取聊天返點與榜單獎金時，再到「發布」分區補齊分類標籤與分級問卷。

### 三種公開範圍

在「發布」分區的「**公開範圍**」可以隨時切換：

| 公開範圍 | 誰能打開這張卡 | 適用情境 |
|---|---|---|
| **僅自己** | 只有作者本人，以及先前已經玩過這張卡的舊玩家可以繼續對話；新玩家打不開，也不會出現在任何公開列表。 | 自己私下玩，或暫時收起不讓新玩家進入。 |
| **有連結的人** | 不會出現在首頁、排行榜與搜尋結果，也不用先經過審核；但只要拿到卡片連結的人都能直接打開遊玩與留言，玩到的是你最新儲存的內容。 | 公開前請朋友幫忙試玩，或在小圈子裡私下分享。 |
| **公開** | 送審通過後出現在首頁、分類與搜尋結果，新玩家玩到的是已過審的穩定版本。其他玩家在卡上聊天你就能分到積分返點，新發布的卡也會自動參加日榜、週榜與月榜獎金結算。 | 正式上架發表作品。 |

### 公開送審的三個條件

「發布」分區的「**還缺什麼**」面板會自動幫你檢查公開上架前必備的項目：

1. **至少選一個官方分類或玩法標籤**：在「基本資料 → 標籤」下方的分類選取器裡至少挑一個（自己手打的自訂標籤可照留，但不算進這項門檻）。
2. **有效字數超過 3,000 字**：「角色設定」加上「已啟用的世界書常駐條目」合計至少要有 3,001 個有效字，兩邊可以互相補足。中英文字母與數字都按字元計算；空白、標點符號、表情符號、HTML／樣式／腳本標籤與模板變數不計入，開場白、對話示例、額外指示與非常駐的世界書條目也不計入門檻。
3. **填寫分級問卷**：點「填寫分級問卷」，照卡片裡實際寫到的設定、圖片，以及故事最深會走到哪種尺度如實勾選（依台灣遊戲軟體分級標示於卡片頁，成人級卡片只對已開啟成人內容開關的玩家顯示；包含戀愛交往或結婚情節的卡片至少為 12+）。

卡片公開之後，你還是可以繼續叫編輯器儲存修改，改動只會留在你自己的草稿裡，不會馬上動到線上玩家正在玩的版本；等改完確認無誤再次送審通過，新版才會正式上線。更新送審時預設不發通知，勾選通知並附上更新說明才會推播給收藏與追蹤者（每張卡每 3 天最多發送一次更新通知）。

### 開啟工坊（作者 DLC 與玩家擴充）

在「發布」分區打開「**開啟工坊**」開關（預設關閉）後，卡片頁會多出「工坊」分頁：原作者自己可以發布**作者 DLC**（追加額外開場白、顯示規則與世界書條目），其他玩家也能為這張卡製作**玩家擴充**（僅限追加世界書條目，單一擴充的常駐世界書上限為 1,500 字，且玩家擴充完全讀不到原卡私有的角色設定、世界書與正則規則）。

## 沙箱互動腳本與相容性參考

當你想在卡片裡寫 JavaScript 腳本控制輸入框、做跨裝置存讀檔、接全服玩家投票，或是把舊版傳統頁的卡片搬進沙箱時，可以在這一章查閱完整的節點選擇器、`sdk` 方法、事件與錯誤碼。

### 節點選擇器與沙箱專用 CSS 變數

沙箱頁提供固定的 `data-chat` 與 `data-slot` 屬性，與魅魔島（MMD）新版沙箱規格相同，同一份腳本可在兩邊執行。請用下列屬性選取節點，不要依賴站台內部的 class 名稱：

| 選擇器 | 說明 |
|---|---|
| `[data-chat="root"]` | 聊天畫面的根節點。`data-theme` 為 `dark`／`light`；`data-composer` 表示輸入區是否顯示。 |
| `[data-chat="message"]` | 單則訊息容器。`data-from` 為 `ai`／`user`；`data-state` 為 `pending`／`streaming`／`done`；`data-msg-id` 為伺服器端的訊息 ID。 |
| `[data-chat="message-body"]` | 訊息正文（套用顯示規則後的 HTML）。 |
| `[data-slot="statusbar"]` | 頂部功能欄容器。 |
| `[data-slot="left"]`／`[data-slot="right"]` | 左右側邊欄停靠槽。放進這裡的元素視為該側停靠側邊欄，對話欄會自動讓出寬度。 |
| `[data-chat="author-stage"]` | 作者舞台層。呼叫 `sdk.stage.open('content')` 覆蓋訊息區，`open('full')` 覆蓋整頁。 |
| `[data-chat="input"]` | 訊息輸入框。 |
| `[data-chat="composer"]` | 底部輸入區整體容器。 |

除了雙頁共用的[常用外觀變數](#常用外觀變數)之外，沙箱殼的顏色與尺寸另外由 `--chat-*` 系列 CSS 變數定義（例如 `--chat-bg`、`--chat-text`、`--chat-accent`、`--chat-bubble-ai-bg`），在根節點覆寫即可整體換色；這組變數只在沙箱聊天頁有效。

### `sdk` 方法一覽

| 方法 | 說明 |
|---|---|
| `sdk.input.get()` / `set(text)` / `add(text)` / `insert(text)` / `clear()` / `focus()` / `blur()` / `getCursor()` / `setCursor(pos)` | 讀寫與控制底部輸入框文字及游標位置。 |
| `sdk.composer.show()` / `hide()` / `visible()` | 顯示、隱藏底部輸入區，或查詢目前是否顯示。 |
| `sdk.message.send(text)` | 以玩家身分送出訊息。若不在玩家本人的點擊事件當下呼叫，系統會先彈出確認視窗。 |
| `sdk.message.edit(id, text)` | 改寫指定訊息（`data-msg-id`）並重新送出，同樣需經玩家點擊或確認。 |
| `sdk.save.get(key)` / `set(key, value)` / `remove(key)` / `keys()` | 跨裝置永久存檔。每張卡每位玩家最多 10 個 key；key 限英數、`_`、`-`；單筆 JSON 值上限 64 KB。 |
| `sdk.cache.get(key)` / `set(key, value)` / `remove(key)` | 單次開頁暫存，重新整理或離開頁面後清空。 |
| `sdk.stage.open(mode)` / `close()` / `el()` / `visible()` | 開關與取得作者舞台節點（`mode` 為 `'content'` 或 `'full'`）。 |
| `sdk.role.get()` | 取得角色名稱與頭像網址。 |
| `sdk.user.get()` | 取得玩家稱呼、頭像與介面語言（`locale`，例如 `zh-Hans`）。 |
| `sdk.text.convert(text)` / `sdk.text.ready()` | 將腳本自己畫在畫面上的文字轉為玩家當前的簡繁字形，轉換規則與聊天頁處理回覆正文一致；卡片語言與玩家字形相同時原樣回傳。字典載入完成前 `convert` 會先原樣回傳，`ready()` 會在字典就緒時完成（不需轉換時立即完成）。 |
| `sdk.model.get()` | 取得玩家目前選用的模型資訊 `{ name, cost }`：`name` 為頂欄顯示的「模型名 · 線路名」，`cost` 為下一輪預估積分（動態計價模型為區間字串，如 `127–251`）；平台尚未傳入前兩者皆為空字串。若要讓玩家切換模型，請引導點擊輸入區的模型按鈕。 |
| `sdk.generation.get()` | 查詢目前這一輪生成等待狀態 `{ phase, since, outcome }`。 `phase` 為 `idle`、`preparing`（剛送出尚無回應）、`summarizing`（平台正在壓縮整理長篇劇情，在第一個字出現前可能耗時數十秒）、`thinking`（模型思考中、正文尚未開始；不支援思考的模型無此階段）或 `writing`（正文串流輸出中）；`since` 為進入該階段的毫秒時間戳（不含思考內容原文）。 `outcome` 在正常完成或生成中為 `null`；上一輪未正常完成時，回傳聊天頁顯示在訊息下方的狀態卡 `{ kind, label, sub, actions }`。`kind` 可能為 `model-error`、`network-error`、`server-error`、`rate-limit`、`quota`（積分不足）、`filtered`、`length-cap`、`stopped`、`compact-retryable`、`outcome-unconfirmed`（結果確認中，無按鈕，完成後自動更新）或 `interrupted`（Agent 準備尚未跑完）；`label` 與 `sub` 為玩家語言的說明文字；`actions` 為可用按鈕陣列 `[{ action, label }]`，`action` 值為 `retry`、`continue`、`switch-model`、`model-settings`、`capacity`、`refresh`、`retry-stream-off`、`edit-message`、`switch-lane`、`resend-traditional`。最後四項僅出現在 `filtered` 狀態卡：`retry-stream-off` 會先關閉本段對話的串流輸出再重試、`edit-message` 打開被攔截的訊息供玩家修改並取代原訊息重送、`switch-lane` 打開模型選單並停在目前模型的其他線路、`resend-traditional` 將含簡體字的被攔截訊息整句轉為繁體後直接取代重送（同一則僅提供一次）。 |
| `sdk.generation.act(action)` | 觸發上述狀態卡的指定按鈕（傳入 `outcome.actions` 內的 `action`），效果與玩家親手點擊平台狀態卡相同（例如重試會沿用原訊息，不會重複送出新一則）。必須在玩家點擊事件當下呼叫（否則拒絕並回傳 `UNAUTHORIZED`，不會彈窗詢問）；目前狀態卡未提供該動作回 `INVALID_ARGS`；生成中回 `BUSY`；每分鐘最多呼叫 3 次，回傳 Promise。 |
| `sdk.archive.list()` / `save(title?)` / `fork(messageId)` / `open(id)` / `start(opening?)` / `rename(id, title)` / `remove(id)` | 操作平台的對話存檔（每張卡最多 20 段，含目前這段，跨裝置同步）。`open` 讀取指定存檔（原進度保留在清單中）；`save` 把目前進度留一份並取名，回傳 `{ id, current }`（`id` 為保留下來的舊存檔，後續在複製出的 `current` 繼續遊玩）；`fork` 從指定訊息（氣泡的 `serverId`）另開一段分叉；`start` 另開新對話（`0` 為預設開場白，`1` 以上為對應備選開場白）；`list` 回傳 `{ items, count, limit }`，每筆含 `id, title, isCurrent, messageCount, lastMessage, createTime, lastUpdateTime`。會變動存檔的操作請在玩家點擊當下呼叫並搭配卡片自製確認畫面；不在點擊當下呼叫時，系統會彈窗詢問玩家。 |
| `sdk.on(event, handler)` | 訂閱聊天頁事件。 |
| `sdk.debug.log(...args)` | 輸出除錯紀錄；在聊天頁網址加上 `?sdkDebug=1` 即可打開除錯面板查看。 |

### 事件、執行規則與錯誤碼

| 事件名稱 | 觸發時機與載荷 |
|---|---|
| `ready` | 開頁時既有訊息全部掛載完成後觸發一次（不補發）。 |
| `message:new` | 新訊息建立時觸發。 |
| `message:mount` | 訊息節點掛載進畫面時觸發（晚訂閱會收到已掛載訊息的補發）。 |
| `message:stream` | AI 串流輸出文字更新時觸發。 |
| `message:done` | 單則訊息輸出完成時觸發（晚訂閱會收到已完成訊息的補發）。 |
| `message:unmount` | 訊息節點從畫面移除時觸發。 |
| `input:change` | 輸入框文字變更時觸發。 |
| `conversation:switch` | 讀檔、存檔、分叉或開新對話切換會話後觸發，載荷為 `{ conversationId }`。 |
| `theme:change` | 切換深色／淺色主題時觸發。 |
| `back` | 玩家按下頁首返回鍵時觸發。 |
| `stage:close` | 作者舞台被關閉時觸發。 |
| `dispose` | 頁面即將卸載時觸發。 |
| `model:change` | 玩家更換模型，或下一輪預估積分變動（如調整上下文長度、思考深度）時觸發，載荷同 `sdk.model.get()`。 |
| `generation:phase` | 生成等待階段改變時觸發，載荷為 `{ phase, since }`（不補發，晚到的腳本請先呼叫 `sdk.generation.get()`）。 |
| `generation:outcome` | 上一輪異常狀態卡出現或因重試收起時觸發，載荷同 `sdk.generation.get().outcome`，可能為 `null`（不補發）。 |
| `share:change` | 分享設定或玩家推薦碼晚一步載入完成時觸發（無載荷，請重新讀取 `sdk.share`）。 |

腳本執行時遵循四條規則：

- 開頁載入既有對話時，每則訊息依序觸發 `message:new`、`message:mount`、`message:done`，全部跑完後觸發一次 `ready`。
- 在訊息事件處理函式（以及訊息氣泡內的點擊／輸入事件處理函式）裡呼叫 `document.querySelector` 等查詢方法時，只會搜尋**該則訊息氣泡**；在處理函式外部呼叫才是整份 `document`。
- 沙箱腳本無法對外部網址發起網路請求（`fetch` 等），但外部 `<script src="https://…">`、圖片與字型檔可以正常載入。
- 一般錯誤碼：`UNAUTHORIZED`（玩家拒絕確認或非點擊當下呼叫受限動作）、`RATE_LIMITED`（呼叫過於頻繁）、`INVALID_ARGS`（參數不合法或超過容量上限）、`HOST_DENIED`（宿主頁拒絕此操作）、`BUSY`（正在生成回覆中）、`LIMIT_REACHED`（對話存檔已滿；`err.data` 為 `{ count, limit }`，請提示玩家先刪一段舊存檔）、`NOT_SUPPORTED`（目前環境不支援此功能）。

### 可靠的訊息歷史（`sdk.history`）

需要根據完整對話紀錄重建遊戲狀態時，沙箱卡可使用 `sdk.history`（傳統卡為 `stage.history`），不要依賴畫面上隨捲動裝卸的 DOM 氣泡：

- **探測與分頁讀取**：先檢查 `history?.capabilities().available`（舊版宿主頁與離線預覽可能不支援）。呼叫 `list({ cursor, revision, content: true })` 只會讀取目前玩家在這張卡當前對話的紀錄；續讀下一頁時必須沿用第一頁拿到的 `revision`，將各頁累積到收到 `complete: true` 的最後一頁後，才採用整份清單（中途遇到 `HISTORY_STALE` 代表對話已變動，需放棄半途結果重頭讀起）。
- **訊息關聯（`replyTo`）與狀態判定**：每筆項目都帶有 `replyTo: string | null`。AI 回覆的 `replyTo` 指向觸發這則回覆的玩家訊息 `id`（僅供該段對話內部對照的識別字串，與這份 history 共用同一組 ID，目標訊息可能位在另一頁）；玩家訊息、開場白與無法核實關聯的舊資料／分叉複製訊息填 `null`（舊宿主也可能省略此欄，請一律視為未知，不要靠前後相鄰順序猜測）。重新生成會建立新的玩家與 AI 訊息 ID，新回覆指向新的玩家 ID；手動編輯 AI 回覆會保留原 ID 與 `replyTo`；退回會移除捨棄的訊息；若玩家訊息被刪除而 AI 回覆仍保留，該回覆的 `replyTo` 會變為 `null`。一般接續原回覆文字的續寫（`contine`／`continue_response`）仍不支援；繼續已保存的 Agent 準備進度則會沿用原本的玩家訊息 ID。開啟 `content: true` 取回的正文，只包含已經輸出完畢、畫面上看得到的原文（不含思考過程、還在串流中的字，或因內容審核隱藏的文字），請以 `item.complete` 判斷回覆是否完整結束，不要把中斷或失敗的回覆當成成功存檔點。
- **訂閱變更（`onChange`）**：呼叫 `onChange(callback)` 會回傳取消訂閱函式。每次變更項帶有 `{ op, id, replyTo, replacementId? }`（`add`／`update` 的 `replyTo` 為讀取當下可核實的關聯，`remove` 一律為 `null`；從未掛載進畫面或已卸載的訊息被真正刪除時一樣會收到變更，單純捲出可視區的 `message:unmount` 不算刪除）。收到第一包事件時，請先把卡片推算的衍生狀態標為待確認，等重新取得完整清單後再計算（就算只收到玩家訊息刪除，相關 AI 回覆的關聯也可能一併變成未知）。舊游標、`reset` 或 `unavailable` 代表未知，不是空歷史。其他裝置在前景每 15 秒及切回前景時會檢查更新；離開卡片時記得取消訂閱。`revision` 與上述對話內 ID 都不是玩家帳號身分。

### 全服投票、共鬥計數與分享回流（`sdk.shared`）

在規則檔 `rules.json` 的 `sharedState` 宣告過的投票題目與計數器，由所有玩這張卡的玩家共用同一份統計，透過 `sdk.shared`（傳統卡為 `window.stage.shared`）讀寫：

- **`read(keys)`**：收單一 key 或最多 16 個 key，回傳 `{ [key]: { kind: 'poll', counts, total, mine? } | { kind: 'counter', total, mine?, goal?, reachedAt?, previous? } }`。未宣告的 key 不在結果裡；`mine` 為玩家自己投的選項或貢獻（未登入訪客沒有）；計數器的 `total`、`mine` 與排行榜每一期重新開始，`previous` 為上一期的總數。
- **`vote(key, option)`**：回傳 `{ mine }`。同一題每人每天最多投或改 10 次，第一次投票也算；重複投給同一個選項不計次。
- **`add(key, delta)`**：加上 `1` 到該計數器 `maxStep` 之間的整數，回傳 `{ total, mine, reachedAt }`。
- **`leaderboard(key, { limit })`**：回傳本期貢獻最多的玩家 `{ items: [{ rank, name, value }], mine? }`（預設 10 名、最多 50 名，以公開暱稱顯示，不列出測試帳號）。

所有人都能讀；寫入需要已登入且玩過這張卡的玩家（開過一段對話即可）。數字不會主動推播，請自行重讀，間隔至少 10 秒。作者可以在自己任何一張卡上測試（含全新私卡與 CLI 試玩卡），作者自己的數字與正式玩家分開；作者草稿試玩（`?mode=source`）與測試帳號也各有獨立的一份數字，不混進正式統計，可在編輯頁「發布」分區的「玩家投票與計數」或用 `hearthroom card state` 查看、暫停與歸零。

若想做「把題目分享給朋友填、收回統計解鎖內容」的玩法，可為宣告了 `share: true` 的投票呼叫非同步方法 `sdk.share.tallyLink(code, pollKey)`（請在點擊前準備好連結；同一組情境碼與投票會拿回同一條 `?share=~XXXXXXXX` 短連結，每位玩家每天最多 20 條，90 天內有效）。朋友開啟後，`sdk.share.context` 是情境碼，`sdk.share.poll` 是可回答的題目 `{ key, options }`（沒有時為 `null`），以 `sdk.share.respond(option)` 作答（每條連結各記一份，與主投票分開）。分享者用 `sdk.share.results()` 讀取自己發出的連結，每筆為 `{ context, pollKey, total, counts, updatedAt }`：`total` 即時更新，`counts` 要滿 3 位朋友回答才出現並每天更新一次。卡片不會知道誰分享、誰回答；可依數字解鎖卡內內容，但不會發放平台積分。沙箱與傳統兩種頁面使用同一組錯誤碼：`SHARED_DISABLED`（平台或作者已暫停）、`NOT_DECLARED`、`OPTION_INVALID`、`NOT_ELIGIBLE`（還沒玩過此卡，或回答自己的連結）、`UNAUTHORIZED`（未登入）、`RATE_LIMITED`（稍後再試）、`LIMIT_REACHED`（`err.data.reason` 為 `goal` 或 `limit`）與 `HOST_DENIED`（舊版遊玩頁；看過去的對話或審核試玩時只能讀；從沒送審也沒設過公開範圍的試玩卡無法用 `tallyLink` 產生回流連結，因為別人打不開）。

### 分享圖片、複製文案與帶情境的分享連結

- **分享圖片與複製文案（瀏覽器原生能力）**：HTTPS 卡片框架由宿主頁委派 `web-share` 與 `clipboard-write` 權限（不委派 `clipboard-read`）。腳本可在玩家點擊按鈕後呼叫 `navigator.share`（接收事先準備好的圖片 `File` 與文字）、`navigator.clipboard.write` 搭配 `ClipboardItem`（寫入 PNG）或 `navigator.clipboard.writeText`（寫入文案）；這些是瀏覽器原生能力，不是新增的 `sdk` 方法或 HTTP 端點。提供按鈕前請先檢查 `navigator.share`、`navigator.canShare({ files: [file] })`、`navigator.clipboard.write` 與 `ClipboardItem`，並在點擊前就準備好檔案以保留使用者啟動狀態。支援情況依瀏覽器、作業系統、權限與接收 App 而定，分享後不保證圖片與文字都會同時保留；請捕捉拒絕與取消，不支援或被拒時改提供下載圖片與可選取的文案，玩家取消後不要自動重開分享面板。本機不透明來源的預覽仍可能拒絕呼叫，請在目標裝置的實際跨來源卡片上驗證。
- **帶情境碼的分享連結（`sdk.share`）**：呼叫 `sdk.share.link(code)`（傳統卡為 `window.stage.share.link`）會同步回傳這張卡的分享連結 `/cards/<卡號>`，帶上已登入玩家的推薦碼，有給情境碼時再加上 `?share=<code>`（請在點擊前產生連結，於點擊處理函式內交給 `navigator.share`；推薦碼較晚取得時會觸發 `share:change` 事件，屆時可重讀更新連結）。朋友從這條連結開卡時，腳本可由 `sdk.share.context` 讀回同一個情境碼（沒有帶碼或正在看過去的對話時為 `null`），做出「你朋友選了這個，換你接手」的互動。情境碼只收 1 至 64 個英數字與 `.`、`_`、`-` 且開頭須為英數字（不合規則時沙箱卡丟出 `SHARE_CONTEXT_INVALID`，傳統卡得到 `null`）；平台只負責傳遞字串，不會送進模型、也不含玩家資料，而且任何人都能手打網址，請只接受卡片自己定義的代碼，朋友是否已有存檔由卡片自行判斷（例如查 `sdk.archive.list()`；未登入訪客沒有存檔）。`sdk.share.audience` 表示誰打得開這條連結：`author`（僅自己可見的卡，新朋友打不開）、`link` 或 `public`。平台關閉分享開關時 `sdk.share.enabled` 為 `false`，`context` 為 `null` 且 `link()` 回傳一般卡片連結。另可用 `sdk.share.qr(text)` 取得 `{ size, path }`（`size` × `size` 格的 SVG path）畫進分享圖。作者可用 `?mode=source&share=<code>` 在草稿上測試。

### 側邊欄自動避讓（`--lt-dock`）與樣式相容細節

- **固定側邊欄避讓**：貼齊畫面左右邊緣、寬度約 48px 以內的固定按鈕列，聊天頁會自動把中間對話欄往內縮（沙箱與傳統頁皆適用；全螢幕彈窗、置中面板與更寬的區塊不會自動縮排）。想手動指定或關閉避讓時，直接在側邊欄最外層元素的 `style` 屬性寫入 `--lt-dock`（寫在行內 `style` 對所有卡片格式都有效）：

| `--lt-dock` 值 | 效果 |
|---|---|
| `left`／`right` | 強制視為停靠在該側的側邊欄，不必貼齊畫面邊緣，寬度上限放寬到對話欄的 30%。 |
| `none` | 不為這個元素讓出空間。若寫在 `:root` 上則整張卡停用自動避讓（SillyTavern 格式卡片的顯示規則樣式只作用在訊息內，寫在 `:root` 無效）。 |

```html
<div id="my-sidebar" style="position: fixed; left: 0; top: 30%; --lt-dock: left;">…</div>
```

若扣除側邊欄後對話欄剩餘寬度不到原本的 75%，系統不會縮排；實際讓出的寬度會寫在 `<html>` 的 `--lt-canvas-dock-left` 與 `--lt-canvas-dock-right`（未縮排時不存在），可供卡片對齊自己的介面。

- **卡片樣式與顯示規則的相容層級**：AI 風月寫法的 CSS 放在「進階 → 卡片樣式」（CLI 為 `card.css`，上限 512 KiB UTF-8 位元組）時，系統會自動把 `#customized-answer-content`、`#ai-chat-input`、`#ai-send-button` 等已知風月選擇器對應到本站的氣泡、輸入框與送出鍵，作者不必手選來源，同一段 CSS 也能混用風月與本站選擇器（`.mes` 不會被誤判為酒館來源標記；舊卡若想套用最新風月相容效果可重新匯入）。「顯示規則」裡的 `<style>` 則維持既有 `cssDialect` 與已編譯樣式標記，沒有標記時照原卡片格式決定作用範圍（酒館格式只作用在訊息氣泡內，其他格式照寫生效），不會自動對應風月選擇器。整體樣式優先順序由低到高為：平台預設與主題 ＜ 卡片樣式 ＜ 顯示規則裡的樣式；已匯入的舊卡在開啟與儲存時會保留原本的樣式設定與優先序。

### 從傳統頁遷移

傳統聊天頁常用的選擇器（`.mes` 訊息容器、`.mes_text` 訊息正文、`.mes.Ai`／`.mes.User` 發言方、`#msglistview` 訊息列表、`.chat-scope-box` 對話區）在沙箱頁裡全部保留：

- 只用到 CSS 樣式與純文字／HTML 取代的卡片，切到沙箱後直接可用，不必改規則。
- 用 `<img onerror="…">` 啟動腳本的寫法在沙箱一樣有效，放在「功能欄」或「開場白」裡的啟動片段都會執行。
- 原本直接去抓站台頂欄、輸入框等外部節點的腳本，請改用上方的 `sdk` 方法。
- `localStorage` 在沙箱內仍可使用，但只留在該張卡自己的隔離網域下；需要跨手機與電腦保留進度時，請改用 `sdk.save.*`。

### 疑難排解

| 遇到的狀況 | 原因與處理方式 |
|---|---|
| 改了設定或規則，右邊「對話測試」沒變 | 測試面板跑的是上一次存檔的版本，按面板上的「存檔並重載」就會更新。 |
| 第一次開卡畫面空白十幾秒 | 瀏覽器首次載入沙箱環境資源較慢，之後有快取就會變快；若超過 20 秒仍空白會跳出提示，重新整理頁面即可。 |
| 卡片自己的導覽或遮罩蓋住畫面、滑不動 | 這是卡片腳本自帶的新手教學層，點畫面上的「跳過」或關閉鈕即可。 |
| 規則裡的腳本完全沒反應 | 在聊天網址後面加上 `?sdkDebug=1` 打開除錯面板，查看腳本報錯訊息與 `sdk.debug.log` 輸出。 |
| `sdk.save` 存檔失敗 | 檢查 key 是否只含英數字、`_`、`-`，單筆資料是否超過 64 KB，以及這張卡的 key 總數是否已滿 10 個。 |
| 對話氣泡左右兩側變得比預期窄 | 卡片裡貼近畫面邊緣的裝飾元素被自動判定成側邊欄了，在該元素的 `style` 加上 `--lt-dock: none` 即可恢復。 |
