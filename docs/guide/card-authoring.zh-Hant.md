# 寫卡指南

這一頁給寫角色卡的人：一張卡由哪些東西組成、兩種聊天頁怎麼選、規則與腳本怎麼寫、從別的平台匯入要注意什麼。看完就能照著做；不用先懂程式。

## 一張卡有什麼

| 欄位 | 用途 | 一句話建議 |
|---|---|---|
| 名稱、頭像、背景圖 | 榜單與對話頁上看得到的門面 | 頭像用正方形；背景太亮字會看不清 |
| 簡介 | 榜單卡片上的一兩句話 | 寫「玩起來像什麼」，不要寫設定集 |
| 人設 | 角色是誰、怎麼說話、世界規則 | 越具體越穩；「不做什麼」也要寫 |
| 開場白 | 對話的第一則訊息（可以有多條備選） | 給玩家一個能接話的情境 |
| 世界書 | 依關鍵詞觸發的補充設定 | 條目短而多，勝過一條長文 |
| 規則（正規表示式） | 把模型回覆裡的特定文字換成排版、狀態欄、按鈕 | 見下面「規則」 |
| 聊天頁 | 這張卡開起來用哪一種聊天頁：沙箱或傳統 | 新卡預設沙箱 |

存過一次之後，右邊的「對話測試」可以直接開玩；寬螢幕上拖左緣的把手可以改預覽寬度，看卡在不同寬度下長什麼樣。

## 兩種聊天頁：沙箱與傳統

兩種都是同一套聊天畫面（同樣的頁首、訊息氣泡、輸入區、面板），差別只在**你的規則與腳本在哪裡執行**。

- **沙箱（預設、推薦）**：卡片的畫面與腳本在一個隔離的頁面裡執行，跟站台本身分開。你的樣式與腳本可以放手改整個聊天畫面；同時卡片碰不到玩家的登入狀態，也不能替玩家做決定（送出、重新生成這類會花點數的動作，只認玩家自己的點擊）。
- **傳統**：規則直接套在站台的聊天頁上，就是以前的做法。只有當一張舊卡在沙箱裡跑不對勁時才需要切回來。

怎麼選：新卡就用沙箱。既有的卡切到沙箱之後開來看一遍——大多數卡不用改任何東西；如果某個效果沒出來，先看下面「從傳統頁搬到沙箱」，真的搬不動再改回傳統。

## 規則（正規表示式）

一條規則＝「找什麼」＋「換成什麼」。模型回覆的文字先跑過所有規則，再畫到畫面上。

- **找什麼**：可以是一段固定文字（例如 `《狀態欄》`），也可以是正規表示式（`/<status>([\s\S]*?)<\/status>/g`）。用正規表示式時，`$1`、`$2` 在「換成什麼」裡代表擷取到的內容。
- **換成什麼**：任何 HTML。可以帶 `<style>` 與 `<script>`；`<style>` 整張卡合成一份套用，`<script>` 整張卡只執行一次。
- **狀態欄觸發串**：規則編輯器裡的「狀態欄」欄位是一段常駐內容，會放在訊息列表上方；你通常在裡面放幾個觸發詞（例如 `【狀態欄】【美化】`），再用規則把它們換成真正的面板。
- **巨集**：`{{user}}` 是玩家的稱呼、`{{char}}` 是角色名。
- **上限**：單條規則 128 KB；整份規則以 MB 計，超過時編輯器會直接告訴你差多少。

規則編輯器裡有「測試」欄：貼一段模型會回的文字，立刻看規則套完的結果。

## 沙箱頁的作者工具

沙箱頁給作者一組固定的節點名與一個 `sdk` 物件，跟魅魔島新版沙箱相同，同一份腳本兩邊都能跑。

固定節點（用 `data-chat` 屬性找，別依賴 class 名）：

| 節點 | 意思 |
|---|---|
| `[data-chat="root"]` | 整個聊天畫面的根；`data-theme` 是深淺，`data-composer` 是輸入區開關 |
| `[data-chat="message"]` | 一則訊息；`data-from` 是 `ai`／`user`，`data-state` 是 `pending`／`streaming`／`done`，`data-msg-id` 是伺服器的訊息編號 |
| `[data-chat="message-body"]` | 訊息正文（規則套完的 HTML 放在裡面） |
| `[data-slot="statusbar"]` | 狀態欄 |
| `[data-chat="author-stage"]` | 作者舞台：`sdk.stage.open('content')` 蓋住訊息區、`open('full')` 蓋整頁 |
| `[data-chat="input"]`、`[data-chat="composer"]` | 輸入框與輸入區 |

顏色與尺寸走 `--chat-*` 變數（例如 `--chat-bg`、`--chat-text`、`--chat-accent`、`--chat-bubble-ai-bg`），在根節點上覆寫就能整體換色。

`sdk` 能力（都在，直接用）：

| 能力 | 做什麼 |
|---|---|
| `sdk.input.get/set/add/insert/clear/focus/blur/getCursor/setCursor` | 讀寫輸入框 |
| `sdk.composer.show/hide/visible` | 開關輸入區 |
| `sdk.message.send(text)` | 替玩家送一句。不是在玩家點擊當下呼叫的話，會先跳確認框問玩家 |
| `sdk.message.edit(id, text)` | 改寫一則並重送（同樣會問玩家） |
| `sdk.save.get/set/remove/keys` | 存檔：每張卡每個玩家最多 10 個 key，key 只許英數、`_`、`-`，單值 64 KB；跨裝置保留 |
| `sdk.cache.get/set/remove` | 暫存：只活在這次開頁 |
| `sdk.stage.open/close/el/visible` | 作者舞台 |
| `sdk.role.get()`、`sdk.user.get()` | 角色名與頭像、玩家稱呼與頭像 |
| `sdk.on(event, fn)` | 訂閱事件 |
| `sdk.debug.log(...)` | 寫到除錯面板（網址加 `?sdkDebug=1` 就看得到） |

事件：`ready`、`message:new`、`message:mount`、`message:stream`、`message:done`、`message:unmount`、`input:change`、`conversation:switch`、`theme:change`、`back`、`stage:close`、`dispose`。

幾條會影響寫法的規矩：

- 開頁時對每一則既有訊息依序發 `message:new → message:mount → message:done`，最後才發 `ready`；`ready` 只發一次。晚一步才訂閱 `message:mount`／`message:done` 的話，已經掛上的訊息會補發給你。
- 事件回呼裡的 `document.querySelector` 只看得到**那一則訊息**的內容；回呼外面就是一般的頁面。
- 腳本在沙箱裡連不到外部網址（只有外鏈的 `<script src="https://…">` 可以載）。圖片與字型可以用外部網址。
- 錯誤碼：`UNAUTHORIZED`（玩家拒絕）、`RATE_LIMITED`、`INVALID_ARGS`、`HOST_DENIED`、`BUSY`（正在生成）、`NOT_SUPPORTED`。

## 傳統頁的寫法（與從傳統頁搬到沙箱）

傳統頁上，規則套進站台的聊天頁，作者常用的鉤子是訊息的 class 名：`.mes`（一則）、`.mes_text`（正文）、`.mes.Ai`／`.mes.User`（誰說的）、`#msglistview`（列表）、`.chat-scope-box`（整個對話區）。這些名字在沙箱頁裡**一樣都在**，所以：

- 只做樣式與文字替換的卡，切到沙箱不用改。
- 用「壞圖片點火」（`<img onerror="…">`）啟動腳本的卡，沙箱也支援；引擎片段放在狀態欄或開場白裡都找得到。
- 腳本裡直接讀寫站台頁面其他部分（例如頁首、輸入區以外的東西）的做法，在沙箱裡改用 `sdk`。
- 卡片自己存進 `localStorage` 的東西，在沙箱裡仍然可用，但只在這張卡自己的網域下；要跨裝置就改用 `sdk.save.*`。

搬過去之後開一次「對話測試」對照：狀態欄、開場白裡的面板、右側浮動鈕、三個點選單、各個面板（模型設定、用戶人設、手帳…）在兩種頁下應該長得一樣。

## 從別的平台匯入

- **酒館（SillyTavern）**：PNG 或 JSON 角色卡直接拖進「基本」分區；人設、開場白、世界書、正則腳本會自動填好，PNG 裡的立繪會上傳成頭像。
- **魅魔島（MMD）三件套**：規則檔（含 `chatVersion`）、開場白、人設分別匯入；規則檔標了新版沙箱的會自動選到沙箱。
- 匯入後先在「對話測試」跑一輪，再存檔發布。

## 疑難排解

- **開卡後畫面空白十幾秒**：第一次載入沙箱頁的檔案較慢，之後就快了；超過二十秒仍空白會出現提示，重新整理即可。
- **卡片的導覽或遮罩蓋住畫面、滑不動**：那是卡片自己的教學層，按它的「跳過」。
- **腳本沒反應**：網址加 `?sdkDebug=1` 打開除錯面板，腳本錯誤與 `sdk.debug.log` 都在裡面。
- **存檔寫不進去**：看 key 是否只用英數、`_`、`-`，單值是否超過 64 KB，是否已經有 10 個 key。
