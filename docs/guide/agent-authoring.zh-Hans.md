## 能交给 Agent 的事

Agent 依官方写卡技能工作：厘清你的需求（只在不同理解会产生不同卡片时才向你确认），把卡写成文件夹、推成试玩卡，自行检查与试玩，再反馈还能改进的地方。每一项都附一句可以直接输入的提示词。

### 从一个点子写出整张卡

> “写一张修仙卡：我是被逐出宗门的废柴，师姐偷偷帮我，张力是她一出手就会被发现。状态只要修为一项。先做成试玩卡，告诉我最弱的一层。”

只有模糊的想法也可以。Agent 会先与你厘清设定、人物、关系与开场白，再开始撰写。

### 修复现有的卡

> “导入这张 SillyTavern 卡，告诉我为什么聊三轮就没话说，然后修掉。”

SillyTavern 的 PNG、JSON、CHARX 和魅魔岛三件套都能直接导入。

### 制作状态栏、主题或整页界面

> “加一个显示好感度和所在地点的状态栏，渲染开场白给我看。”

需要画面时，Agent 使用工具包内置的沙盒套件（把模型写的状态区块画成面板、选项按钮与主题），以 `hearthroom card check` 检查文件夹，再以 `hearthroom card preview` 与 `card render` 查看结果。即使没有任何显示规则，平台也会把回复结尾的 [status]／[choices] 区块画成面板与按钮；需要自定义样式、主题或钉选栏时才使用套件。

聊天页本身是开源的（`hearthroom/moonstage`，本站的 `stage` 子模块）：skills 的沙盒契约由它的 `src/sandbox/` 生成，文档未涵盖的部分，平台事实页列出应读取的文件。

### 试玩并找出问题

> “用第二个开场白玩十轮，告诉我玩家会在第几轮失去兴趣、原因是什么。”

### 上架前的检查

> “检查这张卡能不能送审，列出还要修的地方。”

## Agent 怎么写卡

1. **写成文件夹**：长文是 Markdown 文件，世界书、规则和图片各有自己的文件，你可以直接打开查看或修改。
2. **推成试玩卡**：只有你看得到，最后一次更新后 3 天过期，同时最多 5 张。
3. **检查与渲染**：依平台规则检查字数与内容，把开场白套上规则渲染出来，确认状态栏和版面正确。
4. **试玩**：实际与角色对话一轮，确认回复能否延续、玩家是否接得下去。
5. **修改**：依结果修改，再推送、再试玩，直到你满意。
6. **保存**：满意之后存成正式的私人卡，出现在“我的卡片”。送审和公开由你在网站上决定。

## 提示词指南

Agent 依官方技能工作，不需要你说明写卡的方法。需要你提供的是技能里没有的信息：玩家的处境、角色的声音、你要的画面、完成的标准，以及 Agent 可以自行决定的范围。这一节按“你会遇到的情况”整理，每一节说明 Agent 为什么会这样、该怎么写，并附一段可以直接复制修改的提示词。先找符合你情况的那一节：

- 产出的卡跟其他卡没有分别：[给处境与张力，不只给题材](#给处境与张力不只给题材)、[用一句对白代替形容词](#用一句对白代替形容词)
- 状态栏与按钮盖过故事：[说明画面要哪一种、不要哪些默认](#说明画面要哪一种不要哪些默认)
- Agent 频繁提问，每一步都等待确认：[写出完成标准与可自行决定的范围](#写出完成标准与可自行决定的范围)
- 想法还不清楚：[想法还模糊时，先要方向](#想法还模糊时先要方向)
- 有原作、设定文件或喜欢的卡：[直接提供素材](#直接提供素材)
- 语言、用语或称呼不对：[说明语言与称呼](#说明语言与称呼)
- 尺度不符预期：[说明内容尺度](#说明内容尺度)
- Agent 修改了未要求修改的内容：[一个版本只改一件事](#一个版本只改一件事)
- Agent 表示已测试，实际三轮就无法延续：[要求完整的试玩，并查看工作记录](#要求完整的试玩并查看工作记录)
- 修改后反而更差：[反馈现象，不指定修法](#反馈现象不指定修法)
- 只是提问，却被直接修改：[只要意见时先说明](#只要意见时先说明)
- 新开对话要接着做：[接续上次的工作](#接续上次的工作)

### 给处境与张力，不只给题材

“写一张好玩的女仆卡”这类指令只提供题材，Agent 会写出该题材最常见的版本：常见的设定、常见的关系、常见的开场。技能能保证卡片的结构，不能替你决定这张卡的看点。看点来自两件事：玩家是谁、面对什么（处境），以及什么事情悬而未决（张力）。开始撰写前，Agent 会先说明这个题材一般会怎么写、这张卡打算有什么不同；不同意时在这一步提出，不必等它写完。

可以这样写：

```text
女仆卡。玩家是刚继承老宅的年轻屋主；她是前任屋主留下的管家，知道这栋房子每一件不能说的事。张力：她守着的秘密，会随玩家取得的信任一件一件交出来，但每交出一件，她自己就少一样可以留下的理由。先说明你打算如何与一般的女仆卡不同，再开始。
```

最后一句是关键：它让 Agent 先把“一般版本”说出来，你才有机会在动工前改方向。

### 用一句对白代替形容词

“对白自然一点”“有个性”“嘴硬心软”这类形容，每个人的理解都不同，Agent 只能套用最常见的解读。一句你想要的对白，就能定义语气、句长、称呼与保留的程度，比任何形容词精确。

可以这样写：

```text
她的语气参考这句：“少爷，那扇门的钥匙，我想您还不需要。”短句、敬语、不解释理由，话说完就停。照这个语气写三句不同场合的对白给我看，确认后再写整张卡。
```

提供对白样本时，一句就够；三句以上 Agent 会开始模仿句型而不是语气。

### 说明画面要哪一种、不要哪些默认

卡片的画面分两种：故事为主、画面辅助；或玩法与数值绑定、画面为核心。没有说明时，Agent 会依题材套用常见的做法：好感度条、每条回复附两到四个按钮、把情绪做成数值。“不要太像 AI”无法对应到具体的模式，Agent 无从判断你指的是哪一个；直接点名不要的默认做法才有效。另外，即使没有任何显示规则，平台也会把回复结尾的 [status]／[choices] 区块画成面板与按钮；是否需要画面，与是否需要编写规则是两个问题。

可以这样写：

```text
这是陪伴卡，故事为主，关闭画面后也要能阅读。不要好感度条、不要每条回复附选项按钮、不要把情绪做成数值。只在回复结尾保留一行：她现在在哪里、几点。
```

玩法绑定数值的卡则反过来说明：

```text
这是求生卡，画面是核心。要显示的状态只有水位、粮食、燃料三项，每一项都要有玩家能做的动作改变它；每轮结尾附两到四个选项。没有玩家能改变的数值不要显示。
```

### 写出完成标准与可自行决定的范围

Agent 停下来提问，通常不是因为任务困难，而是不清楚做到哪里算完成、哪些事可以不经确认。“先写设定给我看，再写人物，再写开场白”会让它每一步都停下来等你。写出完成的标准与它可以自行决定的范围（包括点数上限），其余交给它处理。

可以这样写：

```text
完成的标准：推成试玩卡、你自己试玩过十轮、告诉我最弱的一层。推送与修改试玩卡不需要确认；点数 50 以内自行安排，超过再问我。只有送审、公开，或会写出完全不同的卡的选择，才需要问我。
```

这段也会让 Agent 较少对模糊的要求发问；如果你希望它多确认，删掉最后一句。

### 想法还模糊时，先要方向

想法还不清楚时，“你看着办”会把所有决定交出去，拿回来的多半是题材最常见的版本；在还没看到方向前就要求成品，则会浪费一整张卡的工夫。请 Agent 先给几个方向，各用一句话说明玩家在玩什么、张力在哪，你选一个再往下。

可以这样写：

```text
末日题材。先给我三个方向，各用一句话说明玩家在玩什么、张力在哪，不要写卡。我选一个你再开始。
```

### 直接提供素材

二创的原作、你整理的设定文件、你喜欢的卡，都是 Agent 写不出来的信息。“像那部动画里那个冷淡的学姐”要求它凭印象重建，结果会偏；直接交出素材，并说明哪些必须保留、哪些可以改。附上喜欢的卡时，说明你要的是它的哪一部分（节奏、开场、对白密度），不然 Agent 会连题材一起模仿。

可以这样写：

```text
原作是《〔作品名〕》的〔角色名〕，设定文件附在后面。必须保留：她对学弟的称呼方式、“先做再说”的习惯。可以改：时间线移到毕业后第一年。另外附一张我喜欢的卡，我要的是它开场白的节奏，不是题材。
```

### 说明语言与称呼

卡片的语言、用语习惯、角色对玩家的称呼，Agent 不会自动知道；“用中文写”没有说明是简体还是繁体。一开始说清楚，省下事后逐栏修改。

可以这样写：

```text
全卡简体中文，不混繁体。角色称玩家“你”，不用“您”；玩家的名字由玩家自己填，卡里不要预设。
```

### 说明内容尺度

“不要太色”“不要太过”没有范围，Agent 无法判断界线在哪。说明默认的尺度、玩家主动时可以回应到哪里、不可跨越的底线，Agent 才能同时遵守平台规范与你的意图。

可以这样写：

```text
默认全年龄，角色不主动推进亲密关系。玩家主动时，可以回应到牵手与拥抱为止，再往前就用剧情转开。平台规范的部分由你把关，有冲突时以规范为准并告诉我。
```

### 一个版本只改一件事

“开场白太长、她太快示好、世界观太薄、名字也换一下”会让 Agent 同时修改多处，事后无法判断哪项修改有效，也容易改到你没要求的地方。每个版本只指定一件事，其余请 Agent 列出来先不动。

可以这样写：

```text
这个版本只处理“她太快示好”。其他你注意到的问题列出来，先不动。改完告诉我修改了哪些文件、各改了什么。
```

### 要求完整的试玩，并查看工作记录

“你测过了吗”得到的回答多半是“测过了”，而 Agent 自行试玩两轮，只能确认开场白可以运作；卡片能否延续要看十轮之后，较弱的模型最先出现问题。完整的试玩会消耗点数，Agent 会先告知费用。试玩结束后，除了它的总结，也请查看卡片文件夹中的 `README.md`：这是 Agent 的工作记录，包含每个版本的决定、否决的方向与证据。

可以这样写：

```text
用一个较弱的模型和一个较强的模型各试玩 10–20 轮，每次新开对话。告诉我从第几轮开始无法延续、原因是什么，并把结果记进 README.md。开始前先告知点数。
```

### 反馈现象，不指定修法

“把定义第二段改短”是在替 Agent 开药方；你看到的是游玩时的效果，Agent 看到的是整张卡的结构，原因往往不在你以为的那一段。描述你观察到的现象，请它找原因，并要求与上一版用同一组对话比较，而不是只反馈“已修正”。

可以这样写：

```text
第三轮她就主动示好了，我希望慢很多。请找出原因再修改；修改后用同一组对话与上一版比较给我看。
```

### 只要意见时先说明

“这张卡是不是该走剧情路线？”看起来是提问，但 Agent 无法确定你是在问，还是在要求它改；两者混在一起时，它会选择执行修改。只想听取意见时，明确说明只需要意见。

可以这样写：

```text
先不要修改任何文件。这张卡走剧情或陪伴，各有什么代价？说明后等我决定。
```

### 接续上次的工作

新开一个对话时，Agent 不记得上次做了什么；“继续改那张卡”会让它从头推测。卡片文件夹里的 `README.md` 是它的工作记录，请它先读再动。

可以这样写：

```text
接续 cards/maid 这张卡。先读文件夹里的 README.md，告诉我上一版做到哪里、还有哪些待办，再开始。
```

### 发出指令前的检查

- 玩家是谁、面对什么，是否只用题材名称带过？
- 角色的声音，是否只有形容词而没有一句样本？
- 画面要哪一种、不要哪些默认，是否说明了？
- 完成的标准与可自行决定的范围（含点数上限），是否写出来了？
- 这一条指令，是否只要求一件事？

## 点数与界线

- 起草、推送、检查和渲染都不消耗点数。
- 试玩会消耗点数，Agent 会先征求你的同意。
- Agent 只会修改试玩卡和你自己的私人卡，不会替你送审或公开。
