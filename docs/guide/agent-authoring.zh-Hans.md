## 能交给 Agent 的事

Agent 依官方写卡技能工作：厘清你的需求（只在不同理解会产生不同卡片时才向你确认），把卡写成文件夹、推成试玩卡，自行检查与试玩，再反馈还能改进的地方。每一项都附一句可以直接输入的提示词。

### 从一个点子写出整张卡

> “写一张修仙文的卡：我是被逐出宗门的废柴，师姐偷偷帮我，要有修为和好感度两个状态，先做成试玩卡。”

只有模糊的想法也可以。Agent 会先与你厘清设定、人物、关系与开场白，再开始撰写。

### 修复现有的卡

> “导入这张 SillyTavern 卡，告诉我为什么聊三轮就没话说，然后修掉。”

SillyTavern 的 PNG、JSON、CHARX 和魅魔岛三件套都能直接导入。

### 制作状态栏、主题或整页界面

> “加一个显示好感度和所在地点的状态栏，渲染开场白给我看。”

需要画面时，Agent 使用工具包内置的沙盒套件（把模型写的状态区块画成面板、选项按钮与主题），以 `hearthroom card check` 检查文件夹，再以 `hearthroom card preview` 与 `card render` 查看结果。即使没有任何显示规则，平台也会把回复结尾的 [status]／[choices] 区块画成面板与按钮；需要自定义样式、主题或钉选栏时才使用套件。

聊天页本身是开源的（`hearthroom/moonstage`，本站的 `stage` 子模块）：skills 的沙盒契约由它的 `src/sandbox/` 生成，文档未涵盖的部分，平台事实页列出应读取的文件。

### 试玩并找出问题

> “用第二个开场白玩两轮，告诉我玩家会在哪里失去兴趣。”

### 上架前的检查

> “检查这张卡能不能送审，列出还要修的地方。”

## Agent 怎么写卡

1. **写成文件夹**：长文是 Markdown 文件，世界书、规则和图片各有自己的文件，你可以直接打开查看或修改。
2. **推成试玩卡**：只有你看得到，最后一次更新后 3 天过期，同时最多 5 张。
3. **检查与渲染**：依平台规则检查字数与内容，把开场白套上规则渲染出来，确认状态栏和版面正确。
4. **试玩**：实际与角色对话一轮，确认回复能否延续、玩家是否接得下去。
5. **修改**：依结果修改，再推送、再试玩，直到你满意。
6. **保存**：满意之后存成正式的私人卡，出现在“我的卡片”。送审和公开由你在网站上决定。

## 提示词指南

Agent 依官方技能工作，不需要你说明写卡的方法。需要你提供的是技能里没有的信息：你要的玩法、目的、参考样本，以及 Agent 可以自行决定的范围。以下按常见情况分节，每节附一组效果较差与效果较好的提示词。

### 产出的卡太普通

只提供题材时，Agent 会写出该题材最常见的版本。提供玩家的幻想与核心张力、一张你喜欢的卡，或一句你想要的对白，比“自然一点”“有个性”这类形容更有效。开始撰写前，Agent 会先说明这个题材一般会怎么写、这张卡打算有什么不同；不同意时在这一步提出。

> 效果较差：“写一张修仙卡，对白自然一点、有个性一点。”

> 效果较好：“修仙卡。玩家是被逐出宗门的废柴，师姐暗中相助，张力在于她一旦出手就会被发现。她的语气参考这句：‘这题我不接。进歌。’短、干、不解释。先说明你打算如何与一般的修仙卡不同。”

### Agent 频繁提问，每一步都等待确认

Agent 停下来提问，通常是因为不清楚完成的标准，或不确定哪些事可以不经确认。先说明完成的标准与可自行决定的范围，其余由 Agent 处理。

> 效果较差：“先写设定给我看，再写人物，再写开场白。”

> 效果较好：“完成的标准：推成试玩卡、你自己试玩过、告诉我最弱的一层。推送不需要确认；点数 50 以内自行安排，超过再问我。”

### Agent 修改了未要求修改的内容

“整体再好一点”会让 Agent 同时修改多处，事后无法判断哪项修改有效。每个版本只指定一件事，其余请 Agent 记录下来。

> 效果较差：“开场白太长、她太快示好、世界观太薄、名字也换一下。”

> 效果较好：“这个版本只处理‘她太快示好’，其余列出来先不动。改完告诉我修改了哪些文件。”

### Agent 表示已测试，实际对话三轮就无法延续

Agent 自行试玩两轮，只能确认开场白可以运作；卡片能否延续要看十轮之后，较弱的模型最先出现问题。完整的试玩会消耗点数，Agent 会先告知费用。试玩结束后，除了总结，也请查看卡片文件夹中的 `README.md`：这是 Agent 的工作记录，包含每个版本的决定、否决的方向与证据。

> 效果较差：“你测过了吗？”

> 效果较好：“用一个较弱的模型和一个较强的模型各试玩 10–20 轮，每次新开对话，告诉我从第几轮开始无法延续、原因是什么。开始前先告知点数。”

### 状态栏与按钮盖过故事

卡片的画面分两种：故事为主、画面辅助；或玩法与数值绑定、画面为核心。先说明你要哪一种，再指出不要的默认做法。“不要太像 AI”无法对应到具体的模式。另外，即使没有任何显示规则，平台也会把回复结尾的 [status]／[choices] 区块画成面板与按钮；是否需要画面，与是否需要编写规则是两个问题。

> 效果较差：“加个状态栏，好看一点，不要太像 AI。”

> 效果较好：“这是陪伴卡，故事为主，关闭画面后也要能阅读。不要好感度条、不要每条回复附三个按钮；只保留一行她目前的位置与时间。”

### 修改后反而更差

描述你观察到的现象，不要直接指定修改方式。Agent 能看到整张卡的结构，你能判断实际游玩的效果；两者结合才能找到原因。请 Agent 与上一版比较，而不是只反馈“已修正”。

> 效果较差：“把定义第二段改短。”

> 效果较好：“第三轮她就主动示好了，我希望慢很多。请找出原因，修改后用同一组对话与上一版比较给我看。”

### 只是提问，Agent 却直接修改

只想听取意见时，明确说明只需要意见。Agent 能区分提问与要求，但两者混在一起时，会选择执行修改。

> 效果较差：“这张卡是不是该走剧情路线？”

> 效果较好：“先不要修改。这张卡走剧情或陪伴各有什么代价？说明后等我决定。”

## 点数与界线

- 起草、推送、检查和渲染都不消耗点数。
- 试玩会消耗点数，Agent 会先征求你的同意。
- Agent 只会修改试玩卡和你自己的私人卡，不会替你送审或公开。
