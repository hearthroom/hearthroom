# Community badge collection acceptance

Use an isolated local member fixture for management mutations; do not create test awards in the production community. Separately verify production assets, authenticated readback and anonymous denial after release.

1. Open **Me**, follow **Badge collection**. Confirm level 0 and featured badge icons on the profile, then the collection title, conditions, dates and locked progress on the destination.
2. Select a third earned badge; a fourth selection must be disabled. Deselecting remains possible. Save and revisit the profile to read back the selected order.
3. Enable public collection and save; follow **View public profile**. Confirm featured badges and the full earned collection, with no locked progress, grant reasons or spend totals. Turn visibility off and verify the public collection disappears without changing independent level consent.
4. Inject a failed save in the fixture. Confirm the error remains visible and the draft survives; retry successfully, or explicitly reload/discard. Manager-triggered refresh must retain unsaved visibility and still-valid selected keys.
5. As a manager, create an event badge with a multiline condition and allowlisted icon. Grant it to the fixture handle; verify earned state and the audit entry. Start revoke and cancel; the award must remain. Confirm revoke; verify inactive state and audit readback. As a normal member/reviewer, management APIs must return 403 and controls must be absent.
6. API/D1 tests cover duplicate/concurrent retries, cross-member conflicts, system-badge forgery denial, expiry read filtering and dirty reconciliation, historical activity milestones, and public redaction. These are separate from browser fixture interaction evidence.
7. Use real Chrome at desktop 1440×1000 and emulated touch 390×844; read `innerWidth` to verify the actual viewport (window resize alone may stop at 500 px). Repeat in Traditional Chinese and English. Inspect dark/light contrast, long conditions, form controls, loading/error/disabled states, hidden manager controls, horizontal overflow and actual natural navigation.
8. Run the shared visual audit with a visible bad-key positive control; retain raw output and explain any existing global header/footer warnings separately. The page's enabled controls must have at least 44 px height on touch. Check console errors and same-tab request evidence. The native closed-details content has explicit display:none to keep both layout and geometry visibility consistent.

Chrome fixture journeys cover selection, publication/privacy, failure/retry, manager creation/grant/revoke/cancel, multiline conditions and unsaved-draft preservation. Production deployment/readback is recorded separately and must not be inferred from fixture tests.
